human 明确写「不推 story_list」。我第一反应是两层守卫都做成零帧，但整理回合一旦开始，`start_organizing` 已经下发，设备在 ORGANIZING 非交互页——零帧就是困死到重启（261021 R6 的实证）。architect 把这个矛盾直接摆到台面上，并给出「两条路径两种口径」。最后我按「① 素材侧过滤路径严格零帧；② 整理已发生后必须发页面退出帧」落分法，并在 plan、review-packet 反复留痕「human 如改判，代价 = 困页复现」。

## 三、architect 这轮含金量最高的一条判据

不是「加个占位集合」，而是 **R4：整串被成对括号包裹且剥壳后 ≤16 字 → 判占位**。它不枚举模型措辞，只认形态——「模型宣告无内容时几乎恒用括号包裹，而忠实正文不会被整串括号包裹」。再配上「明确排除引号族」，误伤面被压得很小。

这条给我一个可复用的思路：**防模型跑偏的守卫，优先找形态不变量，退而求其次才是词表**；词表只作补充且必须整串相等。prompt 侧这轮已经证明尽力了（制品里就写了「无内容则输出空」），模型不遵守——防线只能落在产物侧的机械判定上。

## 四、builder 的反直觉发现

把「主体守卫」整体移到 `archive_story` 之后，竟然一条不红——因为单行分支的前置守卫先接住了全部单行样本。必须把「单行前置守卫 + 主体守卫」同时移走才转红。这条让我收紧了对自己派单话术的习惯：**变异证据要对着「结构性质」设计，不能假设删一处就代表整条防线**；单行/多行这类分支，是两道独立的门。

## 五、帮倒忙的规则与工具（如实记）

1. **我自己往长 JSON 字符串里追加中文时，三次漏转义引号/换行**，每次都要靠 `json.load` 才抓回来。这是本轮最没技术含量的时间损耗，也是第二次踩同族坑（轮 B 也踩过截断）。已落 pod-events friction。下次的纪律：**每次 Edit 长 JSON 后立即 `json.load` 校验**，不要等到跑闸。
2. **`verify.mjs --help` 不认 help**，直接当无参跑了一整轮 scoped，白烧了一轮门执行（幸好未发布 round fact、未占序数）。工具的「帮助」与「执行」没有区分，是很容易误触的形态。
3. **`change-manifest` 闸经 current/ 指针恒判 pre-cutoff 放行**的老缺口仍在：它不报错、只是不做事。planner 手工按同规则对账了一遍（清单外 0 件）。这类「沉默通过」比红更值得警惕。
4. **G4 / overlap-tier3** 两处工具缺口沿上一轮，仍未修；本包合并出口依旧被它们与真机轮一起拦着。

## 八、下次改进（我自己的 checklist）

1. 长 JSON（taskpackage / verdict 类）每次 Edit 后立刻 `json.load` 校验，再继续下一步。
