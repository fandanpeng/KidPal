## 0. 想实现的效果与差距

**目标效果一句话**：孩子在 P3 星星记录本里选中任意一条记录双击，**都能进阅读态看到正文**——本机录的、重启前录的、云端恢复回来的老故事一视同仁；断网时看过的那几篇仍然能看。板端 TF 卡（`/sdcard`）成为 story 正文的本地缓存介质，云端的 story 归档仍是唯一真相源，板端只读镜像、一切写入照旧走云。

**现状差距**（2026-10-13 真机轮实证，条目 [TECH-261013-p3-reader-entry-no-text-silent-noop](../../docs/debt/tech/TECH-261013-p3-reader-entry-no-text-silent-noop.md)）：

1. **链路全绿、消费侧断**。手势识别、板级分流（[waveshare-s3-rlcd-4.2.cc:747-754](../../firmware/main/boards/waveshare-s3-rlcd-4.2/waveshare-s3-rlcd-4.2.cc#L747-L754)）、页内裁决（[story_page.c:1467-1475](../../firmware/main/display/story_page.c#L1467-L1475)）全部正确产出 `KSPV2_ACT_OPEN_READER`；断点在消费侧门槛 `g_story_text.id[0] != '\0'`（[mcp_server.cc:305-317](../../firmware/main/mcp_server.cc#L305-L317)）——无正文缓存即手势吃掉、什么都不做，只留一条串口 WARNING，屏幕零反馈。键帽条还在提示「说话·双击看」。
2. **正文只在归档时到达一次**。`g_story_text` 全固件唯一写点 = `view=story_text` 云端推送路由（[mcp_server.cc:1154](../../firmware/main/mcp_server.cc#L1154)），且只装**一篇**（2208B 结构）。冷启动恢复（v1.63）只重推 `story_list` 列表不推正文（[front_app.py:1067](../../server/gateway/front/front_app.py#L1067) 的 `restore=True` 路径）→ 恢复回来的老故事在本开机**永远**无正文缓存。
3. **设备侧没有取正文的通路**。设备从不主动索取任何业务数据；双击既不上报也不请求。
4. **同一函数内两条降级口径不一致**：story_text 解析失败会弹可见提示（[mcp_server.cc:1148-1151](../../firmware/main/mcp_server.cc#L1148-L1151)），无正文缓存却完全静默。
5. **另发现一条未登记的缺陷**：`kidpal_story_open_reader`（[story_page.c:1707-1732](../../firmware/main/display/story_page.c#L1707-L1732)）**完全不看光标选中的是哪一行**——不校验 `g_story_text.id` 与所选列表项 id，只拿缓存那份正文分页；渲染面（[story_page.c:1216-1237](../../firmware/main/display/story_page.c#L1216-L1237)）的标题与正文也都取自该缓存。故只要缓存非空，**双击任意一行都会打开缓存里那一篇**——不是「打不开」，是「打开错的」。本批一并修，并补登 debt。
6. **需求 S-F2.1 AC2 是不可兑现的无条件承诺**：「When KEY 双击，Then 进入阅读态」对存量故事在当前架构下永不成立。

**非目标（本批不做）**：

- **提醒 / 课表 / 日志一律不落卡**。NFR-OFF-1「Given 断网，When 到点，Then 无提醒」（[requirements.md:598](../../docs/requirements.md#L598)）与 §5.4 离线边界（[architecture.md:317](../../docs/architecture.md#L317)）**不被本批触碰**——这批只给 story 正文开一个窄例外。
- **不做光标预取**（BOOT 短按下移即预取光标那一篇）。进列表/翻屏批量预取在故事篇数不大时已覆盖该场景，v1 砍掉、留待真机观测后再评。
- **不做离线产出**。板端仍不能离线录故事、离线删、离线改课表——一切写入仍必须联网。「缓存模式」的定义即在此。
- **不做卡上缓存的淘汰策略**（篇数/字节上限、LRU）。v1 假设卡容量充裕，超限留待真实数据后另裁；只记总量日志。
- **不做热插拔检测**。沿用 261016 现状（启动期挂载一次），运行期拔卡走读失败降级。
- **不动 ADR-005 / ADR-010 已落地的 `data.restore` 补丁**。它们与新机制并存（同为「云端推、板端 RAM 填」）。**摘除补丁是后续独立评估项**，不在本批——避免一个批次同时动两套机制。

## 1. 决策前提：缓存模式 + 决策 24 窄例外

**定位裁决（human 2026-10-16 定）**：板端盘 = 云端数据的**只读镜像**。云端推下来、板端存下来、离线时只读展示；任何写入仍必须联网。板端**不成为第二真相源**，无需双向同步、无需冲突消解，ADR-004 云端唯一 producer 纪律零变化。

**决策 24 的处置**：决策 24（2026-09-02 grilling）含两部分——「离线边界」（断网无提醒）与「**介质禁令**」（板端非易失介质仅允许凭证/资产/固件，一切业务状态只驻 RAM）。禁令原文**明确列举 SD 卡**（[archive/spec.md:598](../../docs/archive/spec.md) 决策 24 条文）。

**起草期的历史更正（human 2026-10-16 裁定，须在需求/架构面如实落笔）**：human 明确「业务数据不落盘是因为之前没用 TF 卡、RAM 根本存不下，**无奈之举**」——即禁令的原始动因是**当时的存储成本约束**，不是产品原则。但账面上被升格成了原则：决策 24 写「『哑终端不存数据』**纯洁性保持**，离线兜底验收撤回」；ADR-005 备选①（[ADR.md:47](../../docs/ADR.md)）与 ADR-010 备选③（[ADR.md:90](../../docs/ADR.md)）都以「直接违反决策 24（板端 RAM 缓存重启即失是**有意不变式**）」为由否决持久化方案。

**这一步很重要**：后面 architect 起草、architect-reviewer 四查读的都是这些句子。批次若不**显式改写**它们，reviewer 会照旧拿「违反决策 24」打回。故本批的动作不是「绕过禁令」，而是**把禁令连同它的理由一起重述**——从「哑终端纯洁性」降回「当时的存储成本约束，现已由 TF 卡解除」。

**禁令解除的技术依据是新的、不是推测的**：TF 卡能力已于 2026-10-16 就绪（261016-sd-card-mount，SDMMC 1-bit 挂载 `/sdcard`，[waveshare-s3-rlcd-4.2.cc:832-875](../../firmware/main/boards/waveshare-s3-rlcd-4.2/waveshare-s3-rlcd-4.2.cc#L832-L875)，无卡/坏卡降级不崩）。该包 plan.md 已明写「story 存储…不是这个包要做的…**须先过决策 24 介质禁令的 spec 裁决**」——本批即在该口子上。

## 2. 设计与改法（T1–T5）

### T1 · 契约面：新增 `kidpal_story_fetch` 上行私有帧

**问题**：设备侧无任何取正文的通路（现状差距 3）。

**关键发现（推翻旧 ADR 的否决理由）**：ADR-005 备选①与 ADR-010 备选②两次否决「设备按需拉取」，逐字理由是「需在 §四端云协议剖面新增**首例**『设备发起请求-应答』消息对（现无 device RPC 先例）」。**该理由已过期**——[protocol.cc:81-87](../../firmware/main/protocols/protocol.cc#L81-L87) 的 `kidpal_story_delete` 是契约 §四既有私有上行帧，设备→网关，261010 批落地、已上线运行，front 侧接收在 [front_app.py:256](../../server/gateway/front/front_app.py#L256)。首例已存在，且**同族**（story 私有帧）。故本项的增量是「照同型再加一条帧」，不是在协议剖面开新面。

**改法**：新增上行帧 `kidpal_story_fetch`，逐字仿 `kidpal_story_delete` 形态；载荷带 **ids 数组**（触发场景天然是「当前屏这一批」，一帧一往返优于逐篇发帧）。下行**不新增**：应答直接复用既有 `story_text` 帧，网关按 id 逐篇回——`story_text` 帧形状零改动，只是第一次被「设备主动要」触发。

**目标文件**：`docs/contracts/interface-contract.md`（§四私有消息族 + §1.3④ story_text 消费语义注记）· `server/gateway/front/front_app.py`（收帧 → 校验 id → 逐篇回 story_text）

**待裁**：见 OQ-2（单 id vs ids 批量）。

### T2 · 固件面：`/sdcard` story 正文本地缓存层（新部件）

**问题**：板端无任何持久化业务数据的机制。

**改法**：新增存储层模块（建议落 `firmware/main/display/` 邻位或独立 `storage/` 目录，具体归位由 planner/architect 按 repo-structure 定）。

- **布局**：`/sdcard/story/<id>.txt`，一篇一文件。
- **命名取舍**：story id 形状 = `_slugify` 产出的 ASCII slug（可能超过 8 字符）或 `_hash_slug` 产出的 `s` + sha1 前 8 位（9 字符，[story.py](../../server/gateway/story.py) `_slugify` / `_hash_slug`）。两者**都可能超 8.3 命名**，而 261016 明确维持了 `CONFIG_FATFS_LFN_NONE`（长文件名关闭），并写明「LFN / 中文文件名归**首个真实消费包**按其需求裁决」——本批即该消费包。两条路：
  - **(i) 开 LFN，直接用 `<id>.txt`**（推荐）：id 是天然主键，免映射、免二次校验歧义。代价 = codepage 与内存取舍，须由 architect 评估。
  - **(ii) 维持 8.3，用 `S<seq:04d>.TXT` + 文件首行存 id**：seq 是 story 的入册流水号（`kidpal_story_text_t` 已带 seq 字段，`KSTORY_SEQ_ABSENT` 为缺席哨兵），免开 LFN；代价 = id↔seq 映射与读回时的 id 校验多一层。
- **RAM 索引**：启动期（或首次进 P3 时）扫一次 `/sdcard/story/` 建「卡上有哪些 id」的内存索引；写入时加、删除时减。「检查本地有没有」必须走这个索引，**不得每次翻页遍历文件系统**（否则翻页卡顿）。
- **卡上数据一律不可信**：卡可拔、可换、可被电脑改写，故**读回的正文必须用云端 `story_list` 校验 id 存在于列表**，不在列表内的一律忽略。这是「缓存模式」定位的必然要求——列表是唯一真相源，卡只是它的镜像。
- **卡不在位/坏卡**：`s_sd_mounted == false`（[waveshare-s3-rlcd-4.2.cc:271-274](../../firmware/main/boards/waveshare-s3-rlcd-4.2/waveshare-s3-rlcd-4.2.cc#L271-L274)）→ 整个存储层失效，预取跳过，双击走「拉进 RAM 显示、不落盘」路径。

**目标文件**：新增存储层模块 · `firmware/main/CMakeLists.txt`（接入）· `firmware/main/mcp_server.cc`（story 路由接线）

### T3 · 固件面：预取器（进列表 / 翻屏触发）

**问题**：按需拉取会在首次双击时暴露一次网络往返延迟。

**改法（human 2026-10-16 定策）**：进入 P3 列表、或翻屏改变当前屏时 → 取**当前屏显示项中本地缺失的** → 串行、限速、可中断地逐篇发 `kidpal_story_fetch` → 到达后写卡 + 更新索引 + 若正显示则重绘。

**边界纪律**：

- **绝不挤占语音主链路**：与孩子说话共用同一条 WebSocket，本仓反复钉的纪律（261016 包专门写「不碰语音主链路」）。故逐篇串行、篇间留间隔、孩子一离开 P3 立即停。
- **一次性成本**：首次进 P3 填满后，此后每次进 P3 全部命中、零流量。
- **顺序按列表序**：最可能被选中的（靠前 / 光标附近）先来。
- **失败静默**：后台预取失败不弹提示、不打扰；正确性由 T4 的兜底保证。

**「预取是优化、按需是正确性保证」**——这是本设计的核心不对称：预取挂掉了功能照常，预取成功了体验是「双击即开」。两者共用同一条帧，区别只在触发策略，故**契约面不因多一个触发点再加东西**。

**目标文件**：预取器（T2 同模块或邻位）· `firmware/main/mcp_server.cc`（渲染/前台切换接缝）

### T4 · 固件面：双击路径 + 兜底 + 可见降级 + id 校验修复

**改法**：

- **命中索引** → 读卡 → `kidpal_story_open_reader` → 进阅读态（零网络）。
- **未命中** → **插队**发该篇 `kidpal_story_fetch`（优先级高于后台预取）→ 到达后进阅读态。
- **离线/超时/卡不在位且拉取失败** → **可见降级提示**（对齐 [mcp_server.cc:1148-1151](../../firmware/main/mcp_server.cc#L1148-L1151) 既有 `SetChatMessage` 先例，或 P3 屏内就地提示；文案口径归 `story_page.h` 单源纪律，版式归设计稿）。
- **修 id 错配（现状差距 5）**：`kidpal_story_open_reader` 或其消费侧（`StoryDispatchAct` 的 `KSPV2_ACT_OPEN_READER` 分支）**必须校验被打开正文的 id == 光标所选行的 id**，不符即拒绝并走降级提示。

**目标文件**：`firmware/main/mcp_server.cc`（消费侧）· `firmware/main/display/story_page.c`（id 校验）· `firmware/main/display/story_page.h`（文案单源，若取屏内提示）

### T5 · 需求 / 架构面措辞（随批同拍，不单独成项）

- **需求面**：S-F2.1 AC2「When KEY 双击，Then 进入阅读态」从「不可兑现」变为「兑现」；补**离线/降级 AC**（未命中且无法回源时的可见行为）；补**补充规则**说明正文缓存的来源与边界。触 UI 与否待判（键帽条提示「说话·双击看」语义是否随之调整）。
- **架构面**：决策 24 加 **story 内容缓存 carve-out**，并按 §1 的史实更正**重述**「哑终端纯洁性」；[architecture.md:232](../../docs/architecture.md#L232) 存储行、[:266-267](../../docs/architecture.md#L266-L267) 板端状态表、[:317](../../docs/architecture.md#L317) 离线边界节镜像改措辞（**NFR-OFF-1「断网无提醒」边界本身不变**）。
- **ADR-005 / ADR-010 的「有意不变式」措辞**需被本批指出已被取代（方式由 architect 定：改原文注记 or 新增 ADR 承接）。

## 5. 风险与记账

- **隐私面（须被 reviewer 看见，不得悄悄发生）**：孩子的故事正文从此**落在可拔走的卡上**。缓存模式下产品叙事自洽（孩子的内容存在孩子的卡上），但这是一次**数据落点扩张**，应在需求面或 ADR 显式记一笔（见 OQ-3）。
- **本批首次把板端从「纯接收端」变成「有本地态的端」**。虽定位为只读镜像、不动 ADR-004 单源纪律，但这是本仓第一次跨这条线——reviewer 应重点查「是否真的没有第二真相源、是否真的无写入面」。
- **两条机制并存**：`data.restore` 补丁（ADR-005/010）与新缓存层并行。短期可接受（互不干扰），但**长期是双机制债**，摘除应另立变更评估（已列入非目标）。
- **LFN 启用**（若取 T2 路线 (i)）会改 `sdkconfig`，影响全局 FAT 行为，须由 architect 评估内存与 codepage 代价。
- **未做真机验证**：本稿全部结论来自源码/账本对读，进入实现面前须由承载包 builder 复读确认（起草期诚实注记）。

## 6. 待裁（随立项 ack 一并裁）

- **OQ-1（已裁，留痕）**：是否先切一个**零契约止血小包**（仅「无正文 → 可见降级提示」+ 修 id 错配，纯固件、不碰决策 24、当轮可烧板）。**human 2026-10-16 选 (a) 完整闭环**，止血包未取——本批一次做全，降级提示作为 T4 的一部分落地。
- **OQ-2**：`kidpal_story_fetch` 载荷形态——单 id 逐篇 vs ids 批量（起草倾向批量，同「当前屏这一批」的触发语义；architect 定）。
