## findings[]

### T3-F1 · SHOULD · 轴 6 — 排程链两处 handoff 未名之

- 引用：`spec:582` / `spec:325` / `spec:324` / `spec:588`；charter §4.3 E-1/E-2、D-5。
- 一句话问题：(1a)「schedule.md 变更 → 重算三档」的重算触发/节奏/owner 未名——决策 26「新建日程即时推」只覆盖 P1 刷新，不覆盖提醒重算；`spec:324`「已过去的档位自动跳过」隐含一个接近档位时刻才发生的重算，然触发无字。(1b)「pending.json → 网关到点推送」跨进程传递未名——OpenClaw（脑，写 pending.json）与流式网关（开源 xiaozhi server，跑 push helper）是两个进程，「到点」由谁检测、pending.json 经何机制被网关读到（共享文件轮询？回调？队列？）全缺。关联 S6：离线期间三档何时被判「过期静默作废」取决于重算粒度（预排 vs 惰性），未定 → 离线一周重连的提醒行为不可判。
- elicitation：半需（预排 vs 惰性重算两选一影响 S6 语义）。

### T3-F2 · BLOCKING · 轴 9 — 幂等去重/回执在「已渲染 vs 排队未渲染」边界自相矛盾

- 引用：`spec:326`（「重推的同 id 直接回回执不再排队（幂等，重复弹窗根除）」）vs `spec:327`（「队列中未渲染的条目待渲染后才回回执」）。
- 一句话问题：同 id 重推命中**队列中未渲染**条目时两条规约不可调和——按 327 不回执 → 网关 60s 重推（上限 3 次）而「易失已知 id 集合」只在渲染完成时加入 → 该条目不在集合 → 重推再次入队 → **重复弹窗**（违背「根除」）；按 326 直接回执 → 对**尚未渲染**条目报「送达确认」→ 违背「渲染即确认」与 327。两条路径必违其一。触发条件正是 charter S4 (a)+(c)：07:45 N 个事项共享墙钟时刻批量到达 + 弹窗驻留到按键 + 60s 重推 → 第 2…N 条在待渲染期被重推是**必然**叠加态，非边角。
- 预期裁定方向（供拍板，非替 spec 改法）：幂等集合（易失 id）是否含「已接收未渲染」队列成员须明示；若含，须改「渲染即确认」为「接收即确认」或引入 received/queued/rendered/acked 四态，否则「同 id 直接回执」卡片式表述无法成立。
- elicitation：**是**（核心，产品语义裁定）。

### T3-F3 · SHOULD · 轴 9 — 幂等 id 生成 owner 与跨重推稳定性未定义

- 引用：`CONTRACT-CHANGE-PACKET-v2-directionB.md:31`（id = `"<reminder-instance-id>"` 占位）；`spec:326`（预设「同 id 重推」跨重推不变）。
- 一句话问题：「同 id 重推」是设备幂等去重成立的前提，但谁生成 id、是否跨 3 次重推稳定、cron 每次重算写 pending.json 时 id 是否重新生成（若重生成 → 旧 id 与新 id 不一致 → 按新 id 重新排队 → 重复弹窗）均未定。轴 9「声明的不变量可强制」不满足——不变量所依赖的键自身无定义。此点也是契约门重写 §三（CDQ-260902）需锁定的字段级事实，供 T2 联动。
- elicitation：否。

### T3-F4 · SHOULD · 轴 9（canary 2 派生，P4 已接受前提的实现含义）— 「带物」内容唯一承载面蒸发

- 引用：`spec:320-321`（20:30 档 = 带物唯一承载档）／`spec:326`（渲染即确认出队）／`spec:294`（P1 分组不含备注列）／`spec:317`（目标「不丢三落四」）。
- 一句话问题：「带物/备注」只出现在提醒文案（20:30 档）；孩子睡着/不在旁时渲染即出队、不重推 → 信息静默丢失且无回读路径（P1/P2 均不回显备注），与「不丢三落四」目标冲突。非重攻「渲染即确认」取舍（禁），攻其实现含义：取舍已定，但「信息唯一承载面无持久化」的下游后果未入账、无缓解声明。
- elicitation：**是**（是否接受带物仅靠孩子当场看到，或备注列并入 P1/P2 视图）。
- 注：勿升级为「家长逐条确认」→ 那才是轴 11 违规；正确落点是不变量完整性。

### T3-F5 · SHOULD · 轴 9 + S4(a) — 「驻留无超时 + 队列不设上限」失效响应缺失

- 引用：`spec:327`（无超时驻留、不设上限「提醒低频」）；`spec:320`（20:30/07:45 共享墙钟）；`spec:326`（「过期静默作废」仅覆盖未送达）。
- 一句话问题：(1)「不设上限」的辩解「低频」是断言非不变量——07:45 档 N+m 个事项同时触发 → 队列深度由事项数决定、无界。(2)「过期静默作废」只覆盖**未送达**，已渲染但**永未按键关闭**的弹窗「驻留到按键」永不过期 → 课前 15 分钟弹窗可滞留屏上越过事件本身，spec 无设计响应。
- elicitation：半需（是否接受无上限，涉及事项数上限量化）。

### T3-F6 · SHOULD · 轴 9 + S3 — 提醒 TTS 随推送实时合成 → 对 edge-tts 的隐性同步依赖无降级响应

- 引用：`spec:328` / `spec:589`（「网关合成 TTS 随推送一并下发」）；charter S3「TTS 慢 → 提醒延迟」检查点。
- 一句话问题：合成先于推送 → 弹窗到达被 TTS 延迟串行；spec 未声明 (a) TTS 合成失败时是「弹窗+提示音照常仅静默」还是「整条 alert 扣住不发」，(b) edge-tts 慢时弹窗是否等待。决策 18/2「可替换 provider」只解换供应商，不解推送当口 TTS 挂掉的瞬态降级。charter S3 期望答案在 spec 中缺。
- elicitation：否。
