## 0. 想实现的效果与差距

**目标效果一句话**：孩子问完字，屏幕上**立刻是完整的字**（一眼看到字形，同时听到读法与笔名）；想学怎么写时按一下 KEY，才**一笔一笔画出来**。

**human 2026-09-26 最终口径（原话）**：

> 「我们换个思路：如果现在的播报还是正常的，就跟原来一样正常播报。只是一开始直接显示完整的字，点击播放的时候，它才开始逐笔去绘画、写那个字。」

**现状差距**：现行 spec（v1.57 口径）把查字窗的**演示**钉成「弹窗即自动逐笔动态演示」（§2.2 查字窗行「超大字逐笔演示」、F3 交互包、S-F3.1 AC1「米字格内超大字逐笔动态演示，像看老师写字」、AC3「演完一轮歇 2 秒自动重播」、线框初始态注 `(逐笔写)`）；KEY 短按因此只剩「重播」一义（§2.3 矩阵、S-F3.3 AC1）。孩子没有「我准备好了，你慢慢写给我看」的入口。**播报侧（TTS）现状即符合新口径、本批一字不动。**

**沿革（前两轮被否的路线，记录以免重走）**：

- v1.0 曾裁 **板端缓存下行音频**（KEY 才播、opos 压缩帧暂存 PSRAM）——human 2026-09-26 否；
- v1.1 曾转 **不缓存 / 按 KEY 经 `kidpal_session_ctx` 从云端现取**——human 同轮先选后否。该路线若走通需同时撞三处：`docs/ADR.md` **ADR-003**（「front 侧**不自建 TTS 合成、不做 mp3→opus 编码、不自己向设备腿注入二进制音频帧**」，且理由②点明「在 front 里挂 TTS provider 与 opus 编码器会把网关养成第二个大脑」）、**ADR-005**（「现无 device RPC 先例、`kidpal_session_ctx` 是单向通知」）、以及 `source_page` 闭集扩枚举的契约变更（`docs/contracts/interface-contract.md:266` 现有闭集 = `story`/`home`/`schedule`）。
- **最终口径把播报留在原样，问题面从「云端 + 契约 + 协议」缩小到「板端一个动画计时器」**——这是本批的全部内容。

**非目标（本批不做，防 scope creep）**：

- **播报链路零改动**——云端合成（引擎 edge-tts）、TTS 随回复自动下行、逐笔笔名承载（OpenClaw 回复文本，试点期口径）、`view=char` display 响应块、D3 笔顺 JSON 全部不变；**不触 `docs/contracts/**`**。
- **不新增任何端→网关消息**——不扩 `kidpal_session_ctx` 的 `source_page` 闭集、不新增 device RPC。
- **板端不缓存音频**——音频照旧随回复流到即播，无待播缓冲、无分配类问题。
- **右栏内容零改动**——S-F3.2 右栏五行（拼音 / 共 N 画 / 部首 / 释义 / 组词）现状即满足 human 说的「右侧显示出来解释」。
- **关窗口径零改动**——KEY 长按关窗、BOOT 关窗回原页不翻页（v1.39 隔离）、5 分钟无操作兜底（v1.43）、驻留不随会话关闭，全部维持原文。
- **不实现任何代码**——实现侧三项（见 §3 实现行）照仓例登记对账、归 Phase 1 dev-loop 包。
- **不改设计稿母版**——`docs/ui/kidpal-ui-design-v5.html` 的查字窗自动循播控制器（`:1202` 起）与线框 `[重播]` 键帽文案须随后跟，归设计面另批（§6 留根）。

## 2. 问题、根因与改法（T1–T6）

### T1 · 共享底座三处「弹窗即自动演示」口径失准
**问题**：查字窗在共享底座有三处描述（§2.2 状态表行、§2.3 手势矩阵行、§2.4 P4 撤页注），三处都写「弹窗即逐笔演示」、KEY 短按一律写「重播」。新口径下初始态应为**静态整字**、KEY 首次按下是**起播**而非重播。
**证据**：`docs/requirements.md:68`（§2.2 查字窗行，含「孩子说「勇怎么写」→ 当前页上弹出查字窗：超大字逐笔演示 + 拼音/共 N 画/部首/释义/组词（见 F3）。」「弹窗时 TTS 播引导语，」「按键：KEY 短按 = 重播笔顺（含打断当前播报重新演示）、长按 = 关窗回原页；」）；`:146`（§2.3 矩阵查字窗行 `| 查字窗 | 重播笔顺 | — | 关窗回原页 | 关窗回原页（不翻页） | 同短按 | — |`）；`:181`（§2.4 P4 撤页注，含「当前页上弹出米字格 + 笔顺逐笔演示 + 拼音/部首/组词（见 §2.2 查字窗行、F3）」「KEY 短按 = 重播、长按 = 关窗回原页，BOOT = 关窗回原页（不翻页，v1.39 隔离）。」）。以上引文均于 2026-09-26 起草期以 `grep -F` 逐条回源 byte 比对通过。
**根因**：查字窗 v1.36 定窗、v1.37 定会话口径时的既定交互就是「弹窗即演」，KEY 因此只剩重播一义；human 2026-09-26 把**演示**的起播时点交给孩子（播报不动），共享底座三处描述属连带面。

- 原「孩子说「勇怎么写」→ 当前页上弹出查字窗：超大字逐笔演示 + 拼音/共 N 画/部首/释义/组词（见 F3）。」

- 原「弹窗时 TTS 播引导语，」
  → 新「弹窗时 TTS 播**引导语 + 逐笔笔名**（播报口径 = v1.55 不变、本批不动——顺带归一：原句只写「引导语」，系 v1.55 恢复逐笔笔名后未同步的残留），」

  → 新「KEY 短按 = 起播笔顺演示（首次；已起播则从头重播，含打断当前播报重新演示）」
② `:146` §2.3 矩阵查字窗行整行替换（其余五格语义不动）：

### T4 · NFR-PERF-2 的阈值终点被起播时点抽空
**问题**：NFR-PERF-2 阈值终点写「到笔顺演示开始」——自动演示时代该终点 = 「链路跑通」的可测时刻（跑通即自动起、无人工介入）；演示改 KEY 触发后，起播时刻由孩子按键决定，不再是对答链路的可测终点，阈值语句失去可判性。
