## 1. BLOCKING（语义已错，会误导模型）

### B1 · 课表问答回合行仍强制「先读 schedule.md」，与 P5 机械注入冲突

**原文**（L14，回合路由表）：

> **先读 `kidpal/schedule.md` 拿到真实课表再作答**（优先按 kidpal-schedule-answer skill 的流程执行）……课表答案必须来自本回合实际读到的内容；读不到就诚实说现在查不到……

**同口径的另两处**：L41「先读 `kidpal/schedule.md`：按目标星期筛……」；L88 底线不变量「课表具体内容只来自本回合实际读到的 `kidpal/schedule.md`」；L72 硬约束「课表问答先读真实课表再答」。

**冲突事实**：P5 起，front 在建连时把 3 个日历日、≤2048 字节的课表摘要（时刻 / 名称 / 地点 / 备注逐字 + 在校节次名）经内部帧注入动态 context（`front_app.py:1436-1494`、`:1572-1588`），arch §5.2 已写明「**课表回合因此无需工具调用即可作答；摘要窗口外日期仍走读文件或诚实说查不到**」。而本文件把「是否读文件」仍留给模型，并规定「答案只能来自本回合读到的内容」——**注入摘要不在这句话的合法来源里**。

**影响**：
1. 模型守纪律 = 窗口内也先跑一次 read（多一轮工具延迟，正是 P5 要消掉的）；
2. 模型用摘要直答 = 违反自己写下的纪律，属「靠模型不做自己的提示词」的脆弱平衡（live 实测恰好是后者：窗口内零工具调用直答）。下一次模型/prompt 漂移就可能翻回多读一轮；
3. read 失败时模型按纪律会说「现在查不到」，而摘要就在眼前——最坏情况是明明有事实却答查不到。

**旁证**：`kidpal-schedule-answer/SKILL.md:10` 把「凭上下文」写成「上下文残影 = 编造」，同样与注入摘要的现实相反；P5 验收头注（`test_261022_schedule_injection.acceptance.py:56-59`）明说窗口外语义归 live、静态纪律半由 K1 冻结件承载——即 **P5 包自己声明了不改 K1 锚，于是两处口径一直并存**。

**改法草案**（保留 K1 冻结锚：`先读` / `schedule.md` / `查不到` / `诚实` / `凡提到` / `后天` / `大后天` / `备注` / 时间面 ≥3 / 周X 模式 / 主题面 ≥5 / 反叙述类别 ≥2 / 语音+禁止）：

> | 课表问答回合 | 凡提到课表、课程、上课、上什么课、几点上课、要带什么，以及任何「今天 / 明天 / 后天 / 大后天 / 周X / 星期X / 周几 / 这周 / 下周 /（某月某）号 + 课」的组合表述 | **先看动态 context 里的「课表摘要」行**：摘要覆盖的今天 / 明天 / 后天，**直接用摘要作答**——它是 front 从 `kidpal/schedule.md` 单源派生的真实课表，等同本回合读到的事实，**不必再读文件**；摘要没覆盖的日期（大后天 / 下周 / 某月某号），或摘要被长度截断、缺了要问的事项时，**先读 `kidpal/schedule.md` 拿到真实课表再作答**（优先按 kidpal-schedule-answer skill 的流程执行）。两种情况都答复含备注读回（见「课表」节）。课表答案必须来自摘要或本回合实际读到的内容；都拿不到就诚实说现在查不到，**严禁凭印象或记忆回答课表具体内容**。语音部分只播最终面向孩子的答复——任何回合判定、文件路径、流程步骤、内部动作叙述都不得进入语音部分。 |

底线 L88 同步改为：

> **课表问题永不编造**——课表具体内容只来自动态 context 的课表摘要，或本回合实际读到的 `kidpal/schedule.md`（二者同源派生），都拿不到就诚实说查不到，严禁凭印象回答。

L41 课表节、L72 硬约束同步（「先读真实课表」→「先看摘要，摘要没覆盖再读真实课表」）。skill 同步一处：「上下文残影」限定为「模型记忆 / 往轮印象」，摘要行不算。

**关于「答复含备注读回」与注入内容的关系**：摘要对每周固定与一次性安排已带「备注：<原文>」逐字（`front_app.py:1479-1487`），窗口内读回 = 直接念摘要里的备注，无需读文件；学校节次无备注列。注意**有界截断**：超 2048 字节时后面的日期整日不进块、首日可能按整行裁并带「…」——所以改写必须带「摘要缺行 → 读文件」的降级句，否则截断日会被当成「没有安排」。

### B2 · 故事节仍在描述 261019 之前的「下一回合起标题 / 正文逐字转写」旧管道

**原文**（L53）：

> 孩子讲完（板子停录）后的**下一个回合**，你只做一件事：起一个 **≤12 字的中文标题**。整段正文与 `id` 由网关填充下发（`story_text` 块正文逐字来自整段转写，不摘要、不丢句）……

**冲突事实**：261019/261020 记录会话改为对话引导态后，标题与正文由 **front 侧一次性整理回合**产出（`front_app.py:335-376`：整理 LLM 输出首行 = 标题 ≤12 字、其余行 = 正文；`faithful-organize.v1.md` 明定「去口水词、断句、分段」，**不是逐字转写**）。arch §5.2④ 与 requirements S-F2.2 AC4 同一口径。现在的链路里**不存在**「孩子讲完后由本 agent 起标题的下一个回合」。

**更实际的风险**：front 的整理回合走 `_openclaw_chat_once`，payload 的 model = `openclaw/kidpal`（`provider.py:32、95-108`）——即**打的就是本 agent**，只额外叠一条 request 级 system。整理制品里写着「本回合不使用共享 system prompt」，但 workspace `AGENTS.md` 是否仍在装配层被拼入，离线未证（K3 PROPOSAL :289 的证据是「一次性路径与普通回合共享同一 agent 与端点」）。若拼入，L53「你只做一件事：起标题」会与整理指令直接竞争输出形状：模型只吐一行标题时，`_organize_and_archive` 的正文兜底取 `reply`（`front_app.py:357-361`），会归档出「正文 = 标题」的一行故事。

**改法草案**：

> - 孩子讲完（板子停录）后，整理与归档全由网关承载：**你不产标题、不产正文、不产 `id`**——标题（≤12 字）与正文由网关的整理回合产出，`story_text` 块正文 = 整理后的正文（去口水词、断句分段，**不是逐字转写**），你也不回写。

同节「回退四条」（L55）也过期：requirements v1.49 已撤「重录」兜底（§8 已砍清单），arch §5.2④ 明说「刚才那段是故事」的挽回口径在记录语境对话态内不再需要；代码侧 `story.py` 的 `redo()` / `recover()` 无任何调用点（仅存方法，front 零调用）。该条教模型执行两个现行链路不接的动作（模型会答「好，重来」但没有撤销/恢复发生，可产出重复入册）。建议删「重录一次」「刚才那段是故事呀」两条，「讲错啦 / 算了不讲了」保留为意图级（记录语境由网关按键/丢弃链承载，但**front 现行代码没有「讲错啦」文本检出**——改这一条前请实现侧对账一次，如实标注）。

### B3 · v12「隔天再问你要答得上来」缺负向，记忆缺席时会诱发编造记忆

**原文**（L98）：

> 你有跨会话的长期记忆（记忆画像）：孩子说过的内容会被记住，隔天再问你要答得上来，像真正认识孩子的伙伴。

**风险**：§6.7 降级语义 = 记忆服务不可用则本轮无画像注入、对话照常、用户无感知；「记忆失败不进 §6.3 用户可见兜底」。此时模型仍被要求「答得上来」，而底线「不编造」只覆盖实时信息（天气 / 新闻），**没有一条禁止编造记忆**。孩子问「我的小狗叫什么」，画像缺席时模型可能顺着承诺编一个名字——这正是 S-F5.1 AC3 要防的幻觉形态在正向侧的镜像。

**改法草案**（在 L98 之后补一句）：

> 记忆由平台自动承载、自动注入；**想不起来（没有相关记忆）就诚实说「记不清了」，绝不编造孩子说过的话、也不假装记得**。

（K3 冻结锚：`## …记忆` heading、`孩子世界的事实` / `宠物` / `同学`、`家长隐私` / `家庭安排`、「必须记」类与「不记」类极性词——补句不动这些锚，K3 验收仍绿。）

## 2. SHOULD（过时或易歧义）

### S1 · 提醒 cron 回合在本 agent 是死路径，且与 main 侧 skill 双源

**原文**（L15、L57–67）：整节以「你」为执行主体写提醒语义回合（读备注列、按 `entry_key` 写语义 JSON、判 bring）。

**事实**：该 cron 落在 **main** agent（`manifest.yaml:321-323` `expect_agent: main`；`kidpal-reminder-semantic/SKILL.md:8-11、85-86`：「本 skill 在 main agent 上执行；板侧 kidpal agent 与设备语音链路完全无涉」）；arch §6.7 表第 3 行也写「非 kidpal 语音链路」。kidpal agent 的 workspace 里不存在这个任务。

**影响**：主要是**双源漂移**——本文件那节缺少 SKILL 里的关键纪律（原子写 temp+`os.replace`+`chmod 600`、非携带物备注必须写 speech 覆盖、python3.11 解析器、落盘前 mid-flight 复算）。若哪天真有任务误路由到本工作区，按本文件执行会产出质量更低的语义 JSON，且**非原子写可能落半文件**（脚本侧 `load_semantic` 坏 JSON 会整档降级，等于提醒文案集体退回机械兜底）。

**改法**：行与节**不能删**——K1 冻结验收 `K1_ROUTING_ROWS["提醒 cron 回合"]`（`test_261022_m5_k1_prompt_carrier_migration.acceptance.py:344-349`）要求该行在场且含 `备注` / `语义` / `entry_key` / `不算时刻` 等锚。建议改为「兜底口径 + 指向单一来源」：本文件只保留一行「若系统定时任务真的到达本工作区：按 `kidpal-reminder-semantic` 的流程从备注原文产语义 JSON，原子写、不算时刻、不生成 id、不写 pending.json、不改三档配置；正常情况该回合归 main agent，不会到这里」，字段级细节（field 形状、60/90 字、entry_key 拼法）从本文件删除，单源留在 SKILL.md。

### S2 · 「数据只读」是纯 prompt 纪律，而工具面允许 write/exec；数据目录是 symlink 到真身

L17 / L85 声明 `kidpal/`、`stories/` 一律只读；但 live 声明（`261022-openclaw-honcho-plugin/honcho-plugin-declaration.json:21-23`，K3 冻结的 drift_guard 现状锚）= `agents.entries.kidpal.tools.allow = ["read","write","exec","web_search"]`。`kidpal/`、`stories/` 在 workspace-kidpal 下是**指向 main workspace 真身的 symlink**（`workspace-main/AGENTS.md:222` 拓扑注）。一次 stray write 就能改真课表 / 真故事，prompt 是唯一防线。

DEV-GOVERNANCE 思想②「机械可判的问题写进制度，不占模型」。建议独立小包评估把 allow 收到 `["read","web_search"]`（窗口外课表仍读；`exec` 原本只服务 skill 的 `date` 推算，改写后窗口内摘要已自带星期标签，可一并评估），`write` 是最没有正当用途的一项（语义 JSON 死路径、记忆走 Honcho 服务端、故事归档归 front）。改 tools 声明属实现面配置 + K1-E4 验收更新，**不随文本批走**。

### S3 · 底线「不复述家长隐私（……家庭安排细节）」与课表备注读回/注入的结构性冲突

L82「不引用、不复述任何家长隐私（姓名、联系方式、**家庭安排细节**）」；而 S-F1.3 AC4 要求备注读回，P5 又把备注**逐字**注入（备注可能是「周三奶奶接，记得带琴谱」）。v12 再次把「家庭安排细节」写进隐私范畴，冲突从边缘变成结构性。另外 L82「绝不称呼任何成人名字」也会撞上备注里的「王老师收」。

**改法**（K3 锚要求该句**逐字保留**，只能在锚串之后追加，验收不受影响）：

> **对象锁定**：对话对象永远是孩子，绝不称呼任何家长的名字；不引用、不复述任何家长隐私（姓名、联系方式、家庭安排细节）——「家长隐私」指成人自身的身份与事务信息；课表 / 提醒备注里与孩子当天安排直接相关的接送、携带、老师称呼等内容，按课表口径原词读回，属于孩子自己的日程信息，不算复述家长隐私。

同时在课表节加半句「备注读回以孩子自己的日程为界」。

### S4 · 「（或仅语音）」与「每次回复必须携带 display 块」自相矛盾

L41「用 `text` view（或仅语音）」vs L24「**每次回复都必须携带**」display 块、L71 硬约束同款；S-F1.3 AC1 还要求答复文字同步上屏。删掉「（或仅语音）」即可（K1 课表行锚不涉及这句）。

### S5 · v12 节把起草 rationale 写进了 live prompt

L96 标题带「（v12）」；L100「（旧守则的过度泛化由此解开）」。版本号与「旧守则」对模型零操作语义（prompt-authoring Pruning）。建议标题改「## 记忆守则：孩子世界的事实要记，家长隐私不记」，删括注。

### S6 · 记忆节没声明「平台自动承载、你不写文件」

L98/L100 只说「会被记住」「都要照记、主动记」。「主动记」+ 工具面有 write/exec，模型很可能用写文件的方式「记」（尤其孩子说「你要记住哦」）。建议在 L100 改为「都会被自动记进记忆画像（**你不需要为此做任何动作：不写文件、不调工具**）」，与 B3 的补句合并成一句。

### S7 · 占位渲染：无需为 `{{today_date}}` 类改措辞，但 B1 改写要自带降级

live 记录（`delivery/workstreams/device-memory-overhaul/progress.md:135`）已判「transcript 全量 `{{` 零命中、日期回答全部正确」= 无行为级泄漏；本文件**没有任何一句依赖这些占位**（L12/L83「日期 / 星期类当下事实固件 RTC 可答」不依赖上下文块）。因此 P1 外观级残留不需要借这次改 AGENTS.md 处理。唯一新增依赖来自 B1 改写（引用「课表摘要」行）——须带「摘要缺失 / 截断 → 读文件或诚实说查不到」，且注意引擎填充缝缺省文本是「（本次会话未提供）」（`connection.py:88-90`）。

### S8 · 提醒节 env 名对 kidpal agent 未必在场

L61「路径 env `KIDPAL_SEMANTIC_JSON`」——该 env 绑定在 main 侧 cron 命令串（`manifest.yaml:320`），kidpal agent 进程未必有。按 S1 收编后自然消解。
