# 评审记录 R1 · architect（spec story / T1 主审）

> 评审对象：`docs/systems/kidpal/spec.md` §4 重写（T1）+ 其与契约（T2）的对齐关系。
> 视角：内部一致性、UI 锚点真实性、与他章一致性、契约对齐（不审契约 diff 本身）、可验收性、覆盖完整性。
> 证据基准：`spec.md` / `ui/kidpal-ui-design-v2.html` / `contracts/interface-contract.md`，file:line 逐字引用。
> 结论：**打回**（含 1 项 BLOCKER、若干 MAJOR/MINOR；BLOCKER 升级 human）。

---

## 结论

**打回。** story 与 UI 锚点的「真实性」大体扎实（抽查的 pose/canvas/参数多数对得上设计稿原文），但存在一组**手势语义矛盾**和**与 §5 既有章节未同步**的问题，其中 KEY 长按的定义在 spec 内部直接冲突，会让实现方无法确定行为，属 BLOCKER。修复后可达 GREEN。

---

## Findings

### BLOCKER

**B1 · KEY 长按定义在 spec 内部直接冲突（§4.0 vs §5.3）——升级 human**
- 位置：`spec.md:268`（§4.0 手势表）× `spec.md:439`（§5.3 按键表）
- 证据：
  - §4.0：`KEY 长按=预留（P4 查下一个字候选）`（spec.md:268）
  - §5.3：`| **KEY**（主功能键） | ... | 回首页 | 核心交互键 |`（spec.md:439，KEY 长按列 = 「回首页」）
  - 设计稿与 §4.0 一致：`KEY 长按 ... 预留，暂不定义 | P4 查下一个字的候选触发`（kidpal-ui-design-v2.html:620）；S-F3.3 也用 KEY 长按查下一个字（spec.md:394）。
- 问题：同一颗键的长按，§4.0 说「预留/P4 候选」、§5.3 说「回首页」，两者矛盾。实现方拿到无法判定 KEY 长按到底干什么。本批 T1 只重写 §4、声明「其余章节不动」（PROPOSAL §2-T1），于是 §5.3 的旧定义被原样保留，与新 §4.0 冲突。
- 建议改法：以 §4.0 + 设计稿为准（KEY 长按=预留/P4 查下一个字候选），把 §5.3 的「回首页」改为与之一致，或在 §5.3 加注「键位最终见 §4.0，本节以 §4.0 为准」。**因这触及「回首页」这一既有交互语义的存废，属影响目标效果的取舍，升级 human 拍板**：KEY 长按到底是「回首页」还是「P4 查下一个字」。（顺带：§5.3 自身也写「最终键位在 UI 联调时定」spec.md:445，可借此统一收口到 §4.0。）

### MAJOR

**M1 · §4.0 全局手势表丢了设计稿的「页内特例」列，与各 story 的 KEY/BOOT 用法表面冲突**
- 位置：`spec.md:268`（§4.0 手势表）
- 证据：§4.0 把手势写成一句**全局**定义：`KEY 短按=启动/结束会话·确认·打断播报；... BOOT 长按=P2 今天⇄明天切换`。但设计稿 `gesture-table` 是三列结构，明确有「页内特例」列：`P2 问课程 · P3 选故事／停录音 · P4 播笔顺`（kidpal-ui-design-v2.html:617），且 BOOT 长按标注 `无全局语义 | P2 今天⇄明天切换`（:619）——即 BOOT 长按**本无全局语义**，P2 只是特例。
- 冲突体现：
  - KEY 短按：§4.0 全局=「启动会话」，但 S-F2.1「按 KEY 反白选中项下移」（spec.md:330）、S-F2.3「按 KEY 朗读正文」（spec.md:348）、S-F3.3「按 KEY 重播」（spec.md:393）——三个页面三种含义，与全局定义字面冲突。
  - BOOT 长按：§4.0 写成「=P2 今天⇄明天切换」（像全局），但 S-F2.3「BOOT 长按翻下一屏」（spec.md:348，设计稿 P3-reader `BOOT 长按 翻屏` :923 一致）——表面冲突。
- 问题：§4.0 作为「所有 story 复用的共享底座」，却把页内特例压平了，导致底座与各 story 读起来互相打架；实现方无法从 §4.0 推出「在 P3 列表按 KEY 是下移还是进会话」。
- 建议改法：§4.0 手势表改为与设计稿一致的「全局行为 + 页内特例」两层结构（或直接声明「页内特初见各 story / 设计稿 gesture-table 页内特例列」），并显式列出：P3 列表 KEY=下移、P3 阅读 KEY=朗读、P4 KEY=重播/播笔顺、P3 阅读 BOOT 长按=翻屏。这是文档结构修复，不升 human。

**M2 · P3 从「列表选中」到「进入阅读/回听」的触发手势未定义（覆盖缺口 + 三处来源不一致）**
- 位置：`spec.md:347`（S-F2.3）× `spec.md:459`（§5.4）× 设计稿 P3 主视图
- 证据：
  - S-F2.3：`Given P3 列表选中某故事，When 确认，Then 进阅读态`（spec.md:347）——「确认」是含糊词，未定义用哪颗键、哪种手势。
  - §5.4：`KEY单击光标下移选择，KEY双击播放选中`（spec.md:459）——用 **KEY 双击** 播放。
  - 设计稿 P3 主视图底部：`KEY 选故事` + `听 BOOT`（kidpal-ui-design-v2.html:878-880）——用 **BOOT** 听。
- 问题：同一动作（选中后进入阅读/回听）有三个出处、三种手势（未定义 / KEY 双击 / BOOT 听）。且 spec §4 全篇无「双击」（grep 全文双击仅出现在 spec.md:26 硬件表与 :459/:460 的 §5.4），§4 story 体系完全没承接双击。实现方无所适从。
- 建议改法：在 S-F2.1 或 S-F2.3 明确定义「确认」手势（如「再按 KEY 进入阅读」），并与 §5.4、设计稿三者取齐；若保留双击需在 §4.0 手势表登记双击维度。选哪种手势（BOOT 听 / KEY 双击 / KEY 确认）**建议升级 human**，因设计稿 P3 主视图的「BOOT=听」与设计稿自身 gesture-table「BOOT 短按=翻页，所有页面一致」（kidpal-ui-design-v2.html:618）已自相矛盾，需 human 裁一个权威口径。

**M3 · S-F1.2 砍高亮 vs S-F1.3 仍要「切 P2 高亮相关课程行」——§4 内部张力**
- 位置：`spec.md:290`（S-F1.2）× `spec.md:299`（S-F1.3）
- 证据：
  - S-F1.2：`不做「当前课反白高亮」...课表页只承担「看安排」，不承担「现在进行」指示`（spec.md:290）。
  - S-F1.3：`播报答复 + display 指令切 P2 高亮相关课程行`（spec.md:299）；端云列亦写「[板]（播报 + 高亮）」（spec.md:297）。
- 问题：S-F1.2 刚把 P2 的高亮能力砍掉（圆点收敛为两态：空心=已上完/明天、实心=待上，无高亮态），S-F1.3 又要求语音问答后「高亮对应行」。「高亮」在两态圆点语言里没有可落的形式，属内部不一致 + 不可验收（实现方不知高亮长什么样）。
- 建议改法：给 S-F1.3 的「高亮」一个与两态圆点兼容的具体形式（如「该课程行加星标/边框/小伴指向」，呼应 S-F1.2 已有的「带星标呼应」spec.md:292），或把 S-F1.3 改为「切到 P2 并滚动定位到该课程行」这类无新视觉态的承诺。不升 human，但需在 spec 内闭环。

### MINOR

**m4 · S-F3.1 米字格大字尺寸（~250px）与设计稿及 spec §5.6 均不符**
- 位置：`spec.md:375`
- 证据：S-F3.1：`米字格大框内超大字（~250px）逐笔动态写出`。但设计稿 P4 米字格外框 `width:236px;height:236px`、内部字盘 SVG `width:208px;height:208px`（kidpal-ui-design-v2.html:956-957）——实际字盘 208px，无 250px。而 spec §5.6 旧文又写 `整屏显示一个超大汉字（可达 ~280px）`（spec.md:478）。三处数字（250/208/280）互不相同。
- 建议改法：统一为设计稿真实值（米字格框 236px / 字盘约 208px），并把 §5.6 的 ~280px 一并对齐；或都改为不给死数字、只写「充满米字格字盘」。纯数值对齐，不升 human。

**m5 · spec §4 砍掉的两项功能在设计稿（真相源）里仍作为特性展示，未做任何「已废弃」标注**
- 位置：`spec.md:290,350`（砍功能的 story）× `kidpal-ui-design-v2.html:796,814,835,836`（当前课反白）× `:918,928`（生字反白）
- 证据：S-F1.2 注明砍「当前课反白高亮」、S-F2.3 注明砍「生字自动反白高亮」并称「设计稿该高亮仅为示意」（spec.md:350）。但设计稿 P2 仍画着「当前课反白」`<!-- 列表：当前课反白 -->`（:796）、`现在上` 标签（:814）、p2-notes 把「当前课反白」当特性讲（:836）；P3-reader 正文仍把生字「飞」反白（:918）、figcaption 写「生字反白高亮」（:928）。PROPOSAL §2-T1 非目标明确「不改 UI 设计稿」。
- 问题：spec 说砍、设计稿说留，且设计稿是 story 锚点的真相源。后续实现/评审看设计稿会把已砍功能再做出来，形成持续漂移。story 里那句「仅为示意」太弱，挡不住。
- 建议改法（二选一，建议升级 human 定方向）：①本批顺带在设计稿 P2/P3-reader 对应处加「（已废弃，以 spec S-F1.2/S-F2.3 为准）」标注——但这会破 PROPOSAL「不改设计稿」的非目标，需 human 同意扩大范围；②在 spec §4 顶部加一条显式声明「设计稿中 P2 当前课反白、P3 生字反白两处为已砍功能残留，以本节约定的两态圆点 / 语音问生字为准」，把漂移收口在 spec 侧（不动设计稿，符合非目标）。倾向 ②更省。

**m6 · 提醒弹窗「整屏压 d50 网点」与组件库「弹窗背后铺 50% 网点」一致，但 S-F2.4 盖章帧「d25」与组件库 comp-stamp 未注明网点档**
- 位置：`spec.md:357`（S-F2.4 d25）× `kidpal-ui-design-v2.html:934,945`（盖章帧 d25）
- 证据：S-F2.4 `背景压 d25 网点`（spec.md:357），设计稿盖章帧 `<div class="dev d25">`（:934）+「背景压 25% 网点」（:945）一致 ✓。S-F1.4 `整屏压 d50 网点`（spec.md:307），设计稿 `class="d50"`（:1082）+「整屏压 50% 网点」（:1098）一致 ✓。网点档对齐无误。
- 说明：此项核对通过，列出仅为闭合「网点档 d25/d50」评审点，无需修改。

## 各评审焦点小结

1. **内部一致性**：13 条 story 之间，语音会话生命周期 §4.0 与各 story 自洽（聆听/思考/播报/喊停引用一致）；但**按键手势在 P1–P4 各态不唯一**——见 B1（KEY 长按）、M1（页内特例丢失）、M3（高亮张力）。这是本批最主要的内部问题。
2. **UI 锚点真实性**：抽查的 `state-*`（listening/thinking/speaking/reminder/sleepy 分别对应 kidpal-ui-design-v2.html:1032/1048/1065/1080/1102）、`canvas-p1..p4`（:722/790/850/954）、`p3-recording/p3-reader/p3-stamp-frame/comp-stamp/gesture-table`（:896/912/933/597/615）、`pose-*`、`ic-penhand`(:383) 均真实存在。参数 950ms(:1009/1243)、4.4s(:163)、0.8s(:603)、d25/d50(:29/30)、−8°(:192)、13.5px/1.72(:918) 全部对得上。**唯一对不上的是 m4 的 ~250px**；另 `pgdots` 在设计稿是 CSS class（:138/139）而非 `data-od-id`，spec.md:266 把它当「UI 锚点」列——建议改述为「底部页点组件（class `pgdots`）」以免误导为可 grep 的锚点（MINOR，并入 m4 一类处理）。
3. **与他章一致性**：与 §3 端云划分、§7 已定决策（按一下启动会话/喊停本地/同步HTTP）无冲突。**与 §5.3 冲突（B1 KEY 长按）、与 §5.4 冲突（M2 P3 手势、§5.4「本周」三态 vs §4「今天⇄明天」两态）**——§5.4 说 P2「KEY单击切今天/明天/本周」（spec.md:458），§4 S-F1.2 只讲「今天⇄明天」两态且用 BOOT 长按，「本周」概念在 §4 消失。建议连同 B1 一起在 human 裁决时把 §5.3/§5.4 与 §4.0 收口对齐。
4. **契约对齐**（不改契约）：story 引用的 view 类型 char/schedule/story_list/story_text/text/home/control 均存在于契约（interface-contract.md:48/67/82/96/109/117/125）；`char.words`(:58)、`char.meaning`(:57) 支撑 S-F3.2 组词/释义 ✓；提醒三（interface-contract.md:209 `view:"text"`）与 S-F1.4 的「text→富弹窗映射」（spec.md:310）一致 ✓。已砍功能（当前课高亮/生字高亮）在**契约侧本就无对应字段**（无 status/无生字标注），spec 侧已删承诺——**契约侧无残留**；残留只在设计稿侧（见 m5）。`story_list.total` 字段契约中现无（interface-contract.md:84 仅 items），由 T2 补，属契约门范畴，本评审不预判其结论，仅确认「story 需要 total」与「契约需新增 total」这一对应关系成立（S-F2.1 计数器 ×N、S-F2.4 第 N 颗确需数据源）。
5. **可验收性**：多数 story Given/When/Then 客观可验（像素、时长、网点档、姿态锚点齐全）。含糊处：S-F2.3「When 确认」（M2）、S-F1.3「高亮」（M3）、S-F1.1「优先级冲突时布局保 时间 > 接下来 > 温湿度」（spec.md:282，「保」的判定标准未定义，轻微）。
6. **覆盖完整性**：F1（5 story）/F2（5 story）/F3（3 story）均覆盖；设计稿 4 页（P1 canvas-p1→S-F1.1、P2→S-F1.2、P3→S-F2.1/2.2/2.3/2.4、P4→S-F3.1/3.2/3.3）+ 5 全局状态（聆听/思考/播报/提醒/低电 → §4.0 七行含喊停与页点）均有 story/底座承接。缺口：**P3 列表→阅读的进入手势无 story 承接（M2）**；§5.4 的 KEY 双击播放（spec.md:459）无 §4 story 承接。
