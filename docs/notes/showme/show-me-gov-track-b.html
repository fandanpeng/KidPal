二、逐步：每一步谁干、怎么走到、干嘛、产出什么

  1. 主线程 human ack起草 PROPOSAL → 立项 ack→ PROPOSAL.md（草案）+ 立项授权
    主线程起草 PROPOSAL：业务语言 + 初步技术方案 + human 取舍点标注，骨架 docs/templates/PROPOSAL.template.md。目录命名（起草期硬义务）：governance-lane = <YYMMDD>-gov-review-<slug>、spec-lane = <YYMMDD>-arch-review-<slug>——名字必须命中 scope-map 的 review-agent 写槽 token（gov-review/arch-review），否则评审 / 核验期制品写入被 enforce-scope.mjs 机械拦截。PROPOSAL 须标轨道自评 + 理由（作者不得自路由精神）。随后 human 立项 ack = 前端对齐「为什么改（需求）/ 往哪改（方案）/ 改动多大（量级）」。
  2. architect评审循环至 GREEN→ GREEN（记 PROPOSAL §7）
    architect 只读 canonical、只写评审记录于 PROPOSAL §7；结论二分：GREEN / 打回。影响目标效果的打回项升级 human。打回 → 主线程修订 PROPOSAL 重提 → 再评，循环至 GREEN。评审 3 轮未 GREEN → 触发熔断（见下卡）。
  3. 主线程标 FROZEN→ 内容冻结（授权记 Status 行）
    主线程凭「立项 ack + GREEN」标 FROZEN。FROZEN = 内容冻结；此后落地不可回改 PROPOSAL。
  4. 主线程packet-bound 落地→ canonical 落地 + architect-landing-summary.md
    主线程 packet-bound 落地（G1/G2/G3 全落，landing-manifest 绑定，落地后不可回改 PROPOSAL）+ 写 architect-landing-summary.md（引被批 packet-id，A9 packet-binding，供人类 merge 门 spot-check）。landing 通道恒 = 主线程 packet-bound 一条；architect 恒纯判官 / 起草、永不 landing（其 approved-landing mode 已于 2026-08-02 退役）。
  5. landing-verifier独立核验→ landing-verdict.md（绿）
    主线程派 landing-verifier（独立于落地者，补 builder≠verifier 缺槽）核验「实际落的 == frozen PROPOSAL 的 landing 清单」：跑结构门 landing-fidelity-check.mjs（未冻结 / 无 packet-binding / scope creep / claimed·planned-but-not-landed 硬失败）+ 逐文件人读 diff 核对改法 == PROPOSAL（语义保真，脚本不判）。绿 → commit 分支；RED → 退回主线程修 landing。landing-verifier 只读 codebase、只写自己 verdict——改了被验文件就塌独立性。
  6. 主线程补写 retro（趁热）→ retro report
    主线程补写 retro report（骨架 docs/templates/retro.template.md）于提案目录——landing-verifier 绿后趁热写、先于合并。retro 不含合并锚（合并落点由 INDEX 的 mergedInMain 列经 changes-index.mjs 机械现推承担）。
  7. 机械闸 主线程前置升级闸 → 自动合并本地 main→ 已合并（可回滚）；remote push 仍 human
    主线程跑 pre-merge-escalation-gate.mjs（含 off-main 校验）。放行 → 自动合并本地 main：治理批恒 git merge --ff-only（main 无独有 commit 时才成立，有分歧即停交 human）；回滚口径 = git revert 逐 commit 或 human 裁。升级闸拦 → 升级人。状态转移时跑 changes-index.mjs --upsert <id> 单行钉进 delivery/changes/arch/INDEX.md（arch 段；dev 段在 delivery/changes/dev/INDEX.md，各 lane 只写自己的）。remote push 始终 human。

三、熔断：评审 3 轮未 GREEN human 三选一

回路

human 3 轮未 GREEN → 三选一

① 转 Track A全套对抗（/arch-change）
② 撤回 / 缩圈提案，回起草
③ 换新判官再战 1 轮仍不绿 → 自动转 Track A（不再二次升级）

四、⑦ 升级闸在 merge 期重算什么 例外清单 · 只重算可机判项

必经，不是门

机械闸 pre-merge-escalation-gate.mjs

只重算「merge 期仍可机判的例外」，命中即拦 → 升级人；放行 → merge-driver 落 main。
契约面 diff触 docs/contracts/** 且同批无契约门证据 off-main源 commit 落在 main / master（隔离被破坏） escalation 未 resolve存在未结的 agent-escalation / blocked 态 riskTier high-critical风险等级触顶 supervisor APPROVE provenance批准来源不可机验 architect GREEN 机锚GREEN 标记缺失 / 不可验
不在 merge 期重算：跨系统结构性变更、声明红队、自改递归属路由期裁决——在 merge 前已引走人，升级闸不再重算。

五、边界与不动清单 本路由不改的东西

存疑向严 + 直接 Track A 判据

  • 判据适用存疑默认升 human（不猜、不向宽）
  • 命中任一 → 绕过 Track B 走 Track A：① 触 docs/contracts/**（直走契约门）② 跨系统结构性变更（固件协议与服务端语义同时动）
  • governance 类变更（含 self-def / review-loop agent defs）不再强制升级——Track B 评审循环的对抗力度即为足额
  • 「声明红队」= 自愿逃生门：human 或 architect 任一方随时可启，非路由义务

不动清单（本路由不改）

  • 契约门（contracts Tier-1 → architect-reviewer 四分类 + human 签字）
  • landing-fidelity-check.mjs + landing-verifier 独立核验
  • 机械强制层（scope-map / hooks / verify-gates）
  • 批次目录合法终态 = landed；放弃 / 中断无自动出口，--stale-report 只点名、删除 / 归档恒 human 批准后主线程执行
