## 一、findings[]

### T1-F1 · 板端存储三处自相矛盾：SD「本地缓存录音、字库、课表」直接击穿「不存数据」红线
- **轴**：0 · **严重度**：BLOCKING
- **引用**：
  - `docs/spec.md:32` ——「| 存储 | Micro SD 卡槽（FAT32）+ 16MB Flash | **本地缓存录音、字库、课表** |」
  - `docs/spec.md:57` ——「板子只负责…❌ 不理解业务、**❌ 不存数据**、❌ 不做智能」
  - `docs/spec.md:586` —— 决策 24「**设备不缓存事项/课表**」
  - `docs/spec.md:141` —— D3「makemeahanzi…**已下载到服务器 `kidpal/chardata/`**」
  - `docs/spec.md:215` —— 架构图板子方框「RTC 提醒 + **SD 缓存** + Wi-Fi」
  - `docs/spec.md:205` —— §3.2 职责表「课表/故事/查字业务+**存储** | **云端**」
- **问题**：spec 对「板端是否缓存事项数据」给三个互相打架的答案——§2:32 说 SD 缓存「录音、字库、课表」，§3.3:215 板子方框带「SD 缓存」，而 §3.2:205、决策 24、D3 一致说「事项/字库在云端、板不缓存」。可机判自相矛盾，直接落在「哑终端不存数据」红线（蓝图 §6）上。builder 读 §2/§3.3 会实现 SD 缓存课表/字库，读决策 24 会拒绝。
- **代码佐证（非 spec 引用）**：目标板 `waveshare-s3-rlcd-4.2` 现有代码无任何 SD 挂载 / SPIFFS 字库·课表缓存（仅 NVS 存 url/token/version、SPIFFS 存 1bpp 美术资产）；`server/shim.py` 无「板端缓存课表」消费方。§2:32 是 v0.1 遗留叙述，无实现面。
- **需人类知识**：否。

### T1-F2 · 「缓存」一词两义并用 + P1「接下来」板端持有状态生命周期/介质未声明
- **轴**：0 · **严重度**：SHOULD
- **引用**：`docs/spec.md:291`「今日日程经**云端下发缓存**…**离线不可用**」 vs `docs/spec.md:586`「设备**不缓存**事项/课表」
- **问题**：「缓存」在本 spec 同时负担相反语义——(a) 掉电即失渲染缓冲（则不应叫「缓存」，且「离线不可用」自洽）还是 (b) 持久缓存（违反决策 24）。板端持有 P1 今日日程的生命周期/介质未声明。charter 轴 0 映射点「P1『接下来』缓存」的实证飘移。
- **需人类知识**：否。

### T1-F3 · 「不存数据」红线依赖「易失」隐含前提，从未写成可强制不变量
- **轴**：0 · **严重度**：SHOULD
- **引用**：`docs/spec.md:582`（易失 id 集合）、`docs/spec.md:201`（会话状态机=本地状态，代码 `device_state_machine.cc` 证实 RAM）、`docs/spec.md:363`（录音缓冲实为网关累积、脑侧实用）、`docs/spec.md:586`+`:57`（红线本体）
- **问题**：spec 把「易失 id 集合 / 本地会话状态机 / P1 日程缓存」标定为合理（因是易失 RAM），但从未写出「板端一切有关事项/身份状态只能驻留 RAM、禁止落 Flash/SD/NVS」这类可强制不变量。缺这句，红线不可证伪：builder 可把「易失 id 集」或「今日日程」顺手持久化到 spec:24 明列的 16MB Flash，且不违反任何一句 spec 文本，悄悄突破红线。
- **需人类知识**：否。

### T1-F4 · 实时句边界职责重叠与 v0.1「停顿→送云端」模型未随方向 B 收敛
- **轴**：0 · **严重度**：SHOULD
- **引用**：`docs/spec.md:239`（§3.4「本地 VAD 检测说话结束」）、`:458-459`（§5.2「VAD 检测停顿 → 送云端理解」） vs `:78`（§3.0.0「Opus 帧 → **VAD 切句** → ASR」）、`:535`（§6.1「服务端 VAD 切句」）
- **问题**：「谁判定句边界」这个实时信号有两个 owner：§5.2/§3.4 说板端本地 VAD 检测停顿→才送（v0.1 push-on-pause），§3.0.0/§6.1 说板端连续流式上行 + 服务端切句（方向 B）。互斥——若按 §5.2 停顿才送，网关无从切句。§5.2 是 charter canary 5 未点名的延伸 v0.1 残留（charter 只标了 §3.2–§3.4）。
- **需人类知识**：否（板端本地 VAD 只保留喊停/插话用途即可闭合）。

### T1-F5 · 「新建日程后即时推」刷新触发的 producer 未名（schedule.md 变更检测者无人认领）

- **问题**：三触发里前两个 producer 具名（WS 连接事件、每日 0:00 cron），唯独「新建日程后即时推」的变更检测者无人认领——cron 轮询扫表 / FS watcher / 家长写路径顺带触发，一个没写。而「家长直接改 MD」恰是最难有 watcher 的一条人肉路径。数据 owner 与变更事件 producer 双重断链。charter §4.1 D-5 / §4.3 E-2 已列此点，本 finding 为独立重现。
