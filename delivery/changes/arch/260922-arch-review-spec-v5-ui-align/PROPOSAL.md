## 2. 问题、根因与改法（T1–T6）

### T1 · P1 首页线框与 AC 停在 V4 口径
**问题**：WF-F1-01 线框与 S-F1.1 验收标准描述的 P1 与 V5 设计稿不符——线框画「▶ 14:00 钢琴课 还有 36 分」「明早 · 春游（明日预告）」、辅助条日期「星期三 6月26日」；AC1 写「页面带倒计时贴纸等趣味点缀」、AC2 写「最近一项带倒计时贴纸，再下可带明日预告」。V5 实际口径（`docs/ui/kidpal-ui-design-v5.html` v5 修订记录①②③，OQ2 裁定后定稿 commit 20df3cb）：「接下来」= 常规字号文本列表（时间+课名同行、多项正常换行、无大字无倒计时贴纸）；「明天」= 与「接下来」同规格标签＋多项逐行内容（仅课外班与临时事件）；辅助条日期英文化（Tue 22 Sep，星期简写+日+月简写，无「今天」字样，仅 P1）。
**证据**：requirements.md:210-219（线框）、:226-227（AC1/AC2）、:232（补充规则「布局优先级 = 接下来（最近项+倒计时）」）、:550（§4 可读性分级例举「『接下来』事项与倒计时」）、:614（§6 路线图「接下来」为主体 + 辅助条小图标 + 倒计时 + 电量 ADC 接线）；设计侧 = docs/ui/kidpal-ui-design-v5.html 修订记录 ①②③（2026-09-22）。
**根因**：设计先行迭代（human 2026-09-22 裁「先设计后同步」），spec 同步滞后一轮。
**改法**：① WF-F1-01 线框重画为 V5 形态（文本列表两行 + 「明天」标签区多项列出 + Tue 22 Sep + 键帽 [说话]/[翻页]）；② AC1 删「倒计时贴纸」表述（趣味点缀由小伴演出与倾斜点缀承担）；③ AC2 改「逐项列出（时间+课名同行、正常换行）+ 明天预告区——多项逐行列出，仅课外班与临时事件（学校课不上此区，看课表页）」（OQ2 human 裁定 2026-09-22：标签用「明天」非「明早」、多项列出、仅非课内课程与临时事件）；④ 补充规则布局优先级句删「倒计时」尾巴、新增日期格式口径句（英文简写、仅 P1）与明天区数据口径句；⑤ 线框头注补 v1.57 变更说明；⑥ §4 可读性分级（line 550）例举句「（『接下来』事项与倒计时、星星计数、提醒大字等）用大字」改为与 V5 一致例举（星星计数、提醒大字、P2/P3 网格与正文小字分级维持原句语义，删「与倒计时」并把「接下来」从大字例举中移出）；⑦ §6 路线图阶段一交付行（line 614）删「+ 倒计时」；⑧ §8 已砍清单新增一行：倒计时贴纸（「还有 36 分」）——v1.57 砍，理由 = 常显页两级信息（接下来/明天）足够、1bpp 小字可读性存疑（OQ1 裁定）。倒计时贴纸处置见 OQ1；实现侧对账：P1 已按 V4 布局实现（`home_p1.c`，260921-m3-k4 收口），V5 布局差 = 新对账登记（照 §2.3 对账六条先例形态，标注 Phase 1 dev 修复项）。
目标文件：`docs/requirements.md`（改）

### T2 · P2 今天列「粗框/反色」双口径与 V5 单口径矛盾
**问题**：WF-F1-02 线框注释与 AC2 均写「今天所在列高亮（粗框/反色）」，给实现留了两个合法形态；V5 已裁单口径 = 外轮廓加粗（列外框 4px、列内横线与默认格线 1.5px），反色弃（真机效果不好——与 P3 选中行 v1.31 反白弃用同理）。
**证据**：requirements.md:241（线框注释「← 今天所在列高亮（粗框/反色）」）、:263（AC2「Then 今天所在列整列高亮（粗框/反色）」）；设计侧 = kidpal-ui-design-v5.html v5 第二轮修订⑥。
**根因**：V4 设计时留双口径未裁，V5 真机可实现性收敛时裁掉反色，spec 未跟。
**改法**：AC2 与线框注释统一为「今天所在列外轮廓加粗高亮（列外框加粗、列内格线不加粗；反色弃用——真机效果不好）」；AC2 语义不变（高亮可辨），仅收窄形态。
目标文件：`docs/requirements.md`（改）

### T3 · 键帽条口径：键名上屏与母版指针过期
**问题**：§2.2 键帽条行按「左 KEY 提示 · 右 BOOT 提示」描述、提醒弹窗行写「左『KEY 知道了』+ 右『BOOT 关闭』」，全部线框键帽画 `[KEY 说话]`/`[BOOT 翻页]` 形态；且该行钉「设计稿 v4 §03 comp-keybar（v4 为现行设计母版）」。V5 已改：键名（KEY/BOOT）不上屏，键帽盒内直接写动作文字（说话/翻页/问课程/收尾/…，24 处）；长按场景动作文字加前缀「长按·」；现行母版 = v5。
**证据**：requirements.md:69（§2.2 键帽条行）、:82/:98/:113/:128（WF-B-01~04 线框键帽）、:217/:253（WF-F1-01/02 线框键帽）、WF-F2-01~05 与 WF-F3-01 线框键帽同形态；设计侧 = kidpal-ui-design-v5.html v5 第二轮修订⑤ + comp-keybar 组件规格表。§2.3 手势表的 KEY/BOOT 为物理键位语义（描述硬件按键，非屏显文案），**不改**——键位语义与屏显提示分层。
**根因**：同 T1；键帽是全局组件，V4→V5 的改动波及全部线框。
**改法**：① §2.2 键帽条行改「左槽＝左键动作提示 · 右槽＝右键动作提示，键名不上屏、盒内直接写动作文字（长按场景前缀『长按·』）」，母版指针 v4→v5；② 提醒弹窗行「左『KEY 知道了』+ 右『BOOT 关闭』」→「左『知道了』+ 右『关闭』」；③ 全部线框（WF-B-01~04、WF-F1-01/02、WF-F2-01~05、WF-F3-01）的 `[KEY X]`/`[X BOOT]` 键帽画法改 `[X]`（动作文字入盒）。实现侧无新增对账（键帽条三槽布局本就是 ⚠️ MVP 未实现项，Phase 1 修复面不变）。
目标文件：`docs/requirements.md`（改）

### T4 · P3 框族口径缺失（V5 弃手绘框）
**问题**：requirements P3 各 story 未规定框族形态，实现侧按 V4 手绘框资产化路线准备（ui-implementation-strategy §1：八值圆角需资产化）；V5 已弃——P3 框族一律正常圆角矩形（10px 单值圆角、无倾斜），★×N 星星计数去框裸排，录音态气泡去倾。spec 需补一句口径，否则拆包时引用哪版设计稿无据。
**证据**：requirements.md:325 起 WF-F2-01~05 各线框与补充规则（无框族口径）；设计侧 = kidpal-ui-design-v5.html v5 第二轮修订⑦。
**根因**：框族形态原属设计面细节、由设计稿承载，V4→V5 变化影响实现路线（资产化面缩小），需在 spec 钉住防拆包引用错版。
**改法**：F2 story 组补充规则统一补一句「框族口径 = 正常圆角矩形（单值圆角、无倾斜；V5 起弃手绘八值圆角——真机难实现且显乱），星星计数去框裸排」；锚行「UI = canvas-p3 等」不受影响（锚指向设计稿画布 ID，V5 目录同名接续）。
目标文件：`docs/requirements.md`（改）

### T5 · 查字窗右栏「速查卡」表述与 V5 纯文本口径不一致
**问题**：S-F3.2 补充规则写「右栏保持速查卡密度」、WF-F3-01 对账块用「速查卡」措辞，V5 已将右栏改纯文本（弃框族与静态对照小块）。语义上「速查卡密度」指信息密度而非卡片形态，但表述会误导实现侧做卡片容器。
**证据**：requirements.md:505（补充规则「右栏保持速查卡密度」）、:480（对账块「速查卡」×1）、:468-478（线框右栏）；设计侧 = kidpal-ui-design-v5.html v5 第二轮修订⑧。
**根因**：同 T4。
**改法**：补充规则改「右栏纯文本列出（无卡片容器），保持速查信息密度、不做关键词解释墙」；线框右栏画法本来就是逐行文本，仅键帽行随 T3 改；对账块历史文字按 append 纪律**不改写**（历史记录类文件/块保持原貌），仅在 F3 窗口交互包补 v1.57 注记说明右栏形态改纯文本。
目标文件：`docs/requirements.md`（改）
