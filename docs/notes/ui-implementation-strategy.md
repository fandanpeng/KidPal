# KidPal UI 实现策略 · 「LVGL 骨架 + 预栅格化美术资产」双层方案

> 来源：`changes/arch/260830-arch-review-ui-impl-strategy/PROPOSAL.md`（FROZEN 2026-08-31，architect R3 GREEN）。本文承载完整分析；spec 侧索引见 [spec.md §5.7](../spec.md)。
> 适用对象：M4「4 页 UI 重做」及其后的所有 UI 开发包；资产管线与 P1 重做归后续 dev-loop TaskPackage。

## 0. 一句话定论

页面布局与动态文本走 **LVGL 原生控件**；吉祥物、手绘框、涂鸦、网点、大号图案化文字等美术元素**离线从设计稿 SVG 栅格化为位图资产**（RGB565 直出为基准，I1 留真机优化项），经 SPIFFS 加载、运行时 `lv_image` 渲染，模拟器与真机**同资产双端渲染**。

## 1. 设计稿元素可行性矩阵

设计稿 = `docs/ui/kidpal-ui-design-v2.html`（v2，已与 spec §4 story 锚点互链）。逐元素对 LVGL 9.x 原生能力分类（依据 = kimi 踩坑记录实测 + LVGL 9.3 树内源码核验 + 2026-08-31 模拟器实战验证）：

| 设计元素 | 设计稿锚点 | LVGL 原生可行性 | 结论 |
|---|---|---|---|
| 大字体排版（时间 112px／标题 30／正文） | `canvas-p1` 等 | 位图字体子集可做到任意尺寸，能力满足；真机缺字体管线 | **可实现**（路线已定：小智同款 `lv_font_conv` → SPIFFS `.bin`，踩坑记录 §7.5） |
| 图标家族（48 盒 14 枚） | `sec-icons` | 小智同款 FontAwesome 式图标字，或 `LV_USE_IMAGEFONT`（本仓 LVGL 9.3 `src/others/imgfont/` 目录在场） | **可实现** |
| 三档网点纹理 d50/d25/d12 | `.d50/.d25/.d12`，4px 格 | 原生无图案填充；4px 格规则点阵做成 4×4 平铺贴图资产 | **需资产化**（同框族走资产管线，与 OQ-2(a) 口径一致） |
| 反白强调块（inv） | `.inv` | 原生 fill 直接做 | **可实现** |
| 布局、绝对定位、页点、键帽条 | `pgbuts`/`pgdots` 等 | 原生控件正常发挥区 | **可实现** |
| 米字格笔顺动画 | `canvas-p4` | 契约 D3 已定板端用 `lv_canvas` 折线逼近贝塞尔（spec §3.0.2） | **可实现**（契约已定，不在本批范围） |
| 吉祥物七姿态（Hello Kitty 风 SVG path，贝塞尔+旋转+组合） | `pose-daily` 等 7 个 symbol | 原生**不能**：v9 旋转的是整个矩形对象（踩坑记录 §5.2「旋转小耳朵会变成菱形」）；`lv_line` 不支持贝塞尔 | **需资产化** |
| 手绘不规则圆角（`border-radius: 255px 15px 225px 15px/...` 八值不对称） | `.frm/.frm-sm`，全站框族 | 原生**不能**：LVGL radius 是单值对称圆角，无不对称半径 | **需资产化** |
| 元素倾斜 ±1–2°（`tilt1/tilt2` 每屏 ≤3 处） | `.tilt*`，红线清单要求 | 原生**基本不能**：v9 支持旋转但位图旋转无抗锯齿，1bpp 屏边缘必成锯齿 | **需取舍**（已裁 OQ-1(a)：倾斜烘进资产） |

**根因**：设计稿的表达介质是 CSS/SVG（任意贝塞尔、八值圆角、rotate transform），LVGL 原生控件的表达介质是「矩形 + 单值圆角 + 实心填充 + 标签」。两者之间差一个**栅格化层**。手搓控件跨过这个层只能产出「规整矩形堆叠」——这正是 kimi 路线被 human 判「很烂」的直接原因。

## 2. 实现方案定论

### 2.1 页面骨架走 LVGL 原生控件

布局、标签、页点、键帽提示条、列表、反白块——这是 LVGL 的正常发挥区，保留 widget 语义（动态文本更新、页面切换、焦点）比全屏贴图省 RAM 也好维护。

### 2.2 美术元素走资产管线

吉祥物七姿态、手绘框族、三档网点（4×4 平铺贴图）、涂鸦点缀（星/云/波浪线）、印章，全部离线从设计稿 SVG 导出为位图资产，运行时以 `lv_image` 渲染。帧动画用多帧 `lv_image` 换帧或复用基座 GIF 链路（otto-emoji-gif 组件已在树内），落地时二选一，倾向静态帧换图——GIF 解码在 1bpp 屏是浪费。

### 2.3 资产管线

设计稿 HTML 内嵌 SVG 是唯一母版 → 脚本（`tools/` 下新建，进 dev-loop 包）抽取 symbol → 按目标尺寸栅格化 → **直出 RGB565 位图资产**（`.bin` 经 SPIFFS 加载；实战证明 I1 索引格式在 LVGL 9.5 软件渲染路径下调色板被绕过，RGB565 是双端行为一致的最稳格式，I1 仅作为真机空间优化项留待执行期在 9.3 上再验）→ SPIFFS 资源分区（与字体 `.bin`、笔顺 JSON、课表 MD 同分区策略，沿用踩坑记录 §7.5 定论）。模拟器侧同一批资产文件直接文件路径加载，**同资产双端渲染**，消灭「模拟器好看真机变样」的第三类失真。

管线实战已踩到的三个坑（首版管线已修，后续正式化时须保留这些处理）：

- **透明 SVG 必须 flatten 再阈值化**：libvips 对无底色 SVG 输出 RGBA 且透明像素 RGB=0，直接灰度阈值化会把所有透明区域判成黑。修法：`.flatten({background:'#ffffff'})` 先于阈值化。
- **libvips 不解析多层 `<use href>` 间接链**：设计稿吉祥物是 `<use>`→`<symbol>`→`<use>`→`<defs>` 三层间接，libvips 渲染为空白。对策：抽取 symbol 主体直接内联，defs 随文档注入。
- **`<text>` 元素可渲染但字体依赖运行环境**：设计稿指定的 Baloo 2 在 PC 上以 Segoe UI Bold 替身出图，真机须以实际 Baloo 2 子集重烘——同资产双端一致性的前提是管线环境装齐设计稿字体。

### 2.4 字体

维持踩坑记录 §7.5 定论（模拟器 FreeType 快速迭代 / 真机 `lv_font_conv` PuHui 子集 `.bin`），补三条增量：

- 数字大号字体（Baloo 2 ExtraBold，设计稿 §04 指定）按同管线单独出一个大尺寸子集。
- **大号数字与图案化文字（如首页大时间）首选 imgfont 图像字体或直接预渲染位图资产**——实战确认：原生标签的行距/基线/字距与相邻图形（如眨眼冒号）对齐是高频痛点，整字块烘成资产一次对齐永久稳定。
- 标题字体（站酷快乐体）需确认授权与栅格化效果，列入管线待验项。

### 2.5 坐标转写

400×300 上「绝对定位 + 资产混排」的碰撞调优是主要工时来源（实战占约一半）。P2–P4 铺开时须把「设计稿坐标 → C 坐标」的转写做成管线一部分（从 HTML style 直接抽坐标生成布局表），不允许手抄。

## 3. 模拟器对齐措施

- 模拟器 LVGL 降级/锁定到 **9.3.x** 与固件同版（固件锁 `lvgl/lvgl: ~9.3.0`）；**已落地（260831-simulator-lvgl-align，2026-09-01）**——当前模拟器已对齐 9.3.x（`lv_version.h` 三号一致 + MSBuild 编译通过）。原始动机不变：9.5 验证通过 ≠ 9.3 无坑（I1 调色板行为差异即实证）。
- `lv_conf.h` 以固件 sdkconfig 的 LVGL 配置为基准对齐（ThorVG 关、单色阈值一致）。
- **加「1bpp 滤镜」验证手段**：模拟器是 32bit 真彩渲染，与真机 1bpp 纯黑白观感有系统性差异（灰度抗锯齿让细线/小字在模拟器上显得比真机可用），至少把「画布快照 + 阈值化 PNG」做成一键自查；**验收图一律以阈值化版本为准**。
- 模拟器窗口固定 400×300（已做，踩坑记录 §1.2）。

## 4. 真机性能预算

- 真机渲染是**软件全屏绘制**：flush 回调逐像素把 RGB565 阈值化成 1bpp 再推全屏，无硬件加速。
- PSRAM 实测占用：LVGL draw buffer 240,000 字节（单缓冲 `LV_DISPLAY_RENDER_MODE_PARTIAL` 整块 PSRAM 驻留）+ RLCD 帧缓冲 15,000 字节 + `PixelIndexLUT`（uint16_t）240,000 字节 + `PixelBitLUT`（uint8_t）120,000 字节。
- ThorVG 矢量渲染真机默认关闭（sdkconfig `CONFIG_LV_USE_VECTOR_GRAPHIC`/`CONFIG_LV_USE_THORVG` 均未设置）——「画复杂图形」的唯一低成本方式就是预栅格化资产。
- 动画区（眨眼冒号、声波条、笔顺步进）局部重绘，吉祥物/框族静态资产不参与高频 invalidation。
- RGB565 资产 Flash 占用按 2 字节/像素估算：实测 P1 全套 8 资产约 96KB，其中大时间字块 55KB。**已核算（TP-B 260831-ui-art-assets）**：全量 47 资产 599,698 字节 vs SPIFFS assets 分区 8M，margin 54.1%、不触发 I1；P4 笔顺字盘（保守整帧 ~3.1MB）是唯一逼近预算项，V3 前须锁「笔形 3 态叠加复用 + 米字格单份背景」打包策略。I1 化仍留真机优化位。

## 5. 分阶段路线

1. 模拟器对齐 9.3 + 资产管线脚本跑通（吉祥物日常姿态一枚出图）。
2. P1 用「骨架+资产」重做，human 模拟器目测（**已按 human 指示以实验代码实战验证通过**，2026-08-31：结构+风格保真达标；实验代码属 `tools/` 一次性验证，待 simulator 包接管正式化）。
3. P2–P4 铺开 + 全局状态演出。
4. 真机联调（SPIFFS 打包、前光下目测）。

## 6. 执行期注意项（留根）

- I1 在真机 9.3 + 文件源（SPIFFS `.bin`）路径下是否可用（bin-decoder 的 `decode_indexed_line` 会查调色板），执行期验证后可回收 16 倍空间。
- 大时间字块动态化：imgfont（数字 0–9 十枚图像字 + 冒号动画），执行期验证 imgfont 在 9.3 的渲染质量（等宽数字表格线）。
- 标题字体（站酷快乐体）授权确认与子集化效果验证。
- 16px 以下 CJK 文字在 1bpp 的可读性实测（真机字体子集化时定字号下限）。
- P4 笔顺「未写笔画的虚线点链」dasharray 观感与契约 D3 canvas 折线渲染的视觉对齐核验（进 P4 dev-loop 包验收注意项）。
- 模拟器实验代码（`kidpal_ui.c` / `gen_assets.mjs` / vcxproj 资产挂接）由后续 simulator dev-loop 包接管重写或正式化，避免实验代码沉淀为事实标准。
