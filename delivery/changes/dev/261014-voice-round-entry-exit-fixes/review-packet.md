## 根因与修法

### 主轮三改动点（r1 收口，已 commit 17e0709）

- **改动点 1（VR-A1，`application.cc` HandleWakeWordDetectedEvent idle 分支）**：唤醒词 connecting 态事件经状态合并被跳过，VOICE 层不推入 → 语音页整轮不显示。修法 = idle 分支在 K6 in-flight 守卫与 `EncodeWakeWord()` 之后、`IsAudioChannelOpened()` 判断**之前**直推轮首 UI 两件（`kidpal_layer_chat_clear_event(KIDPAL_LAYER_EVT_NEW_VOICE)` 为真时 `SetChatMessage("system","")` 清屏 + `kidpal_render_node_voice_begin()`），与 connecting 分支同款语义、与 KEY 路径入口直推同构；置于通道判断前 = 同时覆盖「通道已温直跳 listening」子路径。listening 分支零触碰。
- **改动点 2（VR-A2/A3，`application.cc` tts stop Schedule lambda + sentence_start）**：查字/提醒播报后设备滞留聆听态。修法 = tts stop 出口改三守卫（序即优先级）：① ManualStop 既有语义不变；② 查字收尾（`kidpal_render_node_front_layer() == KIDPAL_LAYER_CHAR_WINDOW` → `protocol_->SendStopListening()` + `SetDeviceState(kDeviceStateIdle)`，查字窗驻留语义零改）；③ 出会话 speak 不回聆听（轮来源采样 `speaking_round_entered_from_ != kDeviceStateListening` → `SetDeviceState(kDeviceStateIdle)`）；else 保留对话轮回聆听（连续追问保护 §2.1）。轮来源在 sentence_start 处 `SetDeviceState(Speaking)` **之前**采样。
- **改动点 3（VR-A6，`server/deploy/engine-patch/connection.py` `_kidpal_try_speak`）**：引擎原生 `speak_txt` 为同步函数（返回 None），旧形态 `await speak_txt(...)` 对 None 求值抛 TypeError 进 except、每轮提醒必报 ERROR「播报注入失败」。修法 = 同步直调（去 await）；外层 try/except 降级语义（V20「弹窗+提示音必达」）不变。

### 补充轮两修法（r2 收口，本轮 working-tree diff）

- **A1（VR-A9，主因，CONFIRMED，`application.cc` sentence_start 采样写点）**：`sentence_start` 是**逐句**消息，而 `speaking_round_entered_from_ = GetDeviceState()` 写在同分支内、紧邻 `SetDeviceState(kDeviceStateSpeaking)`——注释自称「每轮重置 single write point」，**实为逐句写点**：第 1 句状态仍 Listening 采样正确，第 2 句起状态已 Speaking **覆写采样 = Speaking** → 收尾判据③ 吃被覆写的 Speaking → 多句对话轮播完即回 Idle（真机证：7 句妖怪轮 / 5 句天气轮末段 `speaking -> idle`；单句打招呼正常）。**修法** = 写点前加 `if (GetDeviceState() != kDeviceStateSpeaking) { speaking_round_entered_from_ = GetDeviceState(); }` 守卫——「逐轮一次」由「状态离场 Speaking 才重采」自然保证（轮间 tts stop 已把状态推出 Speaking、下一轮首句必重采；abort 后同样自然重采，与原注释意图一致）。
- **A2（VR-A10，次因，CONFIRMED，`websocket_protocol.cc` `OpenAudioChannel()` 顶部）**：唤醒时通道超时（`IsAudioChannelOpened()` false 但 TCP 未断、`Protocol::IsTimeout()` 120s）→ idle 分支 `OpenAudioChannel()` 阻塞主循环于 TLS 握手；其间 `CreateWebSocket(1)` 裸重赋值析构旧 WebSocket → 其断连回调走 `local_close_pending_ == false` 路径（该标志刚被复位）→ 误判「服务端/网络侧断」→ `Schedule(SetDeviceState(Idle))` 积压到主循环解阻后才跑 → 压在新会话 `connecting -> listening` 之后，产生 `listening -> idle` 毛刺。**修法** = `OpenAudioChannel()` 顶部、`local_close_pending_ = false` **之前**加 `if (websocket_) { CloseAudioChannel(); }`——旧通道按本地关分类拆除，`websocket_.reset()` 同步等 receive task 退出，stale 回调当场抑制。真服务端/网络侧断分支（`local_close_pending_ == false` 路径）零改动。

**正交矩阵（缺一不可，plan 节）**：修 A1 未修 A2 → 冷通道毛刺仍把首句前状态打成 Idle（冷通道单句打招呼仍错）；修 A2 未修 A1 → 暖通道多句轮第 2 句覆写 Speaking → 回 Idle（连续追问仍错）。
