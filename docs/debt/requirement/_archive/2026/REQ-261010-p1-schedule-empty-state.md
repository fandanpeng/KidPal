**定性：需求设计缺口，非实现 bug。** S-F1.1 四条 AC（AC1 版式 / AC2「Given **今日有日程**」分组列举 / AC3 电量 / AC4 断网）**没有任何一条覆盖「今日无剩余安排」或「明天无安排」的空态**——AC2 的 Given 直接从「今日有日程」起笔，空态语义在 spec 层缺席，实现「无值不渲染」是对 spec 沉默的忠实执行。对比：P2 课表页有明确空态条款（S-F1.2 补充规则「断网或未收到推送时翻到本页显示友好空态提示（引导孩子用语音问课表）」），P1 首页没有对称条款——而 P1 是 90% 时间常显的主面，「瞟一眼就知道接下来该干嘛」正是设备定位（§1）。

**实现侧现状（取证）**：`home_upcoming.c:413`「preview:null 容忍（明日无项 = 无预告，不降级）」——明天区空 = 整区不画；「接下来」列表空 = 标签下无行。真机观感 = 用户报的「压根不显示，搞不清是没有课还是出了问题」。

**修法（走 /requirement-change，档 1 语义修改）**：S-F1.1 补空态条款，需区分两种空态语义（正式定稿归 story-author + requirement-reviewer，human 拍措辞）：
1. **无安排空态**（云端算过、确实没课）→ 各区显示友好默认话术——human 已提方向「明天没有什么课喽」（明天区）；「接下来」区对应「今天接下来没有安排啦」式话术。话术按 v1.58 纯文本同款字号渲染，占位不破布局优先级（接下来 > 明天区 > 小伴演出）。
2. **数据未达空态**（断网/未收到推送）→ 与 AC4 断网小标联动，回引 P2 空态口径（友好提示、引导语音问课表），不与「无安排」话术混淆——这正是本次用户「分不清没课还是坏了」的病根，两态必须在需求面显式分叉。

需求定稿后 dev-loop 落地：空态话术渲染归 P1 dev 包（若与 v1.57 登记的 V5 版式重排批〔home_p1.c 按 V4 实现〕同批做可省一轮烧录）。**riskTier: low**。

**结项（2026-10-11，主线程销行，§9 v1.61 定稿）**：human 指示起草后走 requirement-change 档 1，两轮 author/reviewer 闭环定稿 v1.61。起草期口径升级：human 三答改判「明天区并学校课」（翻转 v1.57 OQ2「仅课外班与临时事件」）——学校课合并「XX:XX 上学」项进明天区，上学日必然非空、「空态联动上学日」由该项承载；空态话术定稿「今天接下来没有安排啦」/「明天没有什么课喽」，数据未达空态判据落「有无日程数据」非「断网与否」（AC7 与 AC4 分层）。渲染落地 + 明天区多项化 + V5 版式重排 human 裁同包一块做（含契约门：`data.upcoming.preview` 单项→多项 + 「明早」示例旧漂移，对账登记在 S-F1.1 补充规则 6c）——本条需求面义务已毕，落地追踪转 dev 侧（triage → 拆包 → launch），不再挂本账。
