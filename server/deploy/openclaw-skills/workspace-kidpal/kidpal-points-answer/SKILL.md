# KidPal 积分问答（我现在多少分 / 最近得了什么）

孩子或板子问起积分（星星）时走本 skill：问「我现在多少分 / 积点 / 星星」「最近得了什么分 / 为什么加分」「够不够兑换 XX」「离目标还差多少」——答复只能来自动态 context 的「积分摘要：」行，或本回合实际读到的 `/opt/kidpal/points/state.json`（二者同源派生）。注意摘要行只在会话从积分页（积分本 / 详细账本）进语境时注入；平常用聊天进语境时它显示「（本次会话未提供）」，这时按下面第 2 步兜底读源——**摘要缺席不等于零分**。

**没有事实依据绝不凭印象报数**——没读到摘要、也没读到账本就报数字，就是编造。这里的「上下文残影」= 模型自己的记忆、往轮印象或「差不多记得」，**不是**动态 context 的积分摘要。2026-11-14 真机实证：引擎的摘要填充缝已在工作（会话态里确有积分摘要），模型却答「我看不到积分」——缺的正是本 skill 这层「摘要优先 + 兜底读源」的指令，与课表 skill 同型（课表先例：摘要优先、摘要没覆盖再读文件）。

## 步骤

1. **摘要优先**：先看动态 context 的「积分摘要：」行，形状是 `当前积分 N 分；目标「X」M 分；最近记录：事由 +N；事由 -M；…`（由 front 从 `points.py` 权威状态单源派生，等同本回合读到的事实）。
   它覆盖的问题——当前余额、激活目标与目标分值、最近三条记录内的事——**直接用摘要作答、不必再读文件**。
   完成判据：报出的每个数字都能在摘要行里逐字找到。

2. **兜底读源**：下列情形只读 `/opt/kidpal/points/state.json`（本机绝对路径、只读）再答：
   - 摘要行显示「（本次会话未提供）」或缺行（= 本会话不是从积分页进语境，最常见的一个）；
   - 问最近三条之外的历史、全部记录、某天或某件具体的事；
   - 问某条的分录字段（变动前后余额、记账先后、revision 这类账本细节）。
   读到的形状（以盘上代码为准）：顶层 `revision` / `balance` / `entries`，条目存在时可另有 `targets`（自定义目标，四键 `id/name/points/asset`）与 `active_target`（激活目标 id；**缺这个键 = 出厂默认目标「游乐场」40 分**）。
   `entries` 是时间倒序的六键分录：`id` / `delta`（正加分、负扣分）/ `reason`（事由）/ `occurred_at`（UTC ISO）/ `balance_before` / `balance_after`。
   完成判据：拿到顶层 `balance` 与需要的分录行。

3. **`balance` 是权威余额，不许自己加分重算**——不要把 `entries` 里的 `delta` 求和当余额，也不要把首条的 `balance_after` 当余额：删改重算、负分录、旧账迁移都可能让两者与权威余额不同。目标分值取摘要或 `active_target` 指向的目标（缺键 = 游乐场 40 分）；账本里没有的目标，不报它的分值。

4. **两段格式作答（语音部分 + 末尾一个 display 块）**
   - 语音部分口语化、简洁（说给孩子听）：
     - 「我现在多少分」→ 直接报数 + 目标进度一句，例如「你有 20 分啦，游乐场要 40 分，还差 20 分」。
     - 「最近得了什么分」→ 按 `entries` 时间倒序念**最近三条**，每条「事由 + 分值」，例如「帮妈妈收拾碗筷，加了 3 分」；再往前的说「更早的在详细账本里」，不逐条念全账。
     - 「能不能兑换 XX」→ 只报「够 / 不够 + 差多少分」，例如「还差 20 分，攒够就能换」。**不执行兑换、不报成功**；兑换由孩子按板子上的兑换键、网关执行器落账。
   - display 块用 **`text` view**：`{"view":"text","data":{"text":"…"}}`——与百科问答同一问答框，不缩略成摘要。
     **绝不下发 `points_home` / `points_ledger` 块**：积分页由网关按权威数据机械推送，模型不抢屏、不生成任何一条记录。（孩子明确说「打开积分本 / 看详细账本」时，按 workspace AGENTS.md 积分节发 `{}` 薄载荷，那是导航意图、不是本 skill 的问答载荷。）
   - 完成判据：回复 = 语音部分 + 末尾合法 display JSON（text view）。

5. **日期口径**：`occurred_at` 是 UTC ISO 时间，说「今天 / 昨天 / 11月5日」之前先换算到 Asia/Shanghai（+8 小时）并用 `date` 核对今天日期。别把 UTC 的深夜算成同一天——例如 `2026-11-14T23:30:00+00:00` 在本地是 11 月 15 日早上。

## 验证

- 每个报出的数字都能在摘要行或 `state.json` 里逐字找到；余额取顶层 `balance`，不是自己加出来的。
- 摘要显示「（本次会话未提供）」时没有凭空报数，也没有把缺席当成 0 分。
- 兑换类问题只有「够 / 不够 + 差多少」，没有任何写动作、没有「已经换好了」式宣称。
- display 块是 `text` view；回复里没有 `points_home` / `points_ledger` 块。
- 说「今天 / 昨天」的日子，按 Asia/Shanghai 换算后与 `date` 实际日期一致。

## 边界（板侧 agent 专属）

- **只读、零写权**：本 skill 只读 `/opt/kidpal/points/state.json`。**绝不**执行 add / redeem、绝不写 state、绝不改目标、绝不调任何写命令（含 `python -m gateway.points` 一类 CLI）。单 writer = 网关 front 与 `points.py` 执行器（D-10：模型只产薄意图，确定性模块写账），模型侧零写权。
- **只读一个源**：不读第二账本、不猜别的路径、不把回执或缓存当账本。文件不存在 / 读失败 → 诚实说「我现在看不到积分本，你看一眼小伴屏幕上的积分页」，不编造数字、不虚称已查。
- **不宣称记账结果**：不说「已经帮你记上了 / 兑换成功了」，除非网关推来的权威结果就是那样；余额、分录 id、变动前后余额、revision、游标这些权威字段一律以账本为准，不由你生成。
- **与注入 system prompt 的关系**：动态 context 的「积分摘要：」行由 front 从 `points.py` 权威状态派生（契约 §四 `kidpal_session_ctx` 的 points 两值半）；静态纪律在本 workspace 的 `AGENTS.md`。两者冲突时以 `AGENTS.md` 为准；本 skill 只补「怎么用摘要、摘要没覆盖时怎么兜底读源」这层操作指令，不改任何纪律。
