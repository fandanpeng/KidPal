## 3. 摩擦与卡点（按痛感排序）

**F1 · 我把「子目录口径」误升格为「闸口径」——判官真跑闸抓出（BLOCKING）**
- **现象**：§1 写「验收闸固件面枚举到的 **13 件全在归档目录下、现役 0 件**」。R1-F1：**真跑闸**实测 `firmwareAcceptanceFiles: 20`——真身是**归档 13 + 现役 7**。根因 = **我只扫了 `firmware/main/test/acceptance/` 一个子目录，未核对闸的枚举根**（`acceptance-run-check.mjs:137` = `const fwDir = join(root, 'firmware')`）。
- **根因**：**用自己的复刻脚本代替了「跑真东西」**。我按闸的 `collectFiles` 逻辑复刻了一份，但**给错了根**——复刻逻辑对、输入错，而我没跑一次真闸来校验输入。**危害定性也因此写错升级**（原写「oracle 输入集只剩退役件」，实为「20 件里混着 13 件退役」）。
- **证据锚**：§7 R1-F1；v0.6 的双口径更正段。

**F2 · 修正时又新引入一处机制错（R2-F7）——「退役断言会被计入现役结果」不成立**
- **现象**：F1 更正的**后半句**「退役面上的断言失败会被计入现役验收结果」被 R2-F7 判**机制不成立**：该闸固件面是**结构闸**（`fwAccFiles` 只喂 `decide()` 的存在性判定与 `surfaces` 计数，**不执行任何断言**），且 host_app runner 用**显式清单**（CMakeLists 恰列 7 件现役件、注释明言归档件「不再编入」）⇒ **退役件无通道进入现役结果**。
- **根因**：**修一个错时顺手补了一句未验证的机制解释**——「更严重的后果」听起来合理，但没核通道是否存在。**这与 P1/P2 的「处方未实测」同族：都是「听起来对」压过了「跑一遍」。**
- **证据锚**：§7 R2-F7；v0.7 的据实回收（改为 ARQ-260916 原口径）。

**F3 · 起草期从 ARQ 搬运的数字有一半是错的（三处引据漂移 + 总数 7→20）**
- **现象**：`ARQ-260908-tighten-only-unwritten` 记「**7 份**冻结件带 REVISION LOG 页脚」并给 7 个 `file:line`。现跑核实：**总数 20 份**（含 6 份**现役**），且 **7 个引据中 3 个已漂移**（原文指正文行而非页脚行）。
- **根因**：ARQ 的取证时点距今已久，而数会随仓前进腐化。**该更正强化了本条主张**（使用面比记录宽得多 ⇒ 成文必要性更高），所以「搬运期引据不得免检」这条纪律（硬项 1a）确有价值。
- **证据锚**：§1 的「数字与引据更正申报」；v0.6。

**F4 · V1 的件数预测在落地时已过时（时点变化，非失误）**
- **现象**：FROZEN §5 V1 写「20 → 7」，落地时实测 **22 → 9**——因为落地前执行了 **main → gov 回同步 merge**（四批共同前置），带进 m2 系列的 2 件新现役验收件。
- **根因**：**契约（FROZEN）与实际仓库之间隔了一次前置操作**；凡 FROZEN 里写死具体件数的验证项，在前置 merge 之后都可能失效。**改法（集合补一个成员）与危害定性都不受影响**，但读数会吓一跳。
- **证据锚**：landing-summary §3-1；verdict 独立复测判「申报属实」。

**F5 · 判官自己也出一处算术 slip，被我照抄（R2-F10）**

- **证据锚**：§7 R2-F10；v0.7 的更正。

## 4. 优化建议（按 ROI 排序）

1. **「跑真东西」应成为断言前的硬纪律**（载体：**ARQ 收件箱 / `gov-arq` skill**）——F1 的根因是我用复刻脚本代替真跑。**凡断言某个闸/脚本的输出，必须至少真跑一次**；复刻只可用于解释、不可作为断言的唯一依据。**本批 ROI 最高的一条。**
2. **「修正时不要顺手补机制解释」**（载体：**ARQ 收件箱 / 写作纪律**）——F2 的教训：修正一个错时，新补的解释句**须与原文同等验证强度**。
3. **搬运任何数字（ARQ / 判官记录 / 旧制品）都须复算**（载体：**已在硬项 1a 内有原则，建议 `/loop-retro` 观察其执行率**）——F3（搬 ARQ）与 F5（搬判官）同病。
4. **FROZEN 里写死件数的验证项，落地前须重测一次并允许申报时点偏差**（载体：**`docs/templates/PROPOSAL.template.md` / 或随下一批**）——F4 的教训：前置 merge 会改数。
