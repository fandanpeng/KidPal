# 星星积分本：功能与页面讨论记录

- 日期：2026-11-03
- 状态：讨论中（grilling 需求盘问阶段）；本文记录积分本已确认的账本语义、页面结构、兑换规则、加减分通道与目标配置
- 文档性质：想法讨论记录，不替代 `docs/requirements.md` 等正式需求文档
- 关联：主页面循环与故事封皮见 [261103-story-cover-navigation.md](261103-story-cover-navigation.md)；积分首页线框见 [docs/notes/showme/261103-star-points-home-wireframe.html](../../docs/notes/showme/261103-star-points-home-wireframe.html)

## 概念边界（已确认）

- 积分与故事星星是两个独立概念：积分是家长针对做家务、在学校受表扬等具体表现给予的奖励；故事星星是星星记录本里保存的篇数。
- 两个数字互不影响：记录故事不加积分，做家务不动故事星星，删除故事记录也不影响积分。

## 主页面（已确认：单页进行中）

- 定位 = 看得见进度的奖励账本，不是任务清单。
- 只有一个页面，始终处于进行中状态——曾讨论过「已达成待兑现」「暂无目标自由积累」两个附加状态页，human 裁定收敛为单页，不设独立状态页。
- 版式（线框已按此绘制）：
  - 顶部 = 页名 + 当前积分（金币图标内嵌五角星 + 数字）。
  - 中部 = 一条横向进度线：起点、分值刻度、当前激活目标的场景标（出厂默认 = 游乐场 40 分城堡）画在激活目标的分值位；小伴标志放在线上代表当前余额位置；已走过的部分为实线、未走到为虚线。
  - 不放「再得 N 分就能去游乐场」一类解释文案。
  - 下部 = 最近三条积分记录（分值 + 原因 + 日期）+ 「详细」入口。
- 积分符号统一用金币（圆形外框内嵌五角星），与故事星星在视觉上区分。
- 进度线只随余额变化，不换页面：当前 28 分 = 小伴停在 28 分位置；超过 40 = 实线与小伴越过城堡继续延伸；兑换扣分后按新余额重画（如 63 − 40 = 23，小伴回到 23）。「是否够 40」只是小伴与城堡在线上的位置关系，不是页面状态。

## 详细账本子页（已确认）

- 「详细」进入完整账本列表页，形态与故事列表一致（时间倒序、分屏浏览；human 原话「就跟我们 story 那一样」）。
- 账本同时容纳加分与扣分记录，每条 = 分值 + 原因 + 日期；当前余额是全部记录的计算结果。记录默认保留，误记可显式删除（删除规则见下节），删除后余额重算。
- 页内浏览与返回沿用故事列表的模式：BOOT 浏览条目，KEY 长按逐层返回（详细账本 → 积分主页 → 首页）。

## 兑换规则（已确认）

- 攒到当前激活目标的分值 = 具备兑换资格（出厂默认场景 = 40 分游乐场），不自动扣分。
- 扣分只发生在奖励实际兑现之后，绝不提前扣：哪怕已经定好明天去游乐场，余额也不动；万一临时没去成（如下雨），什么都不用处理——从未扣分，余额与小伴位置保持原样，改天真去了再扣。兑现后经一次明确的兑换确认产生一条 `-40` 记录；同一次兑换不重复扣分。
- 兑换动作要求当前余额 ≥ 激活目标分值（不足不能兑换）。**删除重算允许负余额（human 2026-11-03 触点① 裁定，覆盖此前「余额不允许为负」底线）**：如加 50 → 兑 40 → 删那笔 +50，余额重算为 −40；负余额的进度线画法（小伴钳位、负数显示）留需求起草/线框迭代。
- 兑换是一笔正式的负向账本记录，不是把计数器直接减 40；记录保留完整来龙去脉 = 兑换名目 + 分值 + 日期 + 兑换前/兑换后余额（示例：兑换游乐场 −40，2026年11月3日，兑换前 42 · 兑换后 2）。
- 多余积分保留不清零（42 → 2）；已有加分记录全部保留。
- 兑换后仍是同一个进行中页面：余额与小伴回到新位置，账本继续累计。

## 加减分通道（已确认）

两条通道最终都落成账本里的一条记录（分值 + 原因 + 日期），设备端不直接改余额，余额永远由账本算出：

- **设备语音自报**：孩子在 KidPal 设备上直接说（如「我今天主动洗碗了，加 5 分」），系统解析分值与事由后立即记账，并自动跳转到积分本页面展示。设备不区分说话的是家长还是孩子，自报即到账（human 拍板）。**语音兑换也开放（human 2026-11-03 拍板「加分+兑换都行」）**：说「我们去完游乐场啦」类语句可触发兑换扣分（扣当前激活目标的分值）；删除不开放语音（仍 = 设备详情页按键 + QQ）。
- **触发语句门槛（human 2026-11-03 拍板）**：加、扣都必须是**明确完整的记账句式**——事由 + 动作词（加/扣）+ 分值（如「我今天扫地了，加5分」「我们今天去游乐场了，扣40分」）才触发记账并跳积分页；只提事件、不带分值动作（如随口说「我们去游乐场了」）一律**不触发**，走普通对话。
- **扣分金额校验（human 2026-11-03 拍板「只认目标分值」）**：语音扣分只认「扣的分数 = 当前激活目标分值」这一种语义；金额不匹配（如目标 40 说「扣20分」、目标已换 50 说「扣40分」）→ 温和拒答并说明当前目标要扣多少，不落账。惩罚性扣分的口子保持关闭。
- **重复语句短窗去重（human 2026-11-03 拍板）**：短时间内（如 10 分钟，真机调优定数）分值相同且事由相近的重复记账句 → 不记第二条，友好回应「这条刚才记过啦」并跳积分页；兑换侧「同一次不重复扣分」先例推广到加分。
- **离线边界（沿用仓内既有口径，不另立）**：账本云端为唯一真相源、业务数据不落本地（NFR-OFF-1 同型）；断网时语音记账/兑换失败给可见安抚话术（「现在联系不上账本，等会儿再试」），不做本地暂存补记；积分页数据未达时沿用故事列表两态空态先例（S-F1.1/S-F2.1 AC5/AC6 同型：数据未达不显计数 + 话术，确认无记录显 ×0 类计数）。
- **QQ → OpenClaw（家长通道）**：家长在 QQ 给 OpenClaw 发消息（如「给小伴加 3 分，今天老师表扬了」），OpenClaw 解析后记账，设备端经云端推送更新显示（机制同类 = 星星列表恢复推送）。兑换确认天然走这条通道。**账面规则与设备语音完全同构（human 2026-11-03 拍板「与语音同规则」）**：加任意分 + 事由；扣分同样只认激活目标分值、不符回说明；可删任意记录、可设置/切换激活目标——账本语义全渠道一致，惩罚性扣分的门对所有通道关闭。

## 删除规则（已确认）

- 适用范围 = 加分记录与兑换扣分记录都可删除（human 裁定「减分这一块也能删」）。
- 设备端交互照抄故事列表成熟模式：BOOT 长按选中条目 → 「删掉这条？」整屏确认弹窗（同族 WF-F2-05：KEY 确认、BOOT 取消、10 秒无操作静默取消）。
- QQ 通道同样支持删除（家长发消息删除指定记录）。
- 删除后余额立即重算（如误加 50 分，删掉后余额回到删除前的值）。

## 键位

### 积分主页面（已终审，2026-11-03 human 拍板「KEY短按=语音」）

- KEY 短按 = 开语音会话（积分语境：问答 + 记账，与首页/课表一致；线框原「KEY短按=详细」提案不取）。
- KEY 双击 = 打开详细账本（本页引入双击消歧，~300ms 单击延迟，故事列表先例同型）。
- KEY 长按 = 回首页；BOOT 短按 = 主页面循环下一页（故事封皮）。
- 详细入口的屏上发现性：「最近得到」区「详细 ›」标记 + 键帽/提示承载「KEY 双击」口令；线框待同步（keycap「详细」→ 语音口径 + 双击提示）。

### 详细账本页内（已终审，2026-11-03 human 拍板）

- 形态 = 故事列表同型：BOOT 短按移动选中 / 双击翻屏；BOOT 长按 = 删除确认（KEY 确认 / BOOT 取消 / 10 秒静默取消）。
- KEY 短按 = 开语音会话（积分语境：问答 + 记账，带账本上下文——浏览时问「我为什么得了3分」最顺手）。
- KEY 长按 = 返回积分主页（逐层返回：详细账本 → 积分主页 → 首页）。

## 目标配置（已确认，2026-11-03 human 拍板）

- 目标做成活的：**预置场景库**，每个场景 = 奖励名 + 目标分值 + 场景美术。**第一版清单（human 2026-11-03 拍板）**：
  | 场景 | 目标分值 | 备注 |
  |---|---|---|
  | 巧克力 | 20 分 | 低价位短周期 |
  | 看电影 | 30 分 | |
  | 游乐场 | 40 分 | **出厂默认激活**，线框已画（城堡） |
  | 礼物 | 50 分 | |
- **QQ 可新增自定义奖励（human 拍板）**：家长经 QQ 提供奖励名 + 目标分值，云端入奖励配置并可删除/切换；连带默认口径 = 预置场景有专属美术，**自定义场景在进度线上用通用标记图**（不做逐个定制美术）；自定义分值建议钳在合理区间（如 5–200，起草时定数）。
- **同一时刻只有一个激活目标**（多标同线方案不取）：场景标画在当前激活目标的分值位；家长经 QQ 通道设置/切换激活目标。
- **出厂默认激活「游乐场 40 分」**，保证单页进行中模型恒有目标、不存在「暂无目标」页面态。
- 分值刻度线随激活目标伸缩（激活 60 分目标时刻度画到 60）；设备端不设目标（目标设置只走 QQ 家长通道）。

## 连带决定（沿用仓内既有口径，2026-11-03 记录）

- **页点 4 点制**：主页面 3→4 页后中槽显示 4 点；封面、故事列表、阅读态都显示 4 点、第 4 实心（列表/阅读 = 故事模块子页，模块身份 = P4）；删除确认、录音等覆盖层按既有覆盖层口径页点消失（requirements §2.2 键帽条行）。
- **语音切页目标**：「打开积分本」→ 积分主页；「打开故事」→ 故事封面（不跳过封面直进列表）；「打开详细账本」→ 详细列表。
- **QQ 推送不抢前台**：加分/扣分/切目标经 QQ 到账时只更新数据；正在积分页则原地刷新，在其他页不抢前台（恢复推送「只填缓存不抢前台」先例同型）。设备语音路径例外——孩子主动说记账句，记完跳积分页（已确认）。
- **积分页常驻语音入口提示**：沿用故事列表 AC3 先例（如「说『加5分』就能记账」类提示，措辞归文案单源/设计稿）。

## 已批示不做（2026-11-03 human 批示，第一版）

1. 余额越过激活目标分值时的一次性庆祝演出——先不做。
2. 惩罚性扣分——先不做（与现行建议一致：只允许更正误发并留痕）。
3. 设备语音加分的护栏（如单笔分值上限）——先不做，现行口径 = 自报即到账、无护栏。
4. 页名保留「星星积分本」（human 拍板；金币内五角星呼应，接受与故事页「星星记录本」名称相近）。
