## UI 锚规则块（story 与设计稿的锚定纪律）

1. **粒度**：锚「舞台」——页面画布（`canvas-pX`）与会话状态（`state-*`）；不锚「道具」——图标/字体/组件级资产（`icon-library`/`font-*`/`comp-*`）由设计与实现侧引用，story 不挂。
2. **共享**：跨 story 的状态链在共享底座（§2）钉一次，story 引「共享底座」不重复罗列。
3. **例外**：组件本身是 story 的验收对象时才单锚（如成就盖章 `comp-stamp`）。
4. **指向**：本节引用指「docs/ui/ 现行设计稿」语义，版本更迭只改本行一处；当前 = [kidpal-ui-design-v3.html](ui/kidpal-ui-design-v3.html)。
5. **设计稿锚稳定规约**：`data-od-id` 是约定不是保证——id 只增不随便改，改名/删除 = 有意识的锚维护动作，改设计稿者负责同步本文件引用；出新版设计稿时跑 `node .claude/scripts/spec-anchor-check.mjs --diff-ids <旧设计稿> <新设计稿>`，被 story 引用而消失的 id 必须显式处置（同步改锚或恢复 id），不许静默断。
6. **机检**：每个 UI 锚必须解析到现行设计稿真实存在的 `data-od-id`——`node .claude/scripts/spec-anchor-check.mjs`。

## Story 锚行与撰写纪律（指针）

- 每条 story 末尾的锚行 = 三件：**UI**（设计稿舞台锚）、**支撑**（`arch §x.y`，指向 [architecture.md](architecture.md) 真实小节）、**可行性**三态（✅ 已实证 ｜ 🟡 设计可行·待实证 ｜ 🔴 当前架构撑不住）。
- **🔴 挂账纪律**：标 🔴 必须在同行挂开放问题或 ARQ 编号，不许静默存在；处置路径 = 立项讨论（改需求或改架构），Pod 无权自裁。

## 1. 背景与产品定位

给 8–12 岁小朋友做一个随身学习伙伴。设备本地做「感知 + 显示 + 交互」，云端做「理解 + 生成 + 存储」。三大核心功能：

1. **课表/日程助手** — 记录课表与培训班时间，支持查询与提醒。
2. **故事记录** — 听孩子口述故事，实时转写并归档保存，可回听/回看。
3. **查生字** — 孩子问「某个字怎么写」，设备把汉字的**笔顺/写法**清晰显示出来。

**设备定位**：它**首先是个"常显的信息牌"，其次才是语音交互设备**。平时 90% 时间常显在桌上/书包旁，孩子瞟一眼就知道现在几点、待会干嘛、屋里多少度；孩子有事了才按键交互。

```
【常显状态】屏幕常显（反射屏不耗电）：时间 + 今日日程 + 温湿度 + 电量
【交互状态】按一下 KEY 启动会话（免提说话）/ 按 BOOT 翻页 → 设备响应 → 超时或按键自动回首页
```

## 2. 共享底座：语音会话生命周期、按键与页面结构（所有 story 复用）

### 2.1 语音交互模型（已定：按一下启动会话 + 语音喊停）

**核心：按键只是"激活开关"，一旦激活进入免提会话，无需一直按住。**

```
【常显】屏幕常显信息牌（时间/日程/温湿度）
   │ 按一下 KEY（≈喊了唤醒词）
   ▼
【对话态】设备提示音+屏幕显示聆听中
   │ 孩子说话 → 设备回应 → 继续聆听；可连续追问，不用每次按键
   ▼
【结束】三种任一：
  ① 超时：60 秒无语音 → 自动关闭，回常显
  ② 孩子说"拜拜/不用了" → 判为结束意图 → 关闭
  ③ 再按一下 KEY / BOOT → 手动关闭
```

**语音喊停（MVP 必做）**：AI 播放中孩子**一开口（不管说什么）AI 立即停下并聆听**——既是喊停又是自然插话。孩子说"别讲了"→ 确认停止；说"不对，是勇敢的勇"→ 纠正重答。兜底：KEY 单击 = 随时打断停播（100% 可靠）。

**二期唤醒词**：届时按一下 KEY 可替换为喊唤醒词，其余会话逻辑不变。

### 2.2 状态表（会话生命周期 × UI 演出）

| 状态 | UI 锚点 | 行为 |
|---|---|---|
| 聆听中 | `state-listening`（pose-listen + 麦克风 + 气泡"我在听！"） | 按下 KEY 进会话，三层冗余反馈（竖耳/麦克风/气泡） |
| 思考中 | `state-thinking`（pose-think + 飘问号） | **超 4 秒先开口安抚，不冷场**（回引 NFR-PERF-1） |
| 播报中 | `state-speaking`（pose-talk + 声波条 + 文字上屏） | 语音播放 + 文字同步上屏；声波条跳动表"还在说" |
| 语音喊停 | （播报中插话） | 孩子一开口立即停播并聆听（语义判定在云端）；KEY 单击兜底 100% 打断 |
| 错误兜底 | （云端任一环节失败） | 固定安抚句「**网络出小差了，等一会儿再试试吧**」+ 当轮结束；不静默重试、不曝技术错误（措辞纪律：不说「不舒服」，避免孩子误解）；断线自动重连，屏幕显示不受影响 |
| 提醒弹窗 | `state-reminder`（整屏压 d50 网点 + pose-jump + 铃声） | 覆盖当前页，大字事项+时间；KEY 关闭，BOOT 照常翻页不打断 |
| 低电打盹 | `state-sleepy`（pose-sleep + 月亮 + z/Z） | 电量 ≤ 阈值小伴睡着，充电即"叫醒"，情绪化替代告警框 |
| 页面指示 | 底部页点（4 圆点、当前页实心） | 任何状态下底部提示条 + 页点永不消失 |

### 2.3 按键手势（3 键，无触摸；本节为权威键位定义）

| 键 · 手势 | 全局行为 | 页内特例 |
|---|---|---|
| **KEY** 短按 | 启动/结束语音会话；确认；打断播报 | P2=问课程 · P3 列表=光标下移 · P3 阅读=念给我听 · P4=播/重播笔顺 |
| **KEY** 双击 | （无全局语义） | P3 列表=进入阅读/播放选中 |
| **KEY** 长按 | 回首页 | 所有页面一致 |
| **BOOT** 短按 | P1→P2→P3→P4 循环翻页 | 所有页面一致 |
| **BOOT** 长按 | （无全局语义） | P2=今天⇄明天切换 · P3 阅读=翻下一屏 |
| **PWR** | 开关机（电源管理，不入界面流程） | — |

核心逻辑：平时 BOOT 翻页浏览；有事按一下 KEY 进入语音会话（免提连续对话）；说完自动/手动结束回首页。对话中再按 KEY 可打断。最终手感在 UI 联调时微调。

### 2.4 页面结构（4 页循环）

```
        BOOT 单击 → 切下一页（循环）
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ P1 首页  │→ │ P2 课表  │→ │ P3 故事  │→ │ P4 查字  │→┐
│时间日程  │   │本周课程  │   │我的故事  │   │笔顺演示  │ │
│温湿度    │← │         │← │列表     │← │         │←┘
└─────────┘   └─────────┘   └─────────┘   └─────────┘
```

- **P1 首页**（常显默认）：时间+日期+温湿度+今日接下来日程+电量。按一下 KEY 启动语音会话；到点自动弹提醒（亮屏+提示音）。
- **P2 课表页**：今天/明天课程列表。BOOT 长按切"今天/明天"；语音问"明天有什么课"→ 播报+滚动定位到对应行。课表页只承担"看安排"，不做"当前课"指示（见 S-F1.2）。
- **P3 故事页**：我录的故事标题列表。KEY 单击光标下移选择，KEY 双击进入阅读/播放选中；语音说"我要讲故事"→ 进入录音（显示 ● 录音中），说完自动/按键停止。
- **P4 查字页**：超大字形+拼音+笔画+笔顺演示。语音说"勇怎么写"→ 整屏显示；KEY 单击播/重播笔顺动画（逐笔写出）；继续说"勇是什么意思"→ 释义组词。

> 「查下一个字」不占键——KEY 长按专职回首页（2026-08-29 human 裁定）；「语音查下一个字（指代解析）」的需求可行性挂 §7 开放问题。

**锚（本节级）**：支撑 = arch §2.4（端云职责·音频与会话链路，板）、§3.1（UI 实现策略·渲染，板）、§2.2（服务端架构·网关与 OpenClaw，云）｜ 可行性 = ✅
**NFR 具体化**：思考中超 4 秒先开口安抚（回引 NFR-PERF-1）；错误兜底安抚句与措辞纪律（回引 NFR-SAFE-1 口径）。

## 3. 需求主体（Epic > Feature > Story）

Story 编号 `S-Fx.y` 发布后稳定，不回收、不复用；每条 story = 五件固定顺序（原文 → AC → 线框 → 补充规则 → 锚行），模板与纪律见 skill `write-story`；AC 编号 = dev-loop 验收齿的回引对账点。

### Epic E1 · MVP「会说话的显示器」

目的：板子作常显信息牌 + 语音终端，最小闭环跑通三大核心功能（课表/日程、故事记录、查生字）+ 通用问答——孩子能用、家长能录。二期（唤醒词、OTA、小程序家长端等）另立 Epic。Epic 不直接带锚，锚由 story 聚合上报。

#### F1 课表 / 日程助手

记录课表与培训班时间，支持查询与提醒。覆盖：首页常显「接下来」、课表页浏览、语音问课表、三段阶梯提醒、家长录入。

**WF-F1-01 · P1 首页线框（400×300 横屏）**（实存，自 spec §5.5 迁入）：

```
┌────────────────────────────────────────┐
│  10:24        星期三 6月26日    🔋85%   │  ← ①大时间+日期+电量
│  ┌─────────┐   接下来:                 │
│  │  22°C   │   14:00 钢琴课            │  ← ②左温湿度 / ③右今日日程
│  │  45%    │   16:30 英语培训          │
│  └─────────┘                           │
│  ☀ 晴  适合户外活动       [按一下 KEY 说话]│  ← ④状态/操作提示
└────────────────────────────────────────┘
```

##### S-F1.1 · 常显首页看「现在几点 + 接下来干嘛」

> 作为孩子，我希望瞟一眼就知道现在几点、今天接下来要干嘛、屋里冷暖，以便不用问大人。

**验收标准**
- AC1：Given 设备常显在首页，When 孩子看屏，Then 看到超大时间（冒号眨眼双点）+ 日期星期 + 温湿度 + 电量。
- AC2：Given 今日有日程，When 看「接下来」卡，Then 学校课合并为一项「XX:XX 上学」，培训班/一次性安排逐项列出，最近一项带倒计时贴纸，再下可带明日预告。
- AC3：Given 低电量，When 电量 ≤ 阈值，Then 小伴换打盹姿态 + 电池图形闪烁（低电打盹态）。
- AC4：Given 设备断网，When 看屏，Then 时间/温湿度/电量照常本地显示、日程区不更新（回引 NFR-OFF-1）。

**线框**：WF-F1-01（实存，标注①②③）。
**补充规则**：数据口径 = 「接下来」分组规则（周中白天学校课合并、时刻取首节；培训班/一次性逐项）由云端算好下发；刷新触发 = 设备联网时 + 每日零点 + 新建日程后即时；布局优先级 = 时间 > 接下来 > 温湿度。埋点 = 无。
**锚**：UI = `canvas-p1` + `pose-daily` ｜ 支撑 = arch §3.1（UI 实现策略·首页渲染，板）、§5.1（决策 26·日程刷新与下发，云） ｜ 可行性 = ✅

##### S-F1.2 · 课表页看「今天/明天的课」

> 作为孩子，我希望翻到课表页就看到今天/明天的课排在哪几节，以便知道书包该背什么。

**验收标准**
- AC1：Given 进课表页，When 看列表，Then 每行 = 圆点 + 时间 + 课程名 + 地点；圆点空心 = 已上完/明天，实心 = 待上。
- AC2：Given 想看明天，When BOOT 长按（或直接说「明天的课」），Then 标题切「明天的课」，每行圆点全变空心。
- AC3：Given 某课已被首页「接下来」标记，When 它在课表页出现，Then 带星标呼应。

**线框**：线框待补（归设计稿迭代）。
**补充规则**：数据口径 = 「今天/明天」按设备本地日期零点切换。已砍联动 = 「当前课反白高亮」（见已砍清单）。埋点 = 无。
**锚**：UI = `canvas-p2` ｜ 支撑 = arch §3.1（UI 实现策略·课表页渲染，板）、§2.7（OpenClaw 功能清单 B1/B2·课表数据链路，云） ｜ 可行性 = ✅

##### S-F1.3 · 语音问课表

> 作为孩子，我希望直接问"我下节课在哪""明天有什么课"，设备告诉我，以便不用自己翻。

**验收标准**
- AC1：Given 任意页，When 按 KEY 说「今天下午有什么课」，Then 设备播报答复，同时屏幕切到课表页并滚动定位到相关课程行。
- AC2：Given 答案较长，When 播报中，Then 声波条跳动 + 文字同步上屏（共享底座播报态）。
- AC3：Given 日程条目带备注（如携带画具），When 语音问课表，Then 答复包含备注内容。

**线框**：线框待补（归设计稿迭代）。
**补充规则**：数据口径 = 备注列参与语音答复（带物可语音读回）。埋点 = 无。
**锚**：UI = 共享底座（聆听→思考→播报） ｜ 支撑 = arch §2.6（核心请求链路·语音问答，云）、§2.2（服务端架构·display 指令下发与显示联动，板） ｜ 可行性 = ✅（human 2026-09-13 实测定案；已知的显示定位问题归 phase 2 符合度审计，不影响可行性标定）

##### S-F1.4 · 日程提醒

> 作为孩子，我希望遇到非常规的事（要带的东西、临时安排）和容易忘的课（周末培训班这类）设备提前主动提醒我，以便不丢三落四；例行去上的学校课我自己看课表就行。

**验收标准**
- AC1：Given 录入了明天要带画具的美术课，When 今天 20:30 到点，Then 设备提示音 + 语音读出提醒文案 + 弹窗驻留（大字事项 + 时间），弹窗驻留到按键。
- AC2：Given 弹窗驻留中，When 按 KEY，Then 关闭回当前页；When 按 BOOT，Then 关闭并照常翻页。
- AC3：Given 弹窗期间另一条提醒到达，When 收到，Then 排队不叠屏；当前弹窗关闭后下一条自动弹出。
- AC4：Given 同一提醒已弹过，When 云端因重算/重推再次下发同一提醒，Then 设备不重复弹窗。
- AC5：Given 设备断网，When 到点，Then 无提醒——设备不缓存事项（回引 NFR-OFF-1）。

**线框**：线框待补（归设计稿迭代）。
**补充规则**：范围口径 = 「学校课程表」区块不提醒（在校例行）；「每周固定课表」（培训班，不论周中周末）+ 一次性安排走三段阶梯，每周固定项每周重复生成；携带内容走课表备注列。三档时刻 = 前一天 20:30 / 当天 07:45 / 事项开始前 15 分钟（全局常量，家长侧可调性后置）。过期口径 = 已过时刻的档位不补发，不追催。权限 = 录入仅家长侧（见 S-F1.5），设备端只读。埋点 = 无。
**锚**：UI = `state-reminder` ｜ 支撑 = arch §2.9（提醒调度与推送机制，云）、§3.1（UI 实现策略·提醒弹窗渲染，板） ｜ 可行性 = ✅

##### S-F1.5 · 家长录入课表

> 作为家长，我希望能方便地录入/修改孩子的课表与培训班时间，以便设备能查询和提醒。

## 4. 体验与视觉风格

- 大字体、高对比黑白、图标化。RLCD 刷新快（~45-70 FPS），**滚动、简单动画、笔顺动态演示都可行**，不必局限于翻页式。可用抖动(dithering)模拟灰度层次。
- **趣味性要求（v2，孩子反馈"太正式"后确立）**：设计需有**吉祥物角色「小伴」（猫咪）**贯穿全局（首页常驻 + 各状态换姿态：聆听/思考/播报/录音/提醒），手绘感圆胖线条、拟人化细节（眨眼冒号、卡通温度计、故事果收集）、克制的涂鸦点缀。检验标准：孩子第一反应是"它好可爱"，不是"这是个闹钟"。详见 [UIUX-DESIGN-BRIEF.md](ui/UIUX-DESIGN-BRIEF.md) §3.1。
- **查字页教学字体红线（v3）**：P4 是教学页，**米字格大框里演示笔顺的示范汉字必须用标准规范字体**（思源黑体/楷体），禁用手写趣味体/抖动/倾斜——孩子会照写，不能教歪。拼音、部首、组词等伴随文字可保留可爱趣味字体。详见 brief §3.3。
- **查字界面**：整屏米字格大框内显示一个超大汉字（充满米字格字盘，设计稿框 236px/字盘约 208px）+ **笔顺逐笔动态演示**（像写字一样一笔笔画出来，教学效果好；可配"握笔小手"沿骨架移动）。
- 字体类需求（如标题用「站酷快乐体」类趣味字体）住本节；其技术支撑锚 = [architecture.md](architecture.md) §3（UI 实现策略：字体转 .bin + SPIFFS 资产管道）。

## 5. 非功能需求（NFR）

> 每条四件：量化阈值、验证方式（怎么实测）、支撑锚（arch §x.y）、可行性三态。story 内的相关表述 = 该 NFR 在具体场景的具体化并回引本章 ID；同一约束全仓只在本章定义一次。NFR 只管「产品必须做到什么」；技术实现约束（介质禁令、证书形态、provider 配置约束）归 architecture.md。未拍数值的阈值带「待定」标迁入，数值拍板走后续立项。

### NFR-PERF-1 · 思考响应不冷场
- 阈值：孩子说完到设备开口，等待超 **4 秒**必须先播安抚句，不冷场。
- 验证：260829-voice-roundtrip 包闭环（VRT-A5：4s 安抚句到达即播）；live 冒烟多轮在档。
- 支撑：arch §2.2（服务端架构·网关安抚定时器）｜ 可行性：✅

### NFR-PERF-2 · 查字端到端延迟
- 阈值：从问「X 怎么写」到笔顺演示开始，目标 **5 秒档**——human 2026-09-13 裁：需求保留，实际效果优化归 phase 2。
- 验证：260829-char-stroke 包 CHR-A9（live 口径不 auto-run）；human 2026-09-13 口述：live 首跑延迟长、查字链路当前不可跑。
- 支撑：arch §2.6（核心请求链路·查字）、§2.8（关键数据格式与笔顺渲染）｜ 可行性：🟡（phase 2 修复优先项，与 S-F3.1/3.2 联动）

### NFR-SEC-1 · 传输安全与强制鉴权
- 阈值：公网入口必须带设备 token（≥128-bit 随机），未设 = 拒绝服务，不留 validation-mode 后门；传输 = wss + 自签长期证书（有效期 ≥10 年，把到期死局推出产品生命周期）。
- 验证：260903-device-ws-switch / 260903-gateway-directionB 包闭环；十年期证书已在用（human 2026-09-13 视同通过；轮换脚本/到期告警子项不拆，一句话覆盖全条）。
- 支撑：arch §5.1（决策 22）、§2.2（服务端架构）｜ 可行性：✅

### NFR-SEC-2 · 儿童数据出网记账
- 阈值：无技术阈值——三条出网路径（① 语音音频 → 阿里云 ASR（境内）；② 转写文本 → OpenClaw → DeepSeek 云；③ 回复文本 → edge-tts（微软非官方接口））human 已知晓并接受（2026-09-03）。
- 验证：决策记账完成（arch §5.1 决策 19）。
- 支撑：arch §5.1（决策 19）｜ 可行性：✅（已接受风险记账，非可行性问题）

### NFR-OFF-1 · 离线边界
- 阈值：断网时仅时间/温湿度/电量可用；无提醒、课表/查字/问答不可用（查字/ASR 需联网，给友好提示）；设备不缓存任何事项。
- 验证：260829-schedule-reminder 包闭环（RMD-A7 断网无提醒）。
- 支撑：arch §5.1（决策 24）｜ 可行性：✅

### NFR-SAFE-1 · 内容安全
- 阈值：答案口语化、3 句以内、适合 8–12 岁（生成端约束）；MVP 接受 system-prompt 级约束 + ACCEPT-AS-RISK 记账；明确排除「家长逐条审批」形态；机械内容过滤层留作日后合规选项。
- 验证：human 2026-09-03 裁定在案（决策 28）；超限按有处理的失败模式（截断/分屏）而非仅记遵循度缺陷。
- 支撑：arch §5.1（决策 28）、§2.2（服务端架构·格式校验与超限处置）｜ 可行性：✅

### NFR-READ-1 · 1bpp CJK 字号可读性下限
- 阈值：**待定**——16px 以下 CJK 在 1bpp 真机的可读性下限未实测；实测前按可读字号排版、行数自然变多、滚动承接。
- 验证方式（human 2026-09-13 定）：后续技术包单独烧一个版本，单页排不同字号实测对照（ARQ-260831-small-cjk-1bpp-readability）。
- 支撑：arch §3.1（UI 实现策略·字体资产管线）｜ 可行性：🟡
