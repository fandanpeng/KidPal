## 3. 摩擦与卡点（按痛感排序）

- **F1 · 引据行号漂移三连（同族三次，本批最大纯摩擦）**：现象 = R1 抓 T2 编辑 B/C/D 三处行号漂移、R2 抓 A0 括注一处同类、R3 抓 §2.0 考据行未随 N2 同步——三处全是 file:line 引据类断言 → 根因 = PROPOSAL 多轮改稿中，改动点自身行号随编辑漂移，而「引据行号」不在起草自检的重核清单里（装配锚有 fail-loud 兜底、散文引据行号没有）→ 证据锚 = PROPOSAL §7 R1-F1 / R2-F2 / R3-F4。判官零容忍标准三轮全拦住，未进 FROZEN。
- **F2 · 搭载项授权前提被后续批消化**：现象 = 搭载项 ARQ-260908 的 A.3 四件待重指落点已被 `ARQ-260916-server-mvp-teeth-sweep`（commit `77b6b0cf`）整体归档，「授权重指」的原始问题不复存在 → 根因 = 立项材料里的搭载项引用的是 2026-09-08 的权威清单，其后两个月内处方落点被另一批结构性消化 → 处置 = 主线程复证后把授权问题如实变形（重指 → 逐件结项确认），human 四拍结项，避免按过时前提落一场空重指 → 证据锚 = task_plan P5 节复证记录 + ARQ-260908 归档件结项注记。**「ARQ 处方须实测复证」纪律再次兑现**（本 workstream 连续两批靠它避免了空落）。
- **F3 · 429 熔断打断起草，但草稿已完整在盘**：现象 = architect 起草派发后 429（5 小时窗口耗尽），通知报 failed → 主线程恢复后先核盘上产物：PROPOSAL 63KB 已完整落盘（§0–§7 齐、preflight ok:true、anchorUnion 与 manifest 一致）——agent 死于最终回报之前而非写出之前 → 处置 = 零重跑直接进评审 → 证据锚 = 任务通知 429 报文 + 时间戳（PROPOSAL mtime 09:51 早于中断发现 09:55）。教训 = **中断后先核盘上产物再决定重派/续跑**；与 P4 retro F2 的「中断续跑优于重派」互补——第三态是「已完成，只欠回报」。
- **F4 · 熔断条款字面触发 vs 实质收敛**：现象 = R1/R2/R3 三轮均非 GREEN，条款字面触发；但 findings 逐轮收敛（3 处行号 → 2 处文面 → 1 行散文）且每轮旧项全部实测收口、方向级问题零 → 处置 = 按存疑向严交 human 三选一，拍「换新判官实例再战 1 轮」，R4 单轮 GREEN → 证据锚 = task_plan 决策记录 + R4 记录。条款起了「强制 human 触点」作用而非「强制升轨」——字面触发但实质收敛时，第三选项（换判官）是条党内建的泄压阀，本次验证其有效。
- **near-miss（最险一刻）**：V2 夹具复跑时 `--diff-ids` 用裸版本名传参得 FATAL「设计稿不存在」，差点把「落地后行为变化」误写进 landing-summary——重读脚本用法节（`:25` 相对路径形态）后判定为调用方传参错误而非落地缺陷。若凭一次实跑输出就下结论，会给核验官制造一个假 finding 甚至引发不必要的回改。教训 = **验证脚本的异常输出先对照用法契约再归因**。
- **F5 · V6 负向清单含生成件（核验官 ADVISORY② 同款）**：V6 禁触面空 diff 清单包含 `docs/debt/gov/INDEX.md` 与 `_archive/2026/`，但两者是本批自带的 debt-render 生成件——渲染后跑 V6 必然非空，须人工知道「这两处预期非空」才不误读为红 → 根因 = §5 断言只写了「debt-render 之前」的时点，未把生成件例外写明 → 证据锚 = landing-verdict ADVISORY②。本批主线程按正确时点解读，未造成实际误判。

2. **V6 类负向断言的生成件例外写明**：治 F5 · 载体 = 登记不硬治（verdict ADVISORY② 已留痕；下批 PROPOSAL 起草时顺手在 V6 形断言里加生成件例外句）· 预期收益 = 消「渲染后跑 V6 必红」的误读面。
3. **429 后先核盘上产物**：治 F3 · 载体 = 登记不硬治（本 retro 留痕，与 P4 retro F2「中断续跑」并读成三态：已完成只欠回报 / 半成品可续跑 / 全废才重派）· 预期收益 = 配额类中断不再触发盲目重派。
4. **熔断第三选项先例**：治 F4 · 载体 = 登记不硬治（换判官实例单轮收口已实证；条款本身不动）· 预期收益 = 后批熔断时 human 有本先例可参照，缩短拍板。

## 5. 一句总结

成本 = 子 agent 实测 ~1.24M tokens / 主观 ~6.5 小时（含 ~2h45m 配额等待）/ human 触点 4 次（搭载四拍结项、UI 扩面并入、OQ2 拍丙、熔断三选一）/ 制品 = PROPOSAL（860 行）+ summary + verdict + retro 四件 + 3 条 ARQ 结项（含全场唯一 MAJOR）· 最险一刻 = `--diff-ids` 异常输出差点误判为落地行为变化（未遂）· **保险丝判定：两方独立结构接住了作者偏差**——判官四轮全部实跑亲核，抓出三处行号漂移与一处两读矛盾且零漏放到 FROZEN；核验官独立复核 13/13 逐字节 + 抽查 6 项复跑，并抓出 V6 断言的生成件误读面降级 ADVISORY。最值得带走的一条 = **散文引据行号是 PROPOSAL 里腐蚀率最高的断言类——它不在任何机械兜底（装配锚 fail-loud）覆盖内，只能靠定稿前重核义务补位**。
