> 性质：架构决策的长期留档——每条记「选了什么 / 为什么 / 放弃了哪些备选」。区别于 `delivery/changes/**`（过程证据，按 change 归档）与 `docs/notes/`（经验与策略记录）：ADR 面向「拍板过就不该丢」的决策本体，新会话 / 新成员不考古即可查。
> 落点凭据：human 2026-09-07 裁「放 docs 根目录、和 spec 同级」（OQ3，260907-gov-review-arq-governance-batch-2 T7）——单文件平铺，承本仓单文件 markdown 注册表惯例（对偶 ARCH-REVIEW-QUEUE.md / DEV-GOVERNANCE.md）。
> 写入者：integrator（dev-loop 收口落新增条目）+ 主线程（治理批 landing 落条目）。**append-only：不覆盖、不改写既有条目**；推翻旧决策 = 新增一条并注明 supersedes ADR-XXX。
> 条目格式：每条 = `## ADR-NNN · <决策一句话>`（NNN 三位递增）+ 固定小节：**日期** / **决策** / **理由** / **备选与放弃原因** / **关联**（change-id 或制品锚）。

## ADR-001 · 版本化部署制品的接线不变式：渲染面 == 声明面 == 被测面，且守卫必须版本无关

- **日期**：2026-09-08（TaskPackage `260829-story-p3` 收口；决策本体由 human 于同批裁定，pod-events 决策事件 `c54bbcde-582f-42c2-a337-5260f890a799`，升级单 `80deedcb-1ea8-4550-b1fa-f20c2f0376d7`）
- **决策**：任何以 `.vN` 文件形态版本化落盘的部署制品（当前实例：`server/deploy/openclaw-system-prompt.vN.md`），其「已接线」类冻结守卫必须满足两条：① 守卫从**结构化指向**解析出「当前被接线的那一版」，而不是把版本字面文件名写进断言；② 解析出的渲染面（`apply-xiaozhi-overlay.sh` 的 `PROMPT_SRC`）与声明面（`provider.config.yaml` 的 `system_prompt.{artifact,source,deploy_target}`）必须**集合相等**，且该版文件确实落盘非空、正文逐字携带历史各包的语义锚点。散文提及与前瞻注记**不算**接线。
- **理由**：本包把 prompt 从 v2 forward-bump 到 v3，撞上已 merged 包 char-stroke 的字面断言（要求 `.v2` 被引用）由绿转红——而 v3 逐字继承了 char C1 段落（实测锚点 13 命中 + v2 基座 32 命中），行为完好、只有版本字样变了。两条冻结 oracle 在同一 deploy 面上互斥，不可能同时为真，只能靠一次 human ruling 解开。若沿用字面耦合形状，v4/v5 及每个动版本化制品的包都会复发同款假红 + 同款升级。更坏的一面是「反向失效」：把语料取成整个目录全文 grep 版本字面的守卫（`test_schedule_p2.acceptance.py:583-586` 现状）在 bump 后**仍绿**，因为它靠被引用文件自己的头注和无关散文维持——守卫声称检验「渲染源已切到 vN」而实际什么都没检验，谎报比报红更贵。本不变式的落点是「什么被生产所用」这一事实本身，而非某个版本号字符串。
- **备选与放弃原因**：① 每次 bump 由后继包把前序包的版本字面守卫逐条改指新版——放弃：改已 merged 包的冻结 oracle 需 human 逐次签字（本包即走此路，成本已实付一次），且改的过程正是弱化点；② 前序包只钉「vN 文件存在 + 内容锚点」、完全不钉接线——放弃：会丢掉原守卫真正防的缺陷（prompt 落盘成孤儿文件，overlay 渲染静默 WARN，生产用旧版），实测该缺陷是 char-stroke E3 立齿的初衷；③ 不做版本化、单一 `openclaw-system-prompt.md` 原地改——放弃：丢掉「历史可 diff / 一版一包」的追溯面（v1→v2→v3 演进链是 live 延迟收敛等结论的证据来源，见 char-stroke packet §4）；④ 让 bump 撞红即 fail-closed 停并升级 human 每次裁决——放弃：等于把复发成本永久化，且升级噪声会稀释真跨系统变更的注意力（对偶 ARQ-260907-escalation-cross-system-overfire 的教训）。
- **关联**：`docs/ARCH-REVIEW-QUEUE.md` ARQ-260908-versioned-guard-version-literal-coupling（把本不变式写入 acceptance-author 撰写约定 + 是否设机检门 = 待裁的落地动作，owner=architect+acceptance-author+human）；范例形状 = `server/acceptance/test_story_p3.acceptance.py::test_prompt_carrier_v3_landed_and_wired`（版本 ≥N 容忍 + 两面同指）与 `server/acceptance/test_char_stroke.acceptance.py::test_e3_prompt_v2_wired_into_deploy`（版本无关重指后形态，含两面相等与内容锚点）；载体声明 = `server/deploy/OPENCLAW_SYSTEM_PROMPT_CARRIER`；现状与漂移清单 = `server/deploy/README.md`「OpenClaw system prompt 版本化接线（现状 = v3）」节；过程证据 = `changes/dev/260829-story-p3/review-packet.md` §6。

## ADR-002 · 日程提醒生产侧采「混合分层」：时刻算术与幂等 id 交确定性脚本，语义判断与文案交 agent 回合

- **日期**：2026-09-08（TaskPackage `260829-schedule-reminder` 收口；决策本体由 human 裁定，pod-events `human-decision` 事件 `acaef302-9ddc-4508-b5d3-94023e050f43`）
- **决策**：三档阶梯提醒的**生产侧**分两层，边界按「可机判性」切。① **确定性 python 脚本层**（`server/deploy/openclaw-patch/reminder_schedule_lib.py`，`warm_char_cache.py` 同形态先例）承载全部可离线硬断言的工作：时间串（`17:30-18:30`）解析、按星期/日期落位、跨天映射（前晚档 = 事件日 −1 天）、事前 N 分钟减法、已过去档位跳过、幂等 id 确定性散列（条目 + 档位 + 事件日期）、`alerts/pending.json` 原子写、跨进程条目的机械 schema 校验与坏输入降级；由 **OpenClaw 原生 cron 的 `--command` 载荷**执行（每 15 分钟定期重算 + 家长 QQ 录入即时触发）。② **OpenClaw agent 回合层**承载语义判断与孩子文案：「备注列里哪部分算要带的东西」「念给孩子听的一句话」按 `openclaw-system-prompt.vN.md` 的约定增量产出，写成脚本消费的**语义中间产物**（`semantic.json`，形状 `{entry_key: {title?, speech?, bring?}}`）。脚本对缺/坏语义输入降级继续排程（机械兜底文案，缺备注绝不凭空发明带物）。
- **理由**：让 LLM 做时区算术与哈希不可靠——同一失败形态在 260829-char-stroke 已实证过（离线面全绿、live 面必红）。把算术与哈希收进确定性脚本还有第二重收益：**high 风险包的验收强度得以保全**——三档时刻关系、幂等 id 的三维独立性、过期跳过、原子写这些都能在本机 host 测试里真跑真断言（本包 RMD-A2 的 4 条变异全部转红即其证据），live 面因此可以诚实收缩为「cron 真在跑 + 文件真被写」两条事实，而不是拿一次不稳定的端到端去赌全部正确性。语义那一半反过来**不该**假装能离线验：大模型输出无法被断言锁死，只钉「产物 schema + 约定文本承载 + 对坏输入的降级」。
- **备选与放弃原因**：① **全交 agent 回合**（cron 只发一句 prompt，时刻/id/写文件都由模型产出）——放弃：算术与哈希不可靠，且离线可机判的证据全部退化成 live 抽查，high 包承担不起；② **全交确定性脚本**（含判断备注里哪部分要带）——放弃：那是语义任务，规则化必然误判，且 spec S-F1.4 明写「『备注里哪部分算要带的』由 OpenClaw system prompt 约定钉死」；③ **把三档算术放进 G 网关**（front 自己算档位）——放弃：违反「脑算网关推、网关恒薄」（决策 20）与 RMD-E3 的 additive 纪律，且时刻的家要在服务端配置侧可即时改（放进网关会诱导把常量搬进代码）；④ **让固件承担判定**——直接撞决策 24 哑终端纯洁性（设备零本地事项源由负向扫描齿钉死）。
- **关联**：spec §4.1 S-F1.4（三段阶梯 / V15 幂等 id / V16 预排粒度）与决策 20；契约 `docs/contracts/interface-contract.md` §三（本决策不改契约）；证据 = `.claude/taskpackages/260829-schedule-reminder/taskpackage.json` 的 `notes`【两条 human 裁定】段与 `mutationEvidence`（RMD-A2 四条）+ `changes/dev/260829-schedule-reminder/review-packet.md`。

## ADR-003 · 提醒语音借引擎既有音频链（`speak_txt`）出音；front 不自建合成、不做 opus 编码、不注入二进制音频帧

- **日期**：2026-09-08（TaskPackage `260829-schedule-reminder` 收口；决策本体由 human 裁定，pod-events `human-decision` 事件 `09359e74-005b-45bb-9535-69e19c14ee04`）
- **决策**：提醒到达的三件套（提示音 + TTS 读文案 + 弹窗驻留）中，**语音一半的出音通路 = 借引擎既有音频链**：front 到点向**引擎腿**注入一条内部指令 `{"type":"kidpal_speak","text":<契约 §三 speech 原文>}`，由引擎部署副本认领（`server/deploy/engine-patch/connection.py::_kidpal_try_speak`）并转调引擎现成入口 `core/handle/intentHandler.py::speak_txt(conn, text)`，走既有 edge-tts provider 与已 live 实证的 Opus 下行音频链出音。front 侧**不自建 TTS 合成、不做 mp3→opus 编码、不自己向设备腿注入二进制音频帧**（设备腿 `send_bytes` 恒空 = 可机判红线，被冻结齿 `test_a3_alert_leg_emits_no_binary_frames` 钉住）。降级路径同批钉死：文案缺失 / 注入失败 / 出音异常 → **弹窗 + 提示音仍必达、投递不阻塞**（V20 不对称性：语音是可选增强）。
- **理由**：① 音频链路上「能不能出声」的难点（opus 编码、下行帧序、设备端解码与播放）引擎侧已全部解决并被 260829-voice-roundtrip live 实证过，front 再造一套是**重复实现 + 新失败面**；② 方向 B 的架构定位是「网关恒薄」（决策 23），在 front 里挂 TTS provider 与 opus 编码器会把网关养成第二个大脑；③ 注入内部指令的形态让「提醒播报」与「孩子对话」在引擎里走同一出口，天然继承打断/并发语义，无需在 front 侧另建会话状态；④ 可机判红线清晰（设备腿零二进制帧），裁定本身因此可被验收测试守住而不是靠口头承诺。
- **备选与放弃原因**：① **排程时预合成、音频随推送下发**（spec V20 的字面形态）——放弃：需要在 front/脚本侧引入 TTS 合成 + opus 编码 + 缓存生命周期管理，且缓存必须有界（ECS 实测 Mem available 941MB / Swap 已用 535MB，char-stroke 留根风险 3 同进程面）；本裁定只保留「弹窗必达、合成失败不阻塞」这一半设计意图，「预合成存缓存」半边**未实现且刻意不做** → 由此留下 spec `:332`（V20）与契约 §三 `speech` bullet 的**措辞↔行为口径差**，须走契约门校准（见 `changes/dev/260829-schedule-reminder/docs-delta.md` §C-3），本 ADR 不充当校准凭据；② **到点实时合成但由 front 自己下发音频**——放弃：同上，仍要 front 持编码器；③ **设备侧本地 TTS**——直接违反决策 24 哑终端纯洁性与 spec §3.2「理解语义与合成放云端」；④ **提醒不播报、只弹窗+提示音**——违反 spec「主动播报（2026-09-02 human 定）」的三件套要求（孩子不看屏也能听到）。
- **关联**：spec §4.1 S-F1.4（三件套 + V20 speech 解耦）与决策 27；契约 §三（`speech` 字段与载荷形状不变，本决策不改契约）；引擎补丁授权 = `server/deploy/engine-patch/`（`kidpal_display_strip` 先例已开此形态，ARQ-260907-engine-deploy-patch-drift 在册治理风险）；真机出音与弹窗并发时序殿后 9b + live 齿 `test_a3_live_tts_and_popup_timing_evidence`；证据 = `changes/dev/260829-schedule-reminder/review-packet.md` Findings #2（V20 口径差）与 Simplification Debt 第 3 行。

## ADR-004 · 课表数据链路收归 front 机械计算：周网格/「接下来」producer = schedule.py 单源，OpenClaw 退出载荷生产、专注话术

- **日期**：2026-09-21（契约门五问 human 裁定，随 TaskPackage `260921-m3-k1-cloud-schedule-producer` 契约 diff 同 PR 落地；裁定全文 = packet §5）
- **决策**：① 契约 §1.3② schedule view data 形状重定义为周网格 `{week:{courses:[{day,slot,name,flags}]}}`（扁平形、day 0 基 周一=0、flags 位掩码 bit0=※ 临时安排 / bit1=星标呼应、备注不进网格载荷）；② §1.3⑥ home view 增可选 `data.upcoming`（additive，形状对齐 `home_p1.h` 冻结注入 seam）；③ **producer 归属 = front 机械计算**（schedule.py `group_upcoming`/网格计算单源），OpenClaw（LLM）不再产任何课表 JSON——问课表只走文字答复（备注读回）、显示课表只发意图薄载荷 `{view:schedule, data:{}}` 由 front 截获展开；④ front 机械校验收紧到新形状，旧列表形 schedule data 拒绝并降级提示。schedule.py 模块头旧钉行「不进反白/星标等 UI 语义态」由 flags 位承载取代——※/星标判定信息（一次性安排区块归属、当前接下来标记项）只有云端可知、spec S-F1.2 AC3/AC4 要求板上呈现，属「UI 语义态禁令」的**有据豁免**而非失守。
- **理由**：spec v1.19（2026-09-14 human 裁课表大改）已把 P2 定为周网格、数据口径 = 云端按 B1 三区块算好下发——旧契约列表形是已砍语义，契约滞后（SPEC_CONTRACT_DRIFT）；而周网格与 upcoming 分组的全部输入都在 schedule.md，schedule.py 已是唯一解析器，让 LLM 拼更大更复杂的网格 JSON 是把确定性计算交给不可靠执行者（同 ADR-002 的可机判性切分原则：算术/结构归确定性代码，语义/话术归 agent 回合）。producer 收归 front 单源后，「由 OpenClaw 算 vs front 算」的任何漂移都失去生长土壤；薄载荷截获展开则保证设备恒拿新鲜网格、保持哑终端（决策 24）。
- **备选与放弃原因**：① 新造 view（`schedule_grid`/`home_upcoming`）——放弃：旧 schedule view 无在役消费方（旧验收已 archive、板端旧列表页随 K2 整页重写），原地重定义零迁移成本，新造 view 徒增白名单与设备路由面；② upcoming 走新私有消息（对偶 `kidpal_session_ctx`）——放弃：mcp display 既有通道且 view=home 语义天然贴合首页常显，新增消息类型是更重的契约面；③ OpenClaw 直产 upcoming（决策 26 字面「分组由 OpenClaw 算」）——放弃：分组是确定性计算，交 LLM 引入漂移面；Q4 human 裁 front 机械算，决策 26 字面偏差已过目认可（注记见 K1 plan 取舍点 C）；④ 「今天」列云端下发——放弃：spec 明文设备本地日期零点切换，云端下发引入时区/时钟双源。
- **关联**：契约 `docs/contracts/interface-contract.md` §1.3②/§1.3⑥/§1.5/§1.6/§2.3；CDQ-260921-m3-k1-schedule-grid；packet/evidence = `delivery/taskpackages/260921-m3-k1-cloud-schedule-producer/`（CONTRACT-CHANGE-PACKET.md + architecture-gate-evidence.md）；实现齿 = K1 acceptance（M3K1-A2/A3/A4），prompt v6 影子契约收口归 K3；板端消费 = K2（`home_p1.h` seam 冻结零改、`schedule_page.c` 整页重写）。

## ADR-005 · P2 周网格冷启动恢复采「恢复性推送」：三触发附带重推 grid（`data.restore` 语义，只填缓存不接管前台）

- **决策**：P2 周网格的冷启动恢复不新增触发、不新增消息类型、不触碰决策 24 介质禁令——在「接下来」三触发（决策 26：WS 建连 + 每日 0:00 跨天 + 新建日程即时，producer = front 单源 schedule.py）的推送点**附带重推周网格恢复性载荷**：契约 §1.3② 增 data 内可选布尔 `data.restore`（additive 字段分量；既有「板子行为」条款同步 modifying——无条件接管句逐字改写为带 restore 例外），设备收到 `data.restore: true` 载荷只填 RAM 网格缓存（M3-K2 既有 `s_grid_courses` 渲染缓冲）、不推 SERVER_PAGE 层、不接管前台，P2 在屏时仅重绘本页（同构先例 = home view `data.upcoming` 注入 seam 的「不抢前台」语义，mcp_server.cc home 路由）；`data.restore` 缺省 = 现行为不变（薄载荷展开的语音主动展示无条件接管前台，M3-K3 冻结行为）。恢复性载荷板端入板后解析失败降级 = 静默记日志，不弹提示、不动前台（区别于主动展示路径的 SetChatMessage 降级；front 校验面 V27 降级在入板前独立生效）。断网/未达期间 P2 = 友好空态（空态提示引导语音问课表），离线边界与决策 24 零变化。**部署时序** = 固件先行；旧固件对 `data.restore` 载荷的行为已由仓内代码定案 = **确定性接管前台顶到 P2**（旧固件无 restore 分支，`schedule_page.c:607-613` 对 data 内未知键取忽略语义 + `mcp_server.cc:620-644` schedule 路由无条件 begin_page 为证）；builder 实测复核确认前 ECS 推送开关保持默认关，烧板验证后人工开闸（gate evidence C1 类 closeout condition）。

## ADR-008 · 引擎 `.config.yaml` LLM 段 `model_name` 定为 `openclaw/kidpal`（双 agent 点名定位）；amend ADR-006 的「model_name 零改 / 对引擎不可见」支撑句

- **日期**：2026-10-01（TaskPackage `261001-openclaw-model-name-overlay-drift` 收口；决策本体 = 2026-09-25/10-01 真机 drift 修复的仓内回流，sourceType=drift-report / rigor lite / riskTier low，architect 分流快审 2026-10-01 + human 触点①确认「② 单包 Lite」）
- **决策**：引擎活配置 `.config.yaml` 的 LLM 段 `model_name` 定为 **`openclaw/kidpal`**（点名 agent，双 agent 唯一定位），并同步改四处仓内面：声明面 `server/deploy/provider.config.yaml:62`（`model: "openclaw/kidpal"`）＋ 渲染面 `server/deploy/apply-xiaozhi-overlay.sh:72`（heredoc 直写引擎 `.config.yaml` LLM 段 = live 真源）＋ 探针默认值 `server/deploy/perf-k1/probe_batch.py:42`（`DEFAULT_MODEL`）＋ provider 默认值 `server/gateway/provider.py:32`（`OPENCLAW_MODEL`，无 live 消费方，纯声明一致）。**本条 amend ADR-006 的支撑句**：ADR-006 称「引擎侧 `.config.yaml` 的 LLM 段（base_url `127.0.0.1:18789/v1`、model_name `openclaw/default`）零改，模型选择对引擎与契约 §四完全不可见」——**「对引擎可见」半边随 OpenClaw 演进（单 agent → 双 agent + `ownership: explicit`）失效**：双 agent 下不点名 agent 则引擎无法唯一定位答主（400「Multiple agents are configured, but this operation has no explicit owner」），故 model_name 必须点名 `openclaw/kidpal`。**「对契约 §四不可见」半边仍成立**（契约 §四对 model_name 零命中，只钉 base_url/loopback + 禁 max_tokens）。ADR-006 的**核心决策不受影响**（降 thinking 档 `high`→`off`、模型 primary 恒 `deepseek/deepseek-v4-flash`、出网记账型号名零变动）。
- **理由**：性质为 **drift**（外部演进造成的仓内配置漂移），非某次改动引入的回归。OpenClaw 由单 agent `main` 演进为 `main` + `kidpal` 双 agent（`ownership: explicit`）后，`openclaw/default`（default 无法在双 agent 下唯一定位）在真机部署后触发引擎 400、设备侧对话一律失败。该值早在 2026-09-25 被手工修为 `openclaw/kidpal`，但只落在 ECS 活配置、未回流仓内；261001 的 ECS 重部署以仓内 overlay 重写活配置、把它冲回旧值（备份 `.config.yaml.bak-260930-modelname-clobber`）。活配置已 261001 热修（`docker restart`，探针 `model: openclaw/kidpal` 返 200），本决策管的是**仓内回流**——不修则下次重部署必然复现。渲染面 `apply-xiaozhi-overlay.sh` 的 heredoc 是引擎 `.config.yaml` LLM 段的**唯一 live 真源**，改它才是「防下次 overlay 重部署冲掉」的实质修复；声明面/探针/provider 三处随改保一致性（ADR-001 渲染面 == 声明面 == 被测面）。`openclaw/kidpal` 点名 agent 的定位不随 agent 数量变化（未来新增 agent 仍唯一定位）。
- **备选与放弃原因**：① **只热修 ECS 活配置、不回仓**——放弃：每次 overlay 重部署都会用仓内旧值重写活配置、缺陷必然复现（本次即 2026-09-25 手工修被冲掉的复发实例）；② **保留 `openclaw/default`、改在引擎侧另配 agent ownership/routing 使其可唯一定位**——放弃：须动引擎配置结构面（超出本包 server/deploy 范围），与 ADR-006「零结构隔离」纪律相悖，且把「哪个 agent 应答」的语义埋进引擎侧路由而失去仓内可见性；③ **在 `server/gateway/provider.py` 做运行时把 default 改写为 kidpal**——放弃：该模块 LLM 面**无 live 消费方**（live model_name 由引擎读自身 `.config.yaml` 发起），在无消费方的代码里加改写逻辑是死代码 + 把命名逻辑藏进代码（drift 温床），违反纪律；④ **在契约面固化 model_name**——放弃：model_name 是部署配置而非端云协议，契约 §四不涉，固化会把配置漂移引入契约面。
- **关联**：ARQ `docs/crq/tech/ARQ-261001-openclaw-model-name-overlay-drift.md`（status deferred，trigger = 本包落地后转 closed）；证据 = `delivery/changes/dev/261001-openclaw-model-name-overlay-drift/`（review-packet.md + docs-delta.md）；变更计划 = `delivery/taskpackages/261001-openclaw-model-name-overlay-drift/plan.md`；实现齿 = MNF-A1（仓内旧值零残留：四处显式正钉 + server 现役面残留扫描）/ MNF-A2（PERF-K1 冻结齿 PERF-E1/E2 期望值重钉 + `:917/:939` 失准文案订正）；**amend ADR-006**（本条不覆盖 ADR-006 正文，只修订其 model_name 支撑句）；接线不变式锚 = ADR-001（渲染面 == 声明面 == 被测面）。

## ADR-009 · `data.upcoming.preview` 形状重定义为多项数组并钉三态语义（非空数组 / `[]` 确认空 / `null` 未提供）

- **日期**：2026-10-11（human 契约门 AskUserQuestion 批准，裁定全文 = `delivery/taskpackages/261011-p1-home-v5-rework/CONTRACT-CHANGE-PACKET.md` §5；随 261011-p1-home-v5-rework 同 PR 落地，CDQ-261011-p1-home-v5-rework）
- **决策**：① 契约 §1.3⑥ `data.upcoming.preview` 由单 `{time,name}` 对象重定义为**逐项 `{time,name}` 多项数组**（`time` 钉 HH:MM 字面——K1 裁决自然语言标签不入 wire），承载明日「接下来」全量：学校课合并「XX:XX 上学」（与「接下来」区同款合并规则）+ 课外班 + 临时事件同列，按开始时间升序（requirements v1.61 S-F1.1 AC2，human 改判翻转 v1.57 OQ2「仅课外班与临时事件」口径）。② 数组天然承载**三态语义**并逐态钉死：**非空数组** = 明日项列表；**`[]`（空数组）= 云端确认明日无项**——板端据此显示「明天没有什么课喽」空态话术（AC6 的显式 wire 载体；上学日明天区必然非空，话术仅非上学日可达）；**`null` 或缺省 = 未推送/未提供**——板端显示数据未达友好提示、不显示无安排话术（AC7，与空态话术显式分叉），容忍 legacy 向后兼容不变。③ 板端 seam 同形改：`kidpal_home_p1_schedule_inject(day_key, items, count, next_day_items, next_day_count)`（5 参，preview 列表 + 计数），契约 :155 引用行随批顺修；板端对旧单对象形状保留一个过渡版的解析容忍（部署缓冲防御，不入契约形状定义——过渡性部署缓冲非持久语义）。④ 「明天」chip 定名只落板端渲染资产（spiffs 重烘），不作为 wire 值入契约。
- **理由**：旧单对象形状下 `null` 同时承担「未推送」与「明日确无项」两义，AC6 空态话术无 wire 载体（producer 明日无项发 `null` → 板端无法区分「没数据」与「确认没课」，话术永不触发）；数组化后空数组是天然第三态，零新增字段、零组合矛盾态。AC7 要求「数据未达」与「确认无安排」对孩子可分辨（不清屏、换提示、两态渲染帧分叉），前提是 wire 层先把两态分开。producer 单源纪律不变（front schedule.py 机械计算，ADR-004 延续）；`[]` 语义与「producer 恒发数组不发 None」（plan R1）配对才使 AC6 可达。
- **备选与放弃原因**（CCP §2）：① 单对象扩展字段（`preview: {first, more}`）——放弃：两形状字段并存、板端解析面翻倍，「确认空」仍无载体；② 双形状并存（对象或数组皆合法）——放弃：机械校验与板端解析各自容两形、漂移面翻倍；③ 并行布尔字段（`upcoming_confirmed_empty`）——放弃：与 `preview` 组合出矛盾第四态（布尔 true 且 preview 有项），多一个可漂移源；④ 新 view（`home_upcoming`）——放弃：home view 天然承载、additive 通道在役（ADR-004 先例），新 view 徒增白名单与设备路由面；⑤ 硬拒 `null`/旧单对象——放弃：`null` 是现役在发值、旧单对象是现役板端在解析值，取过渡容忍一个版本作部署缓冲（契约/producer 先行、板端同批跟上）。
