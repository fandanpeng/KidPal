## 3. 摩擦与卡点（按痛感排序）

- **F1' · 核验首轮 FAIL(F1)：5 件接线破坏「current/ 缺席 → exit 0 skipped」短路（核验官抓出）**：现象——acceptance-coverage-check / closeout-check / docs-sync-check / security-check / mutation-check 五件把 `return existsSync(current) ? current : null;` 换成无条件 `.path`，caller 短路失效 → 无 current 场景从 skipped/exit 0 变 fail/exit 1，违 FROZEN「判定语义零变更」不变量 → 根因 = ①新 lib 返回形 `{path,changeId,found}` 与 FROZEN 设计 `{changeId,source}` 有形差、我接线时未逐件核「原短路判据是否保留」；②**我的 V6 回归只测「有 current」一面**（回显在场 + self-check 绿），缺「无 current 改前基线」半边——判官/核验官的「改前原命令作基线」纪律正好覆盖此盲区（判别实证：`git archive HEAD` 独立树，5 件 OLD exit 0 → NEW exit 1）→ 证据锚：landing-verdict F1 段（判别实证 + 影响半径）与修复后 11 件对照（summary §3 注 10）。**修复**：5 件恢复 `existsSync(resolved.path) ? resolved.path : null`（比核验官建议的 `found ?` 更贴原语义：原文只判存在不判可解析），对照 11 件改前/改后 exit 全等。
- **F2' · 新 lib 的 exit 型自检遮蔽宿主（落地期自查抓出、核验前已修）**：现象——lib 初版 `if (process.argv.includes('--self-check')) selfCheck();` 无 isMain 守卫，被 import 时（宿主带 `--self-check`）抢先 `process.exit`，宿主自检末行被 lib 行顶替（`verify.mjs`/`mutation-check`/`taskpackage-required-check` 三件实录）→ 根因 = 我引 `acceptance-id-shared.mjs:182-185` 为「对偶形态」时只抄了「argv 触发」半边、漏了 isMain 守卫半边 → 处置 = 加 `invokedDirectly` 守卫 + 全量回归（宿主自检名全回归）→ 证据锚：本批落地期 self-check 输出对照（修复前末行 = lib 名 / 修复后 = 宿主名）。**此类恰是核验官简报第 5 项「终端 exit 型自检不得挡在后续自检之前」的实例**——若漏网，将是「自检跑了 ≠ 自检真跑了」的真空绿。
- **F3' · summary V1 的 live 佐证不实（主线程自查抓出、核验 PASS 后勘正）**：现象——我写「live 佐证 = landing `git add` 钩子输出新文案」，实况：landing add 时 canary 删除已先行 staged ⇒ 快照非空 ⇒ 回落行未触发（且我随后实测直接调用亦同）→ 根因 = 落笔时把「设计会触发的分支」默认成了「实测已触发」，未实跑即写（批 B F2「单信号源正读数写入正式制品」同族：**未实测的断言以实测口吻落文**）→ 处置 = 勘正 summary §2 V1 行为如实表述 + 交核验官单点复核接受（verdict 维持）→ 证据锚：landing-verdict §8 单点复核段。**跨乘客第 3 次披露类**（批 A R1-F4 / 批 B R1-F3+A1 / 本批 F1+V1 句）。
- **F4' · 配额 429 两次中断判官（过程性，正面应对）**：现象——R2 期两次 429（5 小时窗 → 周配额 → 月配额），判官两次中途终止 → 处置 = 中断点归因（第二次留下「706/490 vs 694/478 差 12 条」中间发现）+ 主线程机械归因（= current 指针副本 12 条）+ resume 续跑（上下文完整、零重跑）→ 证据锚：本会话配额恢复后 R2 一次收敛。**教训（正面）**：长评审环的 resume 机制与「中间发现先落盘、中断不丢」的配合有效——中断前判官已把差额观察写进回执，恢复后一次闭环。
- **F5' · 判官 R2 抓出 census 口径差并以裁定收口（正面）**：判官按文内七类字段映射复算得 706/490，与申报 694/478 差 12 条；主线程双口径对照跑归因（排除/含 current 指针副本，差额逐位落「在场」桶）；判官 R2 裁定**接受排除口径**（副本非包目录、canonical 本体已在集内、计入即同包双计）并如实记入 verdict → 证据锚：landing-verdict/§7 R2 段 + summary census 口径注。此例是「作者申报口径 vs 独立复算口径」的判别性展示，非缺陷。

## 4. 优化建议（按 ROI 排序）

1. **「判定语义零变更」类断言必须带边界输入改前基线**：治 F1'——凡声称 exit/判定零变更的接线，验证集必须含「改前版本在**边界输入**（缺 current / 空夹具 / 畸形文件）下逐件对照 exit」，不得只测「常态输入 + self-check 绿」（本批 V6 缺此半边，F1 溜到核验期）。载体 = **ARQ 收件箱**（与 ARQ-260914 ③ 连带项「断言口径 ↔ 保留面对账」同族——同根：断言口径未覆盖保留面/边界面；登记时查重后同根追注，不新立）。
2. **lib 自带 exit 型 self-check 必须 isMain 守卫**：治 F2'——凡 lib 提供 `--self-check`，入口判断须含「本文件为入口」（否则 import 期抢跑遮蔽宿主，实例在案）。载体 = **ARQ 收件箱**（与 260813 批 argv 触发型 self-check 义务同族；追注该族条目或新立——登记时查重）。
3. **live 佐证句必须先实跑后落笔**：治 F3'——summary/申报里任何「live 佐证 / 实测已现」措辞，落笔前必须实跑一次并把输出留在核验可复现处；未实跑则写「设计触发、未实测」。载体 = **ARQ 收件箱**（ARQ-260914 追注 (B) 第三句已覆盖「承重引文 byte 对账」、未覆盖「live 佐证句」，同根追注扩一句）。
4. **核验官「改前基线」纪律显性化**：本批 F1 完全由该纪律抓出（简报第 5 项第 3 条）——建议把「边界输入基线」列进简报示例（当前示例只举「环境红基线」）。载体 = **留批次**（`track-b-verifier-brief.md` 属 G2 文面，下批一并；本批已改该文件两处，不回头再改）。
5. **死导入清理**：4 件（acceptance-coverage-check / closeout-check / docs-sync-check / security-check）import `echoResolution` 未用（核验新琐记，无行为影响）。载体 = **登记不硬治**（后续批次顺手清理，与下批 T6 面同文件的改动搭车）。

## 5. 一句总结

成本 ≈1.3M tokens 报告口径（判官 688k + 核验官 490k + 主线程 ≥120k 下限，口径声明见 §2）/ 全环挂钟跨夜 ~12h（含两次配额中断等待；纯计算 ~1.5h）/ human 触点 **1 次**（立项 ack + 收圈 + OQ 三裁同场，此后全自动至 commit）/ 制品 4 件齐 + 账本三结项归位 + 两件部分承载 / 对照批 B：面更大（T1–T10、36 文件）而纯流程时相当；最险一刻 = **核验首轮 F1（5 件判定语义破坏）**——纯行为层缺陷、判官三层面不可见、主线程自身 V6 回归半边盲区，唯核验官「改前基线」纪律一次抓出，若放行 merge 即是「零变更」不变量在 4 件闸集成员上的静默破坏 · **保险丝判定：两方独立结构接住作者偏差（第 2 次成形，且分工更清晰）**——判官抓**冻结前文本层**（F1/F2/N1–N3 引文与计数，含 R2 口径裁定），核验官抓**落地后行为层**（F1 短路破坏）+ 抓**披露层**（V1 句不实由主线程自查、核验单点复核接受——两个独立发现三方互不重复）；作者自查亦抓两处（F2' lib 遮蔽、F3' V1 句），仍未替代外部两网（F1' 作者不可见）· 最值得带走的一条：**「零变更」类不变量不能只由「常态输入 + 自检绿」自证——边界输入下与改前版本的逐件 exit/行为对照，是唯一能证明「没有变」的形态**（本批判官 R2 的口径复算与核验 F1 的边界基线，是同一纪律在文本层与行为层的两次立功）。
