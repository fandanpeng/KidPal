## 3. 摩擦与卡点（按痛感排序）

- **F1 · census「不点门名」断言被证伪（R1-F1）**：现象 = 我判 references 三处「不点门名」→ 根因 = 凭 grep 关键词印象下结论，未逐行读 pod-coordination.md:72（该行 pre-existing 陈旧点源仓三门集名）→ 证据锚 = R1 记录 F1 + `pod-coordination.md:72` 实文。教训：census 否定型断言（「没有 X」）必须逐文件实证，印象不构成 sweep 证据。
- **F2 · packet-id 行与折入件失同步（R1-F2）**：现象 = OQ2 折入 T4 后头部 packet-id 行仍写 T1–T3 → 根因 = 折入新 T 时只改了正文与 manifest、没回头改头部结构字段 → 证据锚 = R1 记录 F2。教训：OQ 折入新 T 是一次「结构字段联动更新」，头部 packet-id / §2 标题 / manifest 三处要一起动。
- **F3 · PROPOSAL 编辑工具整段匹配失败一次**：现象 = merge-driver 注释块整段 old_string 不匹配 → 根因 = 大段引文易含不可见差异（全角/箭头/空格）→ 证据锚 = 本会话 Edit 报错记录。处置 = 拆小段重试即过。教训：对 comment 块做整段替换时优先小粒度分段。
- **near-miss（最险一刻）**：R1 出打回项时，「T5 单独走下一批」的偷懒念头闪过——pod-coordination.md:72 是 pre-existing 陈旧、修它超出「这个问题」的字面范围。但判官按锚点纪律判「同批同步」，且 260904 批 R1-F1 已有完全同型的先例（code-review-gate.md:89 升类）——同型错位第二次出现，说明「census 否定断言」是系统性弱面而非个案。教训固化见 §4.3。
- **顺带澄清（R1 NIT-2，§6 留根义务兑现）**：「迁移意图地面真值 = EXPECTED oracle 2 门」与 260829 迁移批记录的适配映射存在历史分歧——本批以 git 历史 + merge-driver 注释自洽性为准据收口：迁移批做了折算决策（_doc 为证）但 merge-driver id 表漏改（源仓残留为证），oracle 2 条是唯一与折算决策自洽的形态。「地面真值」表述不推翻迁移批决策本身，只钉「id 表是漏网残留」这一事实。
