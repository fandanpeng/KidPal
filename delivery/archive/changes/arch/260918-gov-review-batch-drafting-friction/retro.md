## 3. 摩擦与卡点（按痛感排序）

**F1 · 三轮 BLOCKING 全是同一族：新写的检查器把合法情形判红（最痛）**
- **现象**：R2-F7（新增锚本就不在场——本批 T3 目标即新增文件，V3-④ 对本件首跑必红）、R2-F8（加粗探针按字面全文正扫会误咬**正文里引用该错误形态的 prose**——本件自身命中 5 处）、R3-F13（**迁移锚的迁入路径由落地动作诞生、起草期定义上不在场**，而 `preflight` 恰是起草期工具 ⇒ **任何标准迁移批都会被判红**）。
- **根因**：该类判据「对锚并集做仓内存在性检查」**建立在「不存在的即幻影」这一不成立的假设上**——§2 锚清单里的路径**合法地**就可能不在场（新增 / 迁入 / 撤回 / 迁走四形态）。**三轮各撞一类 ⇒ 枚举补丁不可收敛**。
- **证据锚**：§7 R2-F7/F8、R3-F13 原文；落地后写进 §6 留根⑥ 的「三轮证伪表」与根因定性。

**F2 · human 在裁决前先追问「结构门是谁在执行」（正面样本）**
- **现象**：OQ1（候选域改自动派生 vs 补硬编码）我给了推荐位，human 没直接选，而是先问「结构门是在哪一步执行的，那个 agent 负责执行」。
- **根因**：该选择改变的是**核验锚点**（从「清单内容」变成「派生规则」），而**实际读者是核验官**——不先锚定读者，无法判代价。
- **证据锚**：会话内 human 原问；查证结果（`landing-verifier` @ Track B 第 5 步）已写入 §4 OQ 裁决表备注。**这是本批流程上最有价值的一次交互**：它让一个看似「技术二选一」的问题回到「谁在读、读什么」。

**F3 · 熔断规则正确触发、human 缩圈后一轮即绿**
- **现象**：R1/R2/R3 三轮 BLOCK → 按 AGENTS.md「3 轮未 GREEN → human 三选一」熔断；human 裁「缩圈」（拿掉第 3 类）；R4 **一轮直绿**。
- **根因**：熔断的有效性在于它**强制把「继续打补丁」换成「重新划定范围」**——F1 的根因是判据设计不成立，继续补第 N 类只会撞第 N+1 类。
- **证据锚**：§7 R1–R4；PROPOSAL v0.8 缩圈 commit `7915c94`。

**F4 · 主线程自身消耗零观测，计量账不可用（复现既有 ARQ）**
- **现象**：§2 只能给子 agent 单值，主线程（起草/4 轮修订/落地/summary）完全无计量。
- **根因**：harness 不向主线程自身回传 usage；`dispatch-stamp` 记的是**派发**而非主线程。
- **证据锚**：§2 口径注；在册 `ARQ-260909-dispatch-stamp-telemetry-gaps`（本批为其追加证据，不新立）。

## 4. 优化建议（按 ROI 排序）

1. **「检查器先对本件跑一遍」应成起草期纪律**（载体：**ARQ 收件箱**）——F1 三轮里有两轮是「新检查器对自己的 PROPOSAL 首跑即红」。便宜做法：写完检查器后**立刻对本件跑**，红即说明判据含不成立的假设。本批 T2 已落 `--preflight`，**下一批可评估把「对自身跑」写进模板 checklist**。
2. **判据设计前先枚举「合法反例族」**（载体：**ARQ 收件箱 / 或并入留根⑥ 的下一批**）——F1 的教训是「锚清单里的路径合法地可能不在场（四形态）」。凡做**存在性/枚举类判据**，起草期应先列「哪些合法情形会命中」。本批留根⑥ 已含该方向的定性。
3. **熔断后的「缩圈」应成为标准选项之一**（载体：**已生效，建议在 `/loop-retro` 观察其复用率**）——本批实证：缩圈后一轮即绿。建议下次出现「同一族 BLOCKING 连轮出现」时，**优先评估缩圈而非继续修订**。
4. **主线程计量缺口**（载体：**已在册 ARQ-260909-dispatch-stamp-telemetry-gaps，追加证据即可**）——本批为其补充「4 轮评审批」的样本。
