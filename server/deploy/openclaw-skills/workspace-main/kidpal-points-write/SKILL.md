# KidPal 积分家长通道（QQ 一句话 → 一条 CLI 命令 → 如实回执）

家长在 QQ 里说「给小伴加 3 分，今天老师表扬了」「现在多少分了」「把刚才那条加 3 分删掉」
「兑换游乐场」时，本 skill 是唯一的积分账本动作流程。**账本唯一 writer = points.py CLI**
（`/opt/kidpal/front/gateway/points.py`，与设备语音链路共用同一执行器、同一 state 文件）。
你的职责只有两件：把家长的话整理成**一条确定性 CLI 命令**，再把 CLI 的**真实回执**用家长
听得懂的话念回去。你不算余额、不生成分录、不改账本文件。

## 1. 钉死的执行形态（一字不改）

```bash
cd /opt/kidpal/front
KIDPAL_POINTS_STATE=/opt/kidpal/points/state.json /opt/kidpal/venv/bin/python3 -m gateway.points <子命令> [参数...]
```

- **解释器恒用 `/opt/kidpal/venv/bin/python3`**：裸 `python3` 在 ECS 上解析到 3.6.8，跑不动本模块。
- **工作目录恒 `cd /opt/kidpal/front`**：`-m gateway.points` 需要 `gateway` 包在该目录下可导入
  （这是包导入，不是按文件路径加载，别用别的方式绕）。
- **state 路径单源 = 环境变量 `KIDPAL_POINTS_STATE`**（与 front 网关同一个名字，同一个文件）。
  未设该变量时 CLI 会以 exit 2 拒绝执行——这是保护，不是故障：不设它就意味着没有账本可写。
- 账本文件本体（`/opt/kidpal/points/state.json`）与同级锁文件只归 CLI 一支笔；本 skill 从不
  直接碰这两个文件，也不自己抄一份余额。

## 2. 九个子命令与回执字段

回执恒为**单行 key=value**（空白分词）；一行就是一次命令的完整结果，没有第二行花活。

| 子命令 | 命令形 | 回执关键字段 |
|---|---|---|
| `add` | `add --points 3 --reason 老师表扬 --command-id <ID>` | `entry_id` `delta` `balance` `reason` `revision` `command_id` |
| `redeem` | `redeem --points 40 --command-id <ID>` | `entry_id` `delta=-40` `balance` `reason`（= 兑换目标名） `revision` |
| `delete` | `delete --entry-id pt_<hex> --command-id <ID>` 或 `delete --index N --command-id <ID>` | `deleted=true|false` `entry_id` `revision` `balance` |
| `show` | `show` | `balance` `revision` `entries_total` `active_target_id` `active_target_name` `active_target_points` |
| `recent` | `recent [--limit N]`（缺省 5，1–50） | 每条一行：`index` **与** `entry_id` 同行，另带 `delta` `balance_before` `balance_after` `reason` `occurred_at` |
| `targets` | `targets` | 每个目标一行：`id` `name` `points` `asset` |
| `target-add` | `target-add --name 看海 --points 60 --command-id <ID>` | `target_id` `name` `points` `revision` `command_id`（**不带** `delta`/`entry_id`——这不是记账） |
| `target-switch` | `target-switch --target-id <ID> --command-id <ID>` | `target_id` `active_target_id` `balance`（= 没扣分的可对账事实） `revision` `command_id` |
| `target-delete` | `target-delete --target-id <ID> --command-id <ID>` | `target_id` `deleted=true` `revision` `command_id` |

规则要点：

- **`recent` 的 `index` 与 `entry_id` 永远同行**——序号→id 的换算权在 CLI，不在你。要删某条，
  先把 `recent` 打出来的那个 `entry_id` 原样回喂给 `delete --entry-id`，**不要自己编 id、不要
  自己数序号**。`index` 只在「刚看过 `recent`、同一条命令里立刻删」的场景使用，隔了几轮对话
  再用同一个 `index` 会指到别的分录。
- `recent` 的 `index=1` = 时间倒序最新一条（与设备详细账本同一把尺）。
- **删除前恒先 `recent`**（见 §5.1）：「昨天那条」「刚才那条」这类相对时间说法不是稳定定位符，
  只有 `recent` 回执里恰好一条候选时才可 `delete --entry-id`；候选 ≥2 条一律一次性普通文本
  报错、不调 delete。**不得**按时间/金额/事由自行推断唯一性。
- `delete` 的 `deleted=false` = 该记录已不存在（可能已被删过），**账本未变**：如实说「这条记录
  已经不在了」，不要说「已删除」、不要宣称设备已刷新。
- `delete` 成功（`deleted=true`）才代表账本真的变了；`revision` 是权威版本号，每次真实写入 +1。
- `redeem` 的事由由 CLI 取「兑换<激活目标名>」，**你不要自己编事由**。
- `show` / `targets` 只读：它们不创建、不改写账本文件，可以放心多问。
- **回执里的 `reason` 对空白做了 `%XX` 百分号编码**（事由「老师 表扬」在回执里是
  `老师%20表扬`）：回话必须用家长原话复述事由，**绝不把编码串念给家长**；也不要自己解码
  后改写事由语义——编码只是单行 key=value 的传输形态，不是事由本身。

## 3. command_id：每次新消息都必须新建

`--command-id` 是传输幂等的载体：**同一条家长消息重试时用同一个 ID**，不同消息**必须换新 ID**。
推荐形态（平台消息 id 拿不到时的降级形态，公开可对账）：

```
qq:<yyyymmddHHMMSS>:<这次指令内容的短哈希>
```

- 同一次重试（网络抖动、你重发同一条命令）→ 沿用同一个 ID，CLI 会返回**首次结果**（不新增
  分录、不递增 revision）；这是正常回执，照实念给家长。
- 新的家长消息即使文案完全相同（家长今天又说了「加 3 分」）→ **必须新建 ID**，短窗语义去重
  由 CLI 判断（它会回 `duplicate=true`）。**不要**因为「看起来像重复」就换 ID 蒙混、更不要
  因为「看起来像重复」就不调 CLI。
- 回复家长时把这次用的 `command_id` 一并念出来（如「本次命令号 qq:20261114101500:abc123」），
  万一重复记账，家长和你都能一眼对上号——重复因此是可被发现的事实，而不是被静默吞掉。
- `delete` 也吃这套重放保护：同一条删除命令重试（同一 `command_id`）**不会删第二条**，CLI 直接
  返回首次结果（`deleted=true` 与那次删掉的 `entry_id`/`revision`/`balance` 原样），账本不再变。

## 4. 恒调 CLI，永不自行吞重

**每次都必须真的调用 CLI**，不得自行判断两条像重复就跳过不调：去重与幂等（传输层
`command_id` 重放、短窗同额同事由去重、兑换不重复扣分）**全部由 CLI 在锁内裁决**，你只转述
它的回执。看到 `duplicate=true` 就回「这条刚才记过啦，账本没动」，不要报错、不要重试换 ID。

## 5. 命令说不清 = 一次性普通文本回复（不追问、不卡死）

积分通道**不依赖多轮澄清问答**：家长一句话要么能唯一落成一条命令，要么当场用**一次性普通
文本回复**说清正确说法。**禁止**使用任何会挂起等待家长补充的追问工具（QQ 侧追问会把会话
卡死，家长后续消息排队无响应）。没有把握就报错重来，不要「先猜一个再说」。

遇到下列情形，exit 1 + stderr 的说明就是你要转述的内容（可原样贴近家长能懂的说法）：

| 情形 | 一次性回复怎么说 |
|---|---|
| 没给分值 / 分值不是正整数 | 「加分要带一个正整数分值，比如『加 3 分，主动洗碗』。这条我没记。」 |
| 没给事由 | 「加多少分、为什么加，两句都说上，比如『加 3 分，今天老师表扬』。这条我没记。」 |
| 删除没说清删哪条 | 「删记录请说『删掉最近那条加 3 分』或说序号；也可以说『看看最近记录』，我先列给你。这条我没动。」 |
| 相对时间说法（昨天/今天/刚才/上午那条）在 `recent` 里命中 ≥2 条候选 | 「<时间段>有 N 条记录：第1条 … +3；第2条 … +3；第3条 … +3。请说『删掉第N条』或给我记录号。这条我没动。」（详见 §5.1） |
| `--entry-id` 与 `--index` 同时给 / 都不给、序号越界或空账 | 「这条定位不上，账本没动。你可以说『看看最近记录』，我列序号给你挑。」 |
| 试图按金额 / 事由 / 目标删除 | 「删除只认最近记录里的序号或记录号，不能按分数删。这条我没动。」 |
| 兑换金额不等于当前激活目标分值 | 「现在激活的奖励要 40 分才能兑，说别的数兑不了。这条我没记。」 |
| 余额不够兑换 | 「还差 N 分才够兑，现在没扣分。」 |
| exit 2（用法/环境错误） | 「这条命令我这边没说对，没动账本。请再说一次：加几分、为什么。」 |
| 试图删除预置场景 | 「巧克力、看电影、游乐场、礼物是预置场景，不可删；只有自定义奖励能删。这条我没动。」 |
| 试图删除正在激活中的自定义目标 | 「这个目标正在用，先切换到别的目标再删。这条我没动。」 |
| 自定义目标分值不在 5–200 之间 | 「自定义奖励的分值要在 5–200 之间（整数），比如『加个看海，60 分』。这条我没记。」 |
| 目标名为空 | 「自定义奖励要带一个名字，比如『新增目标 看海 60 分』。这条我没记。」 |

### 5.1 相对时间不是稳定定位符（S-F6.4-AC3/AC4：删除前必查）

「昨天那条」「今天那条」「刚才那条」「上午那条」「上一次」这类说法**不是稳定定位符**：同一
时间窗里可能有多条分录，家长的「那条」到底指哪条是模型的猜测，不是账本事实。

- **执行前提**：只有 `recent` 回执里**恰好一条**候选时，才可发 `delete --entry-id`。候选 ≥2 条
  一律**一次性普通文本报错**、把候选列给家长，请家长用「第 N 条」或记录号重述；报错后不调
  delete。列候选时每条都带 `index` 与 `entry_id`，另附事由与 `occurred_at`，家长才能凭序号或
  记录号复述。
- **删除前强制动作**：先跑 `recent`（候选多时用 `--limit 20` / `--limit 50` 放大），确认**唯一
  候选**，再把该条的 `entry_id` 原样回喂 `delete --entry-id`。**不得**按时间、金额或事由自行
  推断「应该就是这条」——推断出来的唯一性是猜测，不是账本事实。
- **只给自然语言、既没给序号也没给记录号**（如「删掉昨天那条」）：一律先 `recent` 再判断；仍
  无法唯一定位 → 报错不执行，绝不「先猜一条试试」。
- 报错话术示例（家长可照着重说）：「昨天有 3 条记录：第1条 06:26 帮收拾碗筷 +3；第2条 06:23
  收拾碗筷 +3；第3条 06:23 帮妈妈收拾碗筷 +3。请说『删掉第N条』或给我记录号。这条我没动。」

**禁止**：不落账却回「好了」、不查账却凭对话记忆报余额、把 stderr 的原始报错整段倒给家长。

## 6. 兑换纪律（S-F6.3-AC3/AC4）

- 只认**当前激活目标分值**：家长说的分值 ≠ `show` 里的 `active_target_points` → 一次性说明当前
  目标要扣多少，不落账。
- **真实兑现后才扣**：确认奖励确实给了孩子、家长明确说可以扣，才发 `redeem`。没去成、改天再去，
  什么都不用做——账本上从来没提前扣过。
- 同一次兑换不重复扣分：CLI 侧短窗去重与 `command_id` 重放都会挡住第二次，看到
  `duplicate=true` 就回「这次兑换刚记过啦」，不要再发一次不同 ID 的兑换。

## 7. 查账（S-F6.4-AC2）

余额、最近记录、激活目标一律**现查 CLI**（`show` / `recent` / `targets`），不凭对话记忆猜。
家长问「为什么得了 3 分」就 `recent` 里找对应那条念事由与变动前后余额；找不到就直说没有这条，
不要编。

## 8. 边界（零写权、不越界）

- **workspace-kidpal 目录（板侧 kidpal agent 的工作区）对你只读**：它是板侧只读边界，孩子侧
  零写权是既有结论。积分账本动作只经 CLI，不往那块目录里放任何东西。
- 本 skill 不读写课表、不碰任何课表面文件或解析器：课表录入走 `kidpal-schedule-write`，两套
  数据互不相干。
- 不提供惩罚性扣分入口（`add` 只加分；减分只发生在兑换与删除重算）。
- 设备显示由 front 网关按账本 revision 自动刷新（QQ 到账只更新数据、不抢前台），**你不要**在
  回复里塞任何设备显示块、也不要宣称「已经让孩子看到了」——设备行为以实际在线状态为准。
- 目标的新增 / 切换 / 删除同属本 skill（见 §9）：家长要改目标时就地执行目标子命令，不必另找通道。

## 9. 目标配置（S-F6.5：预置四场景 + 自定义 5–200 分）

出厂预置四项恒在、不可删：巧克力 20 分、看电影 30 分、**游乐场 40 分（出厂默认激活）**、
礼物 50 分。设备端不设目标——家长要改目标只能经这里。

- 家长说「给孩子加个看海 60 分的奖励」→ `target-add --name 看海 --points 60 --command-id <ID>`。
  自定义奖励分值只接受 **5–200 的整数**（范围由 CLI 单源校验，你不要自己预判或改写数字）。
- 家长说「把这周的目标换成看电影」→ **先 `targets` 读出目标列表，拿现成的 `id`，
  切目标前先取 id，不要自己编 target id**（id 由执行器生成，模型与家长都不该发明）；
  再 `target-switch --target-id <那个 id> --command-id <ID>`。
- 家长说「把看海删了」→ 同样先 `targets` 拿 id，再
  `target-delete --target-id <那个 id> --command-id <ID>`。预置场景删不掉；正在激活中的
  自定义目标要先切到别的目标再删（AC4）。
- **切目标不扣分**：`target-switch` 回执里的 `balance` 就是切完之后的余额——把它念给家长，
  不要自己算、也不要说「已兑换」。之后兑换只认新的激活目标分值（§6）。
- 目标命令回执同样带 `revision` 与 `command_id`；同一条家长消息重试沿用同一个
  `command_id`，重放返回首次结果（不会攒出重复目标、不会把版本号刷两遍）。
