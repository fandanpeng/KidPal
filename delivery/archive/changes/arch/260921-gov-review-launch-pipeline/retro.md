## 3. 摩擦与卡点（按痛感排序）

- **F1 · 主线程用全局字符串替换穿透了判官 append-only 区（本批最重的一处纪律事故）**：现象 = 我在订正 R2-F9（一处「只」字引用误差）时用 `node` 做了一次全局 `split/join`，该替换**同时命中了 §7 内 R2-F9 那条 finding 自身的引文片段**，使判官记录一度**自相矛盾**（引文已无「只归」，而陈述仍写「『只归』应为『归』」）。根因 = **把「文本订正」当成纯字符串操作，忽略了目标文本在别处被逐字引用**；append-only 区的边界是**语义**边界，不是**文件位置**边界——引文把它带进了替换面。证据锚 = PROPOSAL §7 `### R2 - 2026-09-21 - architect` 的 F9 条（现为还原后形态）+ Status 块第 5 行的披露行。**处置**：逐字还原 → Status 块如实披露 → **主动请 R3 判官独立复核 §7 全文与它自己的原始产出是否逐字一致、并就误伤给裁断** → R3 裁「可接受」（记录完整性最终保全）。

- **F2 · 起草期的三处计数错误与一处枚举缺口（本该在起草期抓掉）**：现象 = R1 一次抓出 **F1 枚举缺口**（`claude --agent planner` 降级形实为 **4** 处，我只写了 2 处并据此断言 V6 会「零命中」）+ **F2/F3/F7 三处计数错误**（卡 24→**25**、`landsIn` package 形 15→**7**、`devloop/launch` 3→**2**）。根因 = **写了数字但没回头跑一遍确认**；其中 F1 最危险——若不修，**V6 在落地后必假红**，落地核验会卡住且原因难查。证据锚 = §7 R1 的 F1/F2/F3/F7 四条（均附实测命令与输出）。**这四条全部由判官亲核磁盘抓出、主线程照单复核后确认，无一条是我自查发现的。**

- **F3 · 改法扩面后锚清单未同步（R2-F8）**：现象 = F1 让我把 T3 的改法扩到 `planner.md`，我改了改法正文却**忘了同步该 T 的目标文件锚清单与 §3 sweep 表**；因 manifest 里已由 T2 含 `planner.md`，**preflight 仍报绿**——结构门**没兜住**这个漏。根因 = 「改法面」与「锚清单面」是同一节里的两处，改一处不提醒另一处。证据锚 = §7 R2 的 F8 条（「承重指令引未锚文件」）。**这条的价值在于揭示：结构门绿 ≠ §2 硬项满足。**

- **F4 · PROPOSAL 自身的三处「面与面对不上」（落地期才暴露）**：
  - **V7 断言过宽**：§5 V7 写死 `launch prompt` 与 `prompt-<changeId>`「零命中」，而 §2 T2 改法第 4 条**明文要求**在 skill 里留一句指旧路径的存量注记、§10/V10 **明文要求**保留 `SKILL.md:3` 的 description 原样——两处保留项必然产生命中。**落地正确、断言过宽**；R1–R3 三轮判官均未抓到（判官 R1 对 §3 census 的排除面做过 spot-check，但**没做 §5 ↔ §2/§10 的交叉一致性核**）。
  - **指令面 ↔ manifest 面未逐条对账**：frozen §4 明文指令「`docs/ARCH-REVIEW-QUEUE.md` 该行在 landing 时追加注记」，而该文件**不在 landing-manifest 里**。
  - 两处同源。证据锚 = landing summary §3 第 1 条 + §5 的表 + 核验官 ADVISORY **A2**（核验官独立判定「属 PROPOSAL 文本缺陷、非 landing 偏离」，并逐条判「三处 manifest 外簿记**不应回退**」）。

- **F5 · canonical 核验官简报引用了一个本仓不存在的门**：简报第 4 项要求跑 `cross-surface-check.mjs`，实测本仓 `.claude/scripts/` 下**无此件**（迁移残余）。我派遣时主动向核验官声明了这一点，核验官记为 ADVISORY **A1**（「按无此门记录、不判 FAIL」）。根因 = 简报是自源仓迁移的文本，**没有被迁移对账过**。

- **near-miss（最险一刻）**：**F1 那次全局替换穿透 §7**。险在**它没有任何机械门能兜住**——PROPOSAL 是普通 markdown，append-only 没有任何钩子保护；判官的 §7 记录除非有人重读，被改与没被改**在文件系统上完全一样**。我之所以没让它出事，只因为两点：① 我在同一步里意识到替换面可能过宽、立即回读并发现；② 我**没有选择隐藏**，而是把它写进 Status 块并**主动请 R3 判官复核**——于是它变成了一个**被独立核验过的、记录在案的**事件，而不是一个静默损坏。**若我当初选择"悄悄改回去、反正内容一样"，它就会是一个永远没人知道的完整性缺口。**

## 4. 优化建议（按 ROI 排序）

1. **起草期对每一个自己写下的数字回跑一次确认**：治 F2 · 载体 = **固化候选 → 本 retro + 交 `/loop-retro` 观察是否复现**（若下次批再出现同类，则升级为写入 `.claude/references/task-intake-and-slicing.md` 或 PROPOSAL 模板的硬项）· 预期收益 = 直接省掉一轮 R1 的大部分成本（本批 R1 的 242k 中相当份额花在核这些数字上）。
2. **验证集断言必须与改法的「保留面」逐条对账**：治 F4 的第一子项 · 载体 = **固化候选 → ARQ 收件箱**（建议登记一条 gov ARQ：PROPOSAL 模板 §5 增一句「凡『零命中』类断言，起草期须逐条列出 frozen 改法中明文要求保留的命中」）· 预期收益 = 消除本批唯一未达标的验证项，且该类断言在下批会以外形不同的形态复发。
3. **主线程修订一律用定点 Edit（唯一锚），禁用全局字符串替换**：治 F1 · 载体 = **已在本批自行遵守的纪律**（Status 块第 5 行立此条）· **升级候选**：若该形态在后续批复现，则登记 ARQ 讨论「append-only 区的机械保护」（如 `PROPOSAL §7` 的段落哈希校验）。**本批不立机械齿**——一次事件不足以支撑新增门。
4. **PROPOSAL 的「指令面」与「manifest 面」逐条对账**：治 F4 的第二子项 · 载体 = **固化候选 → ARQ 收件箱**（与第 2 条可并作一条：PROPOSAL 的「面间一致性」自检）· 预期收益 = 让 landing 期不再出现「照 frozen 指令做了、却超出 manifest」的申报负担。
5. **canonical 简报与迁移对账**：治 F5 · 载体 = **登记不硬治**（影响面极小：派遣时口头声明即可，本批已如此处置）· 若后续再有第二例，则升为 ARQ。

## 5. 一句总结

成本 ≈ **450k subagent tokens（判官 325k + 核验官 124k）+ 主线程未计量部分（估计 150k–300k，±50%）**、**时长约 24 分钟**（R1 7.6 + R2 3.3 + R3 1.4 + 落地 7 + 核验 4.1）、**human 触点 5 次**（轨道选择更正重拍 1 次 + 立项 ack 1 次 + OQ 2 条 + R1-F5 升级裁断 1 次）、**制品 4 件齐**（PROPOSAL / landing-summary / landing-verdict / retro）；对照同批 2 T 的小乘客，规模约 5 倍而评审成本未同比放大 · 最险一刻 = **全局替换穿透判官 append-only 区（F1），当步发现 + 逐字还原 + 主动披露 + 请 R3 判官独立裁定** · **保险丝判定：两方独立结构接住了作者偏差 —— 判官（独立）抓出 4 条我自查未见的实质缺陷（F1 枚举缺口 + 3 处计数错误）与 1 条锚清单不同步（F8），核验官（独立）则补跑了我申报"未执行"的 V4/V5（真跑证旧形态可达且读侧未令绿转红）、并用 3 组变异独立复证了两条新自检齿的可分辨性，同时对我最需独立判断的一处（V7 自陈是否诚实）判「诚实且成立、非粉饰」；两方各自独立于作者，且各自改变了结论** · 最值得带走的一条 = **「写了数字就回头跑一遍」**——本批判官抓出的实质缺陷里，**四条中有四条源于此**。
