## 一、硬约束（地基，不随本轮梳理变动）

| 约束 | 内容 | 出处 |
|---|---|---|
| 屏幕 | 400×300 横屏、**1bpp 纯黑白**、反射式 RLCD（无背光、不耗电常显）、45–70FPS（滚动与逐笔动画可行） | requirements §4、arch §1.1 |
| 颜色 | 只有纯黑 `#000` 与纯白 `#fff`，不引入第三种颜色；「灰」只能靠网点抖动模拟（**网点口径待收紧，见 §四**） | 设计稿 v3 视觉纪律 |
| 交互 | **3 键、无触摸**：KEY（会话/确认/打断）、BOOT（翻页）、PWR（开关机，不入界面流程） | requirements §2.3（权威键位） |
| 底部键帽条 | `comp-keybar` = 通栏贴底**三槽**：左 KEY 提示 · **正中 4 点页面指示器**（当前页实心放大）· 右 BOOT 提示；高 38px、上沿 3px 实线分隔；键帽高 26px/圆角 8px/3px 描边/圆胖数字体，是**提示不是按钮**（无触摸、不画可点样式）；需长按时键帽左侧挂小字「长按」。**条本身任何状态常驻**（基座 chrome，覆盖层盖不掉）；**页点仅 P1–P4 主页面显示，覆盖层不显示页点** | brand-spec「姿态规则」、设计稿 v3 §06 `comp-keybar`、requirements §2.2 |
| 教学字体红线 | P4 查字页米字格内**演示笔顺的示范汉字必须用标准规范字体**（思源黑体/楷体），禁手写趣味体/抖动/倾斜——孩子会照写。拼音、部首、组词等伴随文字可用趣味字体 | requirements §4、brief §3.3 |
| 吉祥物 | 「小伴」= 宽扁圆脸猫（宽>高约 1.25:1）、黑色剪影语言；姿态集**需求侧现存六姿态**（日常/聆听/思考/播报/录音/提醒跳起）——**低电打盹姿态已砍**（2026-09-13，见 §二）；检验标准 = 孩子第一反应是「它好可爱」，不是「这是个闹钟」。**姿态通道只服务日程/时段演出，不被低电等系统状态抢占** | requirements §4、[brand-spec.md](brand-spec.md) |

## 二、本轮需求变更 → 设计影响（按页面/状态组织）

### P1 首页（常显页）——**重心整体重排，改动最大**

| 变更 | 设计影响 | 出处 |
|---|---|---|
| 常显页要回答的是「**接下来我该干嘛**」，不是「现在几点、屋里多少度」 | 主体 = 接下来的日程 + 到点提醒；**时间/日期/温湿度/电量降为辅助信息**（小字、收进一条辅助带），不与日程抢视觉重心 | requirements §1 设备定位（v1.4） |
| 常显页要有**趣味演出与互动点缀**，不能是冷冰冰的待办清单 | 小伴**常驻**首页并随时段/日程换姿态与表情（如临近上课做「出门准备」状）；允许小彩蛋。**趣味与互动是常显页的构成部分，不是事后装饰**（原「点缀」定位已升格为构成原则） | requirements §1、§4 趣味性条目（v1.4/v1.5） |
| 线框已重排（WF-F1-01） | 新布局：顶部小字辅助条 → 主区左侧小伴、右侧「接下来」列表（**最近一项最醒目 + 倒计时**）→ 底部操作提示。原「☀ 晴 适合户外活动」天气行**已删**（孩子不在乎天气） | requirements §3 WF-F1-01（v1.5） |
| 布局优先级已定 | **接下来（最近项+倒计时）> 小伴演出 > 时间 > 温湿度**——原「时间 > 接下来 > 温湿度」作废 | S-F1.1 补充规则（v1.5） |
| 辅助条加**联网小标** + **图标前置**（v1.17） | 辅助条 = `📶 10:24 星期三 6月26日 🌡22°C 💧45% 🔋85%`：📶 联网打头、每项带小图标——起因 = 湿度 45% 裸数字挨着 🔋85% 易被当成电量。各小图标（📶/🌡/💧/🔋）需 1bpp 资产设计；联网图标链路已实现（基座状态栏每 10s 刷，断网自动变 **WiFi 斜杠断网态**、另有强/中/弱三档信号，S-F1.1 AC4 已补写），电量数字真机当前取不到（见 §四缺口表） | requirements WF-F1-01、S-F1.1 AC1（v1.17） |

> 待设计决定：倒计时贴纸的视觉形态、小伴在首页的占位大小与姿态触发规则（时段驱动 vs 日程驱动）、明日预告的呈现层级。

### 语音轮演出（需求侧现存四态：聆听 / 思考 / 播报 / 提醒；低电已砍）

| 状态 | 变更 | 设计影响 | 出处 |
|---|---|---|---|
| **聆听中** `state-listening` | 新增**话语回显区** | 除现有三层冗余反馈（竖耳 pose-listen / 麦克风 / 气泡「我在听！」）外，**孩子说的话要逐句回显在标识下方**，回显区可滚动、超屏高滚出。目的 = 孩子能确认「它听清了没」 | requirements §2.2（v1.11） |
| **思考中** `state-thinking` | 定进入时机 + **真机从未弹出过** | 进入时机 = **孩子说完这一句**（服务端切句完成/音频上行结束），状态切换与页面弹出**同一时刻**；收到回复开始播报即离开；等待超 4 秒先开口安抚。⚠️ 这是**全新要做的页面**，不是改现有页面——MVP 的渲染接线缺失，真机上思考页从来不弹（详见 §五） | requirements §2.2（v1.12）、arch §3.1 |
| **播报中** `state-speaking` | 无变更 | 维持 pose-talk + 声波条 + 文字同步上屏 | requirements §2.2 |
| **打断停播** | **语音喊停不纳入 Phase 1**，打断只有 KEY 单击 | 播报态**不要**做「开口即停」的视觉暗示；键帽条 KEY 短语应表达「按一下停」 | requirements §2.1/§2.2（v1.7） |
| **提醒弹窗** `state-reminder` | **去掉整屏 d50 网点压暗** | 层级改用**弹窗白底 + 粗黑描边 + 纯黑硬投影**（纯黑偏移，非灰阴影）表达「这是覆盖层」。1bpp 没有透明度，网点原本是模拟背景压暗的唯一手段，去掉后分层信号全靠描边+硬投影 | requirements §2.2（v1.13） |
| **提醒弹窗** | BOOT 语义写明 | BOOT = **关弹窗并照常翻页**（弹窗不劫持 BOOT 的全局翻页语义），KEY = 关闭回当前页。键帽条文案可据此表达 | requirements §2.2、S-F1.4 AC2（v1.13） |
| **低电打盹** ~~`state-sleepy`~~ | **已砍（2026-09-13）** | **不要设计小伴睡姿演出**（pose-sleep + 月亮 + zZZ 整套作废）。理由：① human 判无意义；② 与「小伴姿态随时段/日程变化」抢同一姿态通道、互相覆盖；③ 该演出真机从未出现（活侧零调用者）。**保留的唯一低电信号** = P1 首页辅助条电池图标每秒闪烁、充电即停（已实现且有验收 P1-A4，归 S-F1.1 AC3）——设计上只需保证辅助条电池图标有「闪烁/灭相」两种画法 | requirements §2.2 已删行、S-F1.1 AC3、§8 已砍清单（v1.14） |

### 会话入口与信息架构

| 变更 | 设计影响 | 出处 |
|---|---|---|

## 三、待 human 拍板的设计相关未决项

1. **网点（dithering）全局口径**：本轮只去掉了**提醒弹窗的背景压暗网点**。设计稿里网点还有其它用法——腮红（d12 微点阵，brief 称之为「本套设计里网点的招牌用法」）、故事保存勋章背景（d25）、P4 查字页「未写笔画」的轮廓、聆听态指示点背景（d50）。**是否全局禁用网点**尚未裁定；若全局禁用，requirements §4「可用抖动(dithering)模拟灰度层次」一句要相应收紧，腮红等元素需另找黑白表达法。
2. **「故事记录」改名**：暂名「帮我记录」，候选方向「日记」（限定体裁、有日期概念）vs「帮我记录」（随手记，故事/碎碎念都行）。**内涵差别会影响 P3 页的组织方式**（要不要日期维度、列表按什么排）。牵连面：F2 标题、P3「故事页/我的故事」页名、brief 里的「故事果」收集资产名、里程碑 M5。
3. **回显区与播报文字是否复用同一区域**：聆听态的「话语回显区」与播报态的「文字同步上屏」是否共用一块文字区，待设计定。
4. **回显区/长文滚动字号**：NFR-READ-1 的 16px 以下 CJK 在 1bpp 真机可读性下限**未实测**（ARQ-260831-small-cjk-1bpp-readability 在办），实测前按可读字号排版、行数自然变多、滚动承接。

## 四、Phase 1 已知实现缺口（设计需知道哪些是「新做」）

这几项不是「改现有页面」，而是**真机上目前根本不存在**，设计时按全新页面/元素对待：

| 缺口 | 现状证据 | 影响 |
|---|---|---|
| **思考页真机不弹** | `lang_config.h` 无 thinking 状态文案；活侧 `LcdDisplay::SetStatus` 只映射 LISTENING/SPEAKING/STANDBY 三态；`KVST_SCENE_THINK` 场景码与姿态资产已备且验收过，但**零调用者**；小智 DeviceState 枚举本无 thinking 态 | `state-thinking`（pose-think + 飘问号）需从零接线，Phase 1 修复项。机制细节见 arch §3.1 |
| **聆听态话语回显未实现** | 回显链路本身已通（网关 ASR 切句 → WS `stt` 消息 → `SetChatMessage("user")` 上屏，MVP 真机已实测），但**没有专属回显区**，走的是小智原生聊天文本位 | 回显区的版式（位置、字号、滚动行为、与三层反馈的布局关系）需新设计 |
| **键帽条三槽布局与页点未实现** | `bottom_bar_` 已常驻（全宽、min-height 48px，设计规格为 38px），但内部**只有一个居中 label**（文案随态联动：说完啦/不等了/打断/知道了/叫醒它）；**三槽布局、4 点页面指示器、BOOT 提示、`[KEY]`/`[BOOT]` 键帽图形全部未做**（全仓搜「页点」零命中） | 需按 v3 §06 `comp-keybar` 规格重做该条：左 KEY 提示 / 中 4 页点 / 右 BOOT 提示，并实现「覆盖层隐藏中槽页点、左右槽照常」的随态切换 |
| **电量百分比真机取不到**（v1.17 登记） | 硬件有电池 ADC（官方 Demo `03_ADC_Test`：ADC1_CH3=GPIO4 分压已验证），但固件三处未接线：板类 ADC 成员是死变量、无 `GetBatteryLevel` override、渲染节点无电池注入缝——真机电量**恒显示 100%**，低电闪烁（S-F1.1 AC3）真机不触发 | 辅助条电池图标与数字按「会动」设计（五档电量 + 充电态 + 低电每秒闪的灭相）；接线是固件活，不影响版式 |
